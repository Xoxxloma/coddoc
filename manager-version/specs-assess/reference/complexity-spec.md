# Признаки сложности технической спецификации

Вторая часть задания. Оценка по рубрике остаётся как есть, а в тот же JSON добавь поле `"complexity"` — пункты
признаков сложности той же спеки; запрет рубрики на поля сверх её списка это поле не касается.
Здесь ты не оцениваешь и не считаешь, только выписываешь: считает скрипт.

## Какие файлы можно открыть

Спеку и её файлы задачи — Markdown-файлы в папке спеки и глубже, на которые она ссылается: они часть спеки.
Документы конвейера — БТ, другие спеки, баг-репорты, запросы на правку, индекс разбиения эпика, файлы этапов — не
файлы задачи. Источник требований, названный в задании, ты уже читаешь для рубрики, но цитаты сложности бери только
из спеки и её файлов задачи. Исключение — `"above_threshold"` ниже: его цитата из запроса на правку. Ссылки наружу
(сайты, папки выше папки спеки) не открывай.

## Как записывать пункт

У каждой записи, без исключений, есть `"quote"` и `"file"`. `"quote"` — дословный фрагмент из одной строки спеки или
файла задачи, скопированный символ в символ (разметку `**` и `` ` `` можно опустить), длиной 20–120 знаков; строку
короче 20 знаков бери целиком. `"file"` — имя файла, где стоит цитата. У записей-пунктов (в списках) есть ещё
`"name"` — короткое имя пункта, разное у разных пунктов: имя сервиса, состояния, сущности, ошибки. Несколько пунктов
из одной строки могут иметь одну цитату. Один пункт — одна запись; одно и то же не записывай дважды.

Выписывай только то, что решено в этой задаче:
- раздел или пункт проверки, где записано только, что в этой задаче здесь ничего не делается и не меняется («не
  применимо», «как сейчас», «доступ не меняется», прочерк и т. п.), — не решение: в признаки его не выписывай, в
  проверке «да / нет» это `"yes": false`;
- нерешённое — развилку (❓), TBD, «не решено» — в признаки не выписывай. Если решено само действие (участие
  сервиса, взаимодействие, сущность), а к валидации или к уточнению только сведения о нём (путь, поля, сроки), пункт
  выписывай: проверка сведений идёт в долг, а не отменяет пункт;
- зачёркнутое (~~…~~), подсказки шаблона (строки, начинающиеся с «>», кроме шапки спеки — о ней в `"open_items"`),
  пункты с пометкой «depends-on #0» (контракт, унаследованный от узла-фундамента) не выписывай нигде.

`"open_items"` — долг спеки: каждый пункт списка открытых вопросов в шапке спеки. Списка в шапке нет — открытые
пункты по тексту спеки. Бизнес-пробелы БТ, перенесённые в спеку, — долг БТ, в долг спеки их не выписывай.

## Что выписать

- `"change_type"`: `{"value": "...", "quote": "...", "file": "..."}` — тип изменения словом из спеки: новый
  функционал, доработка, багфикс или мелкая правка.
- `"above_threshold"`: только у мелкой правки — в запросе на правку, который задание называет источником требований,
  ответь `{"yes": true|false, "quote": "...", "file": "<путь>"}`: записано ли в нём, что объём выше порога и аналитик
  всё равно решил идти правкой. У других типов поля нет.
- `"services"`: каждый затронутый сервис из перечня затронутых сервисов и владельцев.
- `"interactions"`: каждое взаимодействие с полем `"kind"`: `"new"` — новое, `"change"` — изменение существующего,
  `"consumption"` — потребление существующего без его изменения.
- `"contracts"`: каждый стык контракта — эндпоинт, событие или сообщение, RPC-метод, — который создаётся заново или у
  которого меняется контракт (запрос, ответ, коды, заголовки, поведение), с полями `"method"` и `"path"`: у эндпоинта —
  метод и путь как в контракте, с параметрами в фигурных скобках, без параметров запроса; у события или сообщения —
  `"EVENT"` и его имя; у RPC — `"RPC"` и имя метода. Пример запроса — не отдельный стык.
- `"field_changes"`: каждое поле контракта существующего стыка, которое добавляется, меняется или удаляется.
- `"errors"`: каждую строку каталога ошибок, которая появляется или меняется (каталога нет — каждый описанный случай
  отказа); код может быть записан как угодно (`409`, «409 Conflict», символьный код), одинаковый код в разных строках
  — разные ошибки.
- `"data_entities"`: каждую сущность хранения, которую реализуем мы, — новую или изменённую. Чужую, которую только
  читаем, не выписывай.
- `"ddl_migration"`: `{"needed": true|false, "quote": "...", "file": "..."}` — нужна ли миграция схемы данных.
- `"ui_states"`: каждое именованное состояние экрана из таблицы состояний UI.
- `"access_nfr"`: какие из пяти разделов записывают решение для этой задачи — авторизация и доступ на бэке, доступ по
  ролям в UI, синхронность, кэш и производительность, надёжность и деградация, безопасность и доступ (сводно). Запись —
  `{"section": "<название>", "quote": "...", "file": "..."}`.
- `"release"`: `{"rollout_order": {"yes": true|false, "quote": "...", "file": "..."}, "rollback_plan": {...},
  "presetup_open": {...}}` — записан ли порядок выката сторон; записано ли, как откатить изменение; есть ли
  незачёркнутый пункт подготовки до релиза, который требует действия (завести роль, флаг, конфиг, учётную запись,
  миграцию).
- `"confirmed_facts"`: каждый факт о существующей, уже работающей системе, который спека помечает как подтверждённый
  аналитиком — меткой из легенды происхождения или словами, — в разделах до раздела «Допущения и открытые вопросы». Не
  выписывай: факты, взятые из карточки сервиса (services/…), решения о новом, обратные ссылки вида «см. §…». Единица —
  одна часть чужой системы: один стык, одна сущность или одно правило; запрос, ответ и доступ одного стыка — один факт.
- `"open_items"`: см. выше.

## Что вернуть

Поле в том же JSON, что и ответ по рубрике:

```
"complexity": {"change_type": {"value": "...", "quote": "...", "file": "..."}, "above_threshold": {...},
  "services": [{"name": "...", "quote": "...", "file": "..."}],
  "interactions": [{"name": "...", "quote": "...", "file": "...", "kind": "new"}],
  "contracts": [{"quote": "...", "file": "...", "method": "GET", "path": "/..."}], "field_changes": [...],
  "errors": [{"name": "...", "quote": "...", "file": "..."}], "data_entities": [...], "ddl_migration": {...},
  "ui_states": [...], "access_nfr": [...], "release": {...}, "confirmed_facts": [...], "open_items": [...]}
```
