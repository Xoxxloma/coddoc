## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего — карточки мероприятия в сервисе продажи билетов: организатору мероприятия добавляется выгрузка списка участников в CSV.

### 1.1. Описание проблемы
Организатор не может сам получить список участников своего мероприятия. Чтобы подготовить регистрацию на входе, бейджи или рассылку участникам, он пишет в поддержку и ждёт выгрузку от одного до трёх рабочих дней. Поддержка разбирает около 40 таких обращений в месяц вручную.

### 1.2. Конечные потребители
Организаторы мероприятий — пользователи с ролью «организатор», каждый по своим мероприятиям.

### 1.3. Заказчик и стейкхолдеры
- Заказчик, принимает результат: руководитель направления по работе с организаторами — Ольга Петрова.
- Стейкхолдер: руководитель службы поддержки — Денис Захаров (с поддержки снимаются ручные выгрузки).

### 1.4. Как сейчас
1. Организатор пишет в поддержку с просьбой прислать список участников мероприятия.
2. Сотрудник поддержки проверяет, что запрос пришёл от организатора этого мероприятия, и вручную собирает таблицу участников.
3. Таблицу отправляют организатору по почте; к моменту получения список уже может устареть.

В карточке мероприятия организатор сейчас видит только число проданных билетов по типам.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как организатор мероприятия должен иметь возможность сам выгрузить из карточки своего мероприятия список участников в CSV, чтобы готовить регистрацию и рассылки по актуальному списку без обращения в поддержку.

### 2.2. Ценность для бизнеса
- Улучшение UX организатора: список доступен сразу, а не через 1–3 рабочих дня.
- Снижение нагрузки на поддержку: уходят около 40 обращений в месяц на ручные выгрузки.
- Качество данных: организатор работает со списком на момент выгрузки, а не с пересланной копией.

### 2.3. Бизнес-риски и меры по снижению
| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| ФИО и e-mail участников попадут к пользователю, который не организует это мероприятие | низкая / высокое | кнопка и выгрузка доступны только организатору этого мероприятия (FR-1, FR-3) |
| У мероприятия окажется больше 5 000 участников, и выгрузка «сразу» станет медленной | низкая / среднее | сейчас таких мероприятий нет; если появятся — отдельная задача на выгрузку с ожиданием |
| Организаторы попросят Excel и фильтры сразу после запуска | средняя / низкое | — |

## 3. Объём проекта

### 3.1. Входит в проект
- Кнопка «Выгрузить участников (CSV)» в карточке мероприятия — видна только организатору этого мероприятия.
- Выгрузка списка участников в CSV: ФИО, e-mail, тип билета, статус оплаты, дата покупки — одна строка на участника.
- Файл формируется и скачивается сразу по нажатию; размер списка — до 5 000 участников.
- Отказы: «нет прав» и «мероприятие не найдено».

### 3.2. Не входит в проект
- Выгрузка в Excel и любые форматы, кроме CSV.
- Фильтры перед выгрузкой (по типу билета, статусу оплаты, датам).
- Выгрузка для других ролей — поддержки, администраторов площадки.
- Выгрузка с ожиданием: формирование файла в фоне, отправка файла на почту.
- Хранение новых данных: выгрузка ничего не сохраняет.

### 3.3. Архитектурные изменения и интеграции
Новых интеграций нет. Затронут только сервис продажи билетов: карточка мероприятия (кнопка) и формирование файла выгрузки.

### 3.4. Внешние зависимости
Внешних зависимостей нет.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса
Процесс после изменения:
1. Организатор открывает карточку своего мероприятия.
2. Нажимает «Выгрузить участников (CSV)».
3. Файл со списком участников формируется и сразу скачивается.

Требования:
- **FR-1.** В карточке мероприятия кнопку «Выгрузить участников (CSV)» видит только организатор этого мероприятия. Организаторам других мероприятий и пользователям без роли «организатор» кнопка не показывается.
- **FR-2.** По нажатию кнопки организатор сразу получает CSV-файл со списком участников мероприятия: строка заголовков и по одной строке на участника с колонками ФИО, e-mail, тип билета, статус оплаты, дата покупки. В список входят участники с любым статусом оплаты. Участников нет — файл содержит только строку заголовков.
- **FR-3.** Запрос выгрузки от пользователя, который не организует это мероприятие (например, по прямой ссылке), отклоняется с сообщением «нет прав»; файл не формируется.
- **FR-4.** Запрос выгрузки по мероприятию, которого нет или которое удалено, отклоняется с сообщением «мероприятие не найдено».

### 4.2. Критерии приёмки
- **[FR-1]** Дано организатор мероприятия А, когда он открывает карточку мероприятия А, тогда кнопка «Выгрузить участников (CSV)» видна; дано тот же организатор открывает карточку мероприятия Б, которое организует другой, — кнопки нет; дано пользователь без роли «организатор» открывает карточку мероприятия А — кнопки нет.
- **[FR-2]** Дано у мероприятия 3 участника, когда организатор нажимает «Выгрузить участников (CSV)», тогда скачивается CSV-файл со строкой заголовков и 3 строками: ФИО, e-mail, тип билета, статус оплаты, дата покупки. Дано у мероприятия 5 000 участников — файл скачивается сразу и содержит 5 000 строк участников. Дано участников нет — скачивается файл только со строкой заголовков.
- **[FR-3]** Дано пользователь не организует мероприятие А, когда он запрашивает выгрузку участников мероприятия А, тогда отказ с сообщением «нет прав», файл не скачивается.
- **[FR-4]** Дано мероприятия нет или оно удалено, когда организатор запрашивает выгрузку его участников, тогда отказ с сообщением «мероприятие не найдено».

### 4.3. Бизнес-данные
Не применимо: новых данных не хранится — выгрузка берёт уже имеющиеся сведения об участниках, билетах и оплате и ничего в них не меняет.

### 4.5. Разбиение на части
Не применимо: одна поставка — кнопка без выгрузки и выгрузка без кнопки организатору ничего не дают, а отказы «нет прав» и «мероприятие не найдено» — развилки той же выгрузки.
