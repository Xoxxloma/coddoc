# План работы

Ты ведёшь план работы аналитика: какие документы инициативы в работе и какие дела по их открытым вопросам. Список
документов даёт скрипт скилла `peek`; ты спрашиваешь, какие взять, читаешь их копии и пишешь файл плана. Документы,
ноуты и ветки не трогаешь.

Дальше `<скилл>` — папка этого файла; скилл `peek` лежит рядом с ней: `<скилл>/../peek/`. Python — `python3`, на
Windows — `python`.

## Шаг 1. Документы в работе

Из папки репозитория — одна команда:

```
python3 <скилл>/../peek/reference/peek.py --list
```

- Последняя строка `peek: list N path=<копии>` (N может быть 0) — строки списка (начинаются с двух пробелов) и папка
  `<копии>`. Корень репозитория — `<копии>` без хвоста `/.coddoc-tmp/peek/list`; `<планы>` — `<корень>/.coddoc-tmp/work-plan/`.
- Первая строка `в работе — основная ветка <ветка>, …` — главная ветка, от которой построен список.
- Есть строка «origin не обновлён …» — передай её пользователю.
- Последняя строка `peek: error …` — передай пользователю строку над ней; `no-branch` — спроси главную ветку снова, как
  в Шаге 3, иначе остановись. Другая последняя строка или скрипт не найден — «нужен скилл peek 1.2.0 или новее рядом с
  этим — обнови скиллы» и остановись.

Строка списка: `<ключ> · <путь> · <ветка | рабочая копия> · <автор> · <дата> · открытых: N`, у ноута в конце
` · тема: <тема>`. Документ «в плане», если его путь есть в «Документах» любого файла `<планы>/*.md`.

## Шаг 2. Какой план

- В аргументе имя плана и файл `<планы>/<имя>.md` есть — Шаг 4 для него.
- Иначе: планов в `<планы>` нет — Шаг 3. Планы есть — покажи их пронумерованными, последним «новый план», и спроси
  «Какой план обновить?». Жди ответа: план — Шаг 4, «новый план» — Шаг 3.

## Шаг 3. Новый план

Сначала главная ветка — куда вливают задачи; от неё считается, что влито. Гипотеза — `главная:` любого плана в
`<планы>`, планов нет — ветка из первой строки Шага 1. Спроси: «Главная ветка — <гипотеза>? Если задачи вливают в
другую — назови её». Жди ответа. Названа другая или гипотеза не та, что в первой строке, — повтори команду Шага 1 с
`--base <ветка>`.

Кандидаты — строки списка, которых нет ни в одном плане. Кандидатов нет — скажи «новых документов с открытыми
вопросами в работе нет» и остановись.

Покажи кандидатов как есть, пронумеровав с 1, и спроси одним сообщением: «Какие берём в план? Номера через запятую».
Жди ответа. «Все» — все. Номера, которого нет в списке, — переспроси.

Инициатива строки — её ключ; ключа нет (`—`) — имя папки, где лежит файл (у ноута — `notes/<папка>/`). Выбранное с
одной инициативой — один план, без вопроса. Инициатив больше одной — спроси одним вопросом и жди ответа, файлы до
ответа не пиши:

> Найдено 3 инициативы: PAY-12, PAY-15, доставка. По плану на инициативу или все в один план — под каким именем?

По плану на инициативу — файл на каждую; в один — один файл с названным именем.

На каждый план: файла `<планы>/<имя>.md` нет — собери дела (раздел «Дела»), запиши файл (раздел «Файл плана»; цель —
«БТ и спека влиты», главная — ветка из первой строки списка) и отчитайся (раздел «Отчёт»). Файл есть — добавь
выбранные документы в его «Документы» и обнови его по Шагу 4.

## Шаг 4. Обновление плана

1. Прочитай файл плана: шапку, «Документы» и «Дела» — старые дела понадобятся для отчёта. `главная:` не та, что в
   первой строке Шага 1, — повтори команду Шага 1 с `--base <главная>`; строки нет — спроси, как в Шаге 3, и впиши.
2. Каждый документ из «Документов»:
   - есть в списке Шага 1 — ветка и N из строки списка; пометка `· следим` снимается;
   - нет в списке, а в его строке `· следим` — оставь строку как есть;
   - нет в списке и пометки нет — открытых вопросов по нему в работе больше нет: закрыты, или ветку влили или
     удалили. Спроси «Закончили с ним или следим дальше?» (все такие документы — в одном сообщении). «Закончили» —
     убери из «Документов»; «следим» — строка `<путь> · <ветка как была> · открытых: 0 · следим`.
3. В аргументе «добавь» — покажи пронумерованными строки списка, которых нет ни в одном плане, и спроси «Какие
   добавить? Номера через запятую»; выбранные — в «Документы». Вопросы пунктов 2 и 3 вместе — одним сообщением.
4. Дела — заново по всем документам с N > 0 (раздел «Дела»).
5. Перезапиши файл (раздел «Файл плана»): шапка как была, меняется только `обновлён:`.
6. Отчёт (раздел «Отчёт»).

## Дела

Каждый документ читай из копии `<копии>/<путь>`. Дело — один открытый вопрос:

- БТ и спека — пункты блока «Открытые вопросы» в шапке документа; запрос на правку и баг-репорт — пункты раздела
  `## Открытые вопросы`. Кого ждём — «—». Откуда — `БТ <ключ> п.N` (`спека`, `запрос на правку`, `баг-репорт`), N —
  номер пункта блока.
- Ноут — строки `- [открыто] …` без `‖`. Вопрос — текст после `[открыто] ` до ` — ждёт:`; кого ждём — после `ждёт: `
  до ` · ` или `;`; откуда — имя папки ноута и номер пункта в конце строки (`kafka-events 2026-10-14 №1.2`).

Дел по документу столько, сколько «открытых: N» в его строке. Не сходится — дела по пунктам блока, в отчёт строку
«<путь>: в шапке N, в блоке M».

У дела две строки:
- суть — что спросить или сделать, до 15 слов, словами вопроса, без новых фактов; уточнение в скобках у «кого ждём»
  («встреча 2026-11-12», «уточнит у юриста») — в конце сути, в скобках;
- оригинал — текст вопроса дословно: не пересказывай, не сокращай, похожие не объединяй.

Группы — по тому, кого ждём, без уточнения в скобках. В «кого ждём» есть «аналитик» (и в скобках) — группа «Ваши
дела», суть с глагола; «—» — «Без адресата». Больше дел — группа выше, при равенстве — чьё дело раньше по порядку
документов; «Без адресата» — последняя. Внутри группы — по порядку документов, затем пунктов; номера дел сквозные.

## Файл плана

`<планы>/<имя>.md`:

```markdown
# План: <имя>

обновлён: <ГГГГ-ММ-ДД>
главная: <ветка>
цель: <цель>

## Документы
- <путь> · <ветка | рабочая копия> · открытых: N

## Дела
Всего N: <группа> — K · <группа> — K · …

### <группа> — K
1. <суть> · <откуда>
   > <оригинал>
```

- Дата — сегодняшняя, из окружения сессии.
- Цель меняет только человек: при создании — «БТ и спека влиты», при обновлении — как была в файле.
- Документы — в порядке, как были в плане, новые — в конце в порядке списка; дела — по группам (раздел «Дела»).

## Отчёт

В чат — по каждому плану: путь файла, сколько документов и дел. При обновлении ещё:

- закрылось — дела старого файла, которых нет в новом; появилось — дела нового, которых не было (то же дело — тот же
  документ и тот же оригинал);
- убранные документы;
- «ещё K документов в работе не в плане — добавить: /work-plan <инициатива> добавь», если такие строки списка есть;
- строки «в шапке N, в блоке M», если были.

## Чего не делать

- Не править документы и ноуты, не переключать ветку, не делать checkout, stash, pull.
- Не искать документы по веткам сам — их даёт `peek.py --list`.
- Не запускать другие скиллы и не закрывать вопросы: дело — открытый вопрос как он есть.
- Не ранжировать дела и не добавлять своих.
