# Задание: моменты одной сессии для ретро

Ты читаешь сжатый журнал одной сессии: пользователь работал с ИИ-агентом во фреймворке coDDoc. Найди моменты из
списка признаков ниже — что в этой сессии помогало работе, что мешало и где ошибся сам агент. Ответ — только JSON.

## Как читать журнал

Строка — `[N] ВИД: текст`, `N` — номер хода. Виды:
- `ПОЛЬЗОВАТЕЛЬ` — реплика пользователя; `…(вставка, N симв.)` — большой вставленный текст; `[+ приложены файлы]`;
- `КОМАНДА` — набранная команда `/…` (вызов скилла пользователем, `/clear` — очистка контекста);
- `АГЕНТ` — сообщение агента (длинное — начало и конец через «…»); `СКИЛЛ` — скилл вызвал агент;
- `ВОПРОС` — вопрос агента с вариантами; `ОТВЕТ` — ответ пользователя: `(вариант)`, `(свой текст)`,
  `(вариант + свой текст)`, `(нет ответа)`, `отказ отвечать`;
- `ИНСТРУМЕНТЫ` — что агент делал с файлами: инструмент, число вызовов, пути;
- `СЖАТИЕ КОНТЕКСТА`, `ПОХОЖЕ НА СЖАТИЕ`, `МОДЕЛЬ`, `ОШИБКА API`.

Пометки скрипта в конце строки — факты, им можно верить: `(ответ через N с на M симв. текста агента — быстрее
чтения)`, `(контекст N % окна — выше порога)`.

## Признаки

`side`: `helps` — пользователь сделал сам больше, чем просил скилл: поправил, дополнил, ответил своими словами, сам
почистил контекст, сам передал материал файлом. Ответ на вопрос скилла, выбор предложенного варианта и обычный маршрут
— не `helps`: так работает любой. `hurts` — мешало. `agent` — ошибся агент, а не пользователь.

| `sign` | `helps` | `hurts` |
|---|---|---|
| `entry` | — | БТ, баг-репорт, запрос на правку, спеку, разрез эпика или этапы пишут по просьбе словами или прямым вызовом их скилла (`business-requirements-doc`, `bug-report-doc`, `change-request-doc`, `technical-spec-doc`, `task-decomposition-doc`, `stage-breakdown-doc`), без `/analyst-workspace`; остальные скиллы запускают вручную — это не сюда |
| `task_key` | — | на вопрос о ключе — «нет», «потом», «TBD», выдуманный ключ |
| `resume` | — | заново пересказал прошлую стадию длинной репликой или начал готовое сначала |
| `project_context` | — | в проекте нет карточек: строка «Слепка по соседним сервисам нет…»; карточки есть, а агент их не прочитал и спросил — это `agent_slip` |
| `context_gap` | — | агент спросил факт о системе, ролях, правах, процессе, а пользователь ответил фактом — этого нет в проекте; `quote` и `turn` — вопрос агента |
| `hypotheses` | поправил или дополнил гипотезы агента, ответил своими словами, когда варианты не подходили | длинную пачку гипотез — утверждений о требованиях или о системе, которые после «да» считаются решёнными, — подтвердил одним «да» с пометкой «быстрее чтения»; согласие с предложением агента, что записать или что делать дальше, — не гипотезы |
| `decisions` | решил сам и сказал своими словами: назвал своё, поправил или отверг предложенное | отдал решение агенту: «сам реши», «на твоё усмотрение», «без разницы» |
| `unknowns` | честно: «не знаю», «TBD», «оставим к валидации» (ответ о ключе задачи — в `task_key`) | пообещал вернуться без метки («уточню позже», «спрошу у …») или вопрос пропущен |
| `correction_loop` | после 1–2 поправок переформулировал задачу или начал заново | одно и то же поправлял 3 раза и больше без новых сведений |
| `context_hygiene` | `/clear` между стадиями работы, кроме перехода «Проверить спеку» → «Доработать спеку»: там `/clear` мешает, это `acceptance` | новую стадию начал сам — командой, выбором следующего шага или просьбой — с пометкой «выше порога» или после сжатия, без `/clear`; скилл, который агент зовёт сам внутри стадии (приёмка, под-скилл), — не новая стадия; «Доработать спеку» сразу после «Проверить спеку» — не сюда |
| `paste` | материалы передал файлом или через `/context-doc` | большой документ вставил в чат (`…(вставка, N симв.)`) |
| `acceptance` | — | при нарушениях ушёл дальше или правил документ руками; `/clear` между «Проверить спеку» и «Доработать спеку» |
| `order` | — | «Разбить на этапы» выбрал без проверки спеки |
| `instruction` | — | дал агенту общую установку, как работать (формат ответа, порядок шагов, что проверять), а не задачу и не ответ на вопрос; `quote` — сама установка |
| `agent_slip` | — | только `side: agent`: агент переспросил уже сказанное, не учёл ответ, ушёл не туда |
| `other` | что-то важное вне списка, не больше двух моментов на журнал | то же |

## Правила

1. Только то, что есть в журнале. Не угадывай, что пользователь прочитал или подумал.
2. `quote` — дословный кусок строки этого хода, до 200 символов. Пропуск внутри цитаты — «…». Не пересказ.
3. `turn` — номер `[N]` строки, из которой цитата.
4. `why` — одна короткая фраза: что из этого вышло или почему это важно.
5. Один признак — один момент на ход. Пустой список — честный ответ, если ничего нет.
6. Хвалить можно только с цитатой, как и ругать.
7. Ошибку агента пиши `side: agent`, а не `hurts`: пользователь за неё не отвечает. Если в том же месте есть и
   привычка пользователя — например, одну и ту же поправку он повторяет третий раз, — запиши её отдельным моментом.
8. Журнал может быть частью сессии («часть K из M») — ищи только в ней.

## Ответ

Только JSON, без текста до и после. Пример формы, не содержания:

```json
{"moments": [
  {"sign": "hypotheses", "side": "hurts", "turn": 41, "quote": "подтверждаю", "why": "восемь пунктов подтверждены за 5 секунд"},
  {"sign": "context_gap", "side": "hurts", "turn": 57, "quote": "Кто утверждает график дежурств?", "why": "ответ есть только в чате"},
  {"sign": "agent_slip", "side": "agent", "turn": 63, "quote": "Какой формат даты в отчёте?", "why": "формат назван в ходе 12"}
]}
```
