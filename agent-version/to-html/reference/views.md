# Описание вида «Обзор»

Вид «Обзор» раскладывает документ по блокам: карточки, сетки, шаги, требования с критериями приёмки,
взаимодействия, матрица трассировки. Какой файл как раскладывать, задаёт описание вида — JSON в `viewer/views.js`:
`brd` (БТ), `spec` (спека), `bug` (баг-репорт), `cr` (запрос на правку). Описания — часть to-html, их правит
фреймворк; у других файлов обзора нет. Неизвестный блок страницу не роняет: предупреждение в консоли, раздел — как
есть.

Главное правило: **обзор только раскладывает текст документа**. Что не взял ни один блок, показывается как есть, на
своём месте. Скрыть раздел описанием нельзя.

## Поля вида

| Поле | Что задаёт |
|---|---|
| `id` | имя вида |
| `files` | имена файлов, к которым применяется вид |
| `kind` | разбор документа: `brd` (требования FR и критерии), `spec` (взаимодействия INT, трассировка), `bug`, `cr` (требования строками `- **FR-n:**`); без поля — `doc`, только разделы и шапка |
| `label` | короткое имя документа для чипов в соседних документах: «БТ · Готово к оценке» |
| `role` | `source` — из этого документа спека папки берёт требования FR; `spec` — это спека папки |
| `layout` | `sections` — раздел с заголовком, блок, не взятые подразделы карточками; `cards` — каждый раздел карточкой целиком. По умолчанию: `cards` для `bug` и `cr`, остальным — `sections` |
| `hero` | шапка — ниже |
| `sections` | правила разделов верхнего уровня — ниже |

## Шапка (`hero`)

| Поле | Что задаёт |
|---|---|
| `sibling` | чип соседнего документа со статусом: `spec` — спека папки, `source` — документ, из которого спека берёт FR |
| `line` | ключ строки шапки, которая идёт отдельной строкой под чипами (у спеки — `Источник`) |
| `questions` | открытые вопросы из шапки: `list` или `numbered` |
| `legend` | `true` — легенда меток свёрнутым блоком |
| `critical` | правило раздела, первое слово которого («Средняя.») идёт чипом «критичность» |
| `foundation` | `true` — чип «фундамент #0», если документ — часть эпика |

Чипы задачи, статуса, автора и редакции — всегда, если они есть в шапке. Остальные строки шапки — текстом под ними.

## Правило раздела

```json
{ "title": "^Шаги воспроизведения", "num": "2", "block": "steps" }
```

| Поле | Что задаёт |
|---|---|
| `title` | регулярное выражение по названию раздела без номера, без учёта регистра |
| `num` | номер раздела: `"2"`, `"4.3"` |
| `block` | как раскладывать (каталог ниже); без поля — карточкой |
| `style` | цвет карточки: `problem` (красная), `goal` (зелёная), `scope-in`, `scope-out`, `fact`, `was-card`, `proc`. Красятся: раздел без блока, пункт ряда без своего блока, первый раздел `pair` (цветом из правила пары); второй раздел пары и всё со своим блоком — нет |

**Как раздел находит правило.** Правила одного уровня разбирают разделы в два прохода:
1. Сначала по названию.
2. Оставшиеся — по номеру среди ещё не занятых разделов.

Один раздел — одному правилу. Поэтому если в шаблоне поменялись номера, раскладка не съезжает, а документ с другими
названиями всё равно раскладывается по номерам. Достаточно указать что-то одно, надёжнее — оба поля.

## Блоки

| Блок | Для чего | Параметры |
|---|---|---|
| — (нет поля) | раздел карточкой | `style` |
| `rows` | подразделы рядами: ряд из двух — две колонки, из трёх — три, из одного — во всю ширину | `rows`: массив рядов; пункт ряда — правило подраздела с `block` (`stories`, `table-cards`, `labeled` или карточка), `style`, `scroll` (таблица прокручивается), `small` (`true` — карточка мельче) |
| `stories` | (в `rows`) абзацы подраздела — зелёными карточками | — |
| `table-cards` | (в `rows`) таблица подраздела — карточками | `cards`: `roles`, `services`, `objects` |
| `labeled` | (в `rows`) строки «**Ключ:** значение»: «Суть» карточкой, остальные сеткой | — |
| `requirements` | требования FR карточками, у каждого — его критерии «Дано / Когда / Тогда» | `data`: правило подраздела бизнес-данных (карточками объектов) |
| `interactions` | взаимодействия INT карточками: метод и путь, направление, этап, свёрнутые поля | — |
| `release` | раздел выката; чек-лист — галочками | `checklist`: правило подраздела чек-листа |
| `trace` | трассировка: матрица «FR × INT» и тест-кейсы | — |
| `steps` | нумерованный список — шагами | — |
| `touched` | таблица «Что тронуто»: тронутое — «сейчас → станет», нетронутое — чипами | — |
| `pair` | этот раздел и раздел `with` — рядом; во втором требования FR карточками. Только при раскладке `cards` | `with`: правило второго раздела, `style` — цвет первого |
| `questions` | раздел открытых вопросов — в блок «Открытые вопросы» под шапкой | — |

## Своя раскладка

Поверх описания вида человек сам расставляет блоки «Обзора»: кнопка «Редактировать форму» над обзором, блок тянут за полосу с
названием, ширину — за правый край (сетка из 12 колонок, от 3 до 12), «Скрыть» убирает блок в свёрнутую полосу
«Скрыто» под обзором — его текст остаётся на странице. Высота блока — по содержимому. Код — `viewer/layout.js`.

**Блоки.** Шапка (`:hero`), открытые вопросы (`:questions`), раздел — заголовок и текст под ним, пункт ряда `rows`,
бизнес-данные `requirements`, подраздел выката `release` и его чек-лист, подраздел без правила, половина пары `pair`,
текст вне документа (`:outside`). Требования, взаимодействия, трассировка и шаги — блоком целиком. Ширина по умолчанию:
пункт ряда из двух — 6, из трёх — 4, половина пары — 6, остальное — 12.

**Ключ блока** — по правилу вида: первое название из `title` без знаков выражения («^Введение» → «введение»),
подраздел — через «/» («введение/описание проблемы»); раздел без правила — по названию без номера. Ключ один на все
документы вида, поэтому раскладка — одна на тип документа.

**Файл** — `.coddoc-tmp/to-html/layouts/<вид>.json` в корне репозитория, личный (git его не видит):

```json
{ "format": 1, "view": "brd", "items": [ { "k": ":hero", "w": 8 }, { "k": "введение", "w": 12, "hide": true } ] }
```

- Блок документа, которого нет в файле, встаёт сразу за своим соседом выше по документу.
- Запись о блоке, которого в документе нет, пропускается и остаётся в файле: сохранение из одного документа не
  стирает раскладку разделов другого документа того же вида.
- Файл не прочитался или он для другого вида — обзор как в документе, в консоли предупреждение.
- Удалить файл — вернуть обзор как в документе; кнопка «Сбросить» делает то же для блоков этого документа.

**Сохранение.** Chrome и Edge пишут файл прямо в папку раскладок: в первый раз её выбирают в диалоге (путь страница
показывает и кладёт в буфер), браузер запоминает выбор; узнаёт папку по файлу-пометке `to-html-layouts.txt`, его
создаёт `pack.sh` / `pack.ps1`. Остальные браузеры скачивают `<вид>.json` — его кладут в ту папку руками. Вкладка
помнит сохранённое до пересборки набора; следующий вызов to-html вшивает файлы папки в набор (`layouts.js`). Чистка
старых наборов папку раскладок не трогает.
