## 0. Решено

| Вопрос | Решение |
|---|---|
| Форма | Режим `rehearse <путь> проверка` → `reference/check.md`. Роли — те же карточки, поправка ролям `check-brief.md`, сводящий `merge.md`. Отдельного скилла нет |

| Критичное | вопрос, без ответа на который исполнитель решит сам и неверное решение потеряет/задвоит данные, пропустит действие без права, покажет не то или потребует переделки после выката |
| Сводящий | чистый контекст, читает документ; выбрасывает отвеченное, вне предмета, чужой контракт, объявленное неизменным, некритичное; сводит дубли; чужие имена — смыслом; ≤ 10; у пункта «чем грозит» и роли |
| Ведущий | документ не читает; сверяет опоры итогового списка; одно сообщение |
| Оркестратор | `stage-final.md` §1: `rehearse <путь> проверка`, список — хендофф, узел тем же ходом; в доработку — пункты с ответами |
| База сравнения | `spec-readiness` 1.2.0, `runs/2026-11-04-rex-base` (ответ пользователя 04.11) |

## 1. Стенд

Модель `claude-sonnet-5`. Пробы подают скиллу спеку напрямую (без оркестратора), один ход.

| Проба | Фикстура | Что мерит |
|---|---|---|
| `chk-gap` | SR-GAP | подсаженные дыры g1–g6, вне таблиц g7 (g8 — ПДн, вне предмета по решению) |
| `chk-clean` | SR-CLEAN | пункты, на которые спека отвечает прямо |
| `chk-yellow` | SR-YELLOW | литералы-приманки из `services/itsm.md`, требования чужого контракта |
| `chk-blue-yes`, `-idk`, `-cr` | SR-BLUE | пункт про изменение; про прежнее поведение ≤ 1 |

Оценщик `grade-chk.mjs` (самопроверка 10/10). Качество — слепой судья: свежий субагент получает спеку и два списка
(база и новый) под буквами A/B в случайном порядке, размечает каждый пункт (критичный / мелочь / ответ в спеке есть /
вне предмета) и говорит, какой список полезнее аналитику перед разработкой и чего не хватает каждому.

Регресс: `reh-arch`, `reh-sec`, `reh-cust`, `reh-stop` (REH-SHT, `grade-reh.mjs`); `reh-ex-gap` с явной ролью
«исполнитель» (`grade-reh-ex.mjs`); `rt-check`, `rt-epic` на заглушке `rehearse` (`grade-rt.mjs`, режим «проверка»);
самопроверки оценщиков.
