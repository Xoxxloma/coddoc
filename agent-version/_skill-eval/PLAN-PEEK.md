# PLAN-PEEK — плагин `/peek`: документы задачи из любой ветки без переключения

Статус: С0–С3 сделаны 2026-11-13 (CHANGELOG 5.98), ветка `feat/coddoc-tmp`.
Источник замысла — `product/plans/PLAN-BACKLOG-2026-11-10.md`, раздел 1.

## 0. Что делает

- `/peek <ключ>` — находит `coddoc/**/<ключ>/` во всех локальных ветках и в origin, берёт самую свежую версию,
  выгружает её в `.coddoc-tmp/peek/<ключ>/` корня репо и печатает: ветка, автор, дата, файлы со статусом из шапки.
  В конце — предложение `/to-html .coddoc-tmp/peek/<ключ>`.
- `/peek <слова>` — ищет слова в `coddoc/` во всех ветках: «ключ · ветка · автор · файл:строка · строка»;
  одинаковая строка из разных веток — один раз; дальше `/peek <ключ>`.
- Не меняет: текущую ветку, рабочую копию, индекс, `notes/`. Ни checkout, ни worktree, ни stash — только чтение
  объектов git и запись в `.coddoc-tmp/peek/`.

## 1. Как устроено

Скилл `agent-version/peek/`: `SKILL.md` + `reference/peek.py` (Python, только стандартная библиотека — нужен Python,
как у `retro`). Агент запускает одну команду и пересказывает вывод; файлы сам не ищет и не читает (как `to-html`).

**Ключ.**
1. Ветки: `git for-each-ref refs/heads refs/remotes/origin`. Перед этим `git fetch` origin без вопросов пароля
   (`GIT_TERMINAL_PROMPT=0`, ssh `BatchMode=yes`); не вышло — строка «origin не обновлён: <причина>», поиск по тому,
   что есть.
2. В каждой ветке — `git ls-tree -r --name-only <ветка> -- coddoc`, папки с именем ключа (без учёта регистра).
   Одинаковое дерево (`<ветка>:<путь>` → хеш) в нескольких ветках — одна версия.
3. Свежесть версии — дата последнего коммита в этой ветке, тронувшего папку ключа (`git log -1 <ветка> -- <путь>`);
   оттуда же автор. Остальные ветки с ключом — одной строкой: «ещё в: main (старее), origin/feature/x (то же)».
4. Выгрузка: `git archive <ветка> -- <путь>` → `.coddoc-tmp/peek/<ключ>/` (старая выгрузка этого ключа удаляется
   целиком, подпапки эпика сохраняются). В `.coddoc-tmp/peek/` — 10 последних ключей, как у `to-html`;
   `.coddoc-tmp/.gitignore` = `*`.
5. Статус: из каждого `.md` строки шапки `**Статус готовности:**` и `**Редакция:**`; нет шапки — «без шапки».

**Слова.**
1. Те же ветки; файлы `coddoc/**` по `git ls-tree -r`; одинаковое содержимое (хеш блоба) читается один раз
   (`git cat-file --batch`).
2. Совпадение — все слова в одной строке, без учёта регистра (кириллица тоже).
3. Ключ строки — ближайшая вверх папка вида `<БУКВЫ>-<цифры>`; автор — последний коммит файла в ветке.
4. Одинаковая пара «файл, строка» в разных ветках — один раз, с самой свежей веткой. До 30 строк; больше —
   «ещё N, уточни слова».

**Вывод.** Строки для человека, последняя — для агента: `peek: ok key=… files=… path=…` /
`peek: found N` / `peek: error not-repo | no-coddoc | not-found | no-write`.

## 3. Решено 2026-11-13

- Скрипт — Python.
- Ветки с ключом, кроме выбранной, — одной строкой.
- `fetch` — только обновление `origin/*`: без `pull`, без `--prune`, текущая ветка, индекс и рабочая копия не
  трогаются; занята блокировка или нет сети — поиск по тому, что есть. Самотест проверяет: коллега запушил в ветку,
  на которой стоит человек, у человека незакоммиченная правка — после `/peek` правка и HEAD на месте.

Не проверить локально: Linux/macOS — только Windows (Git Bash, PowerShell).
