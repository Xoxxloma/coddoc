## [СПРАВОЧНО] Правила работы (для всех срезов)

- Самотесты зелёные → перечитать каждую правку в контексте → только потом стенд.
- Прогон стенда — сначала назвать «что × сколько ≈ $», ждать ответа. Только Sonnet.
- Красный — только потеря данных или неверный факт; объём, место факта, форма — справочно.
- Не больше двух кругов на срез; не прошёл — откат среза, проблема — в стыки. Новых волн ревью нет.
- Правки минимальные; обоснования — в CHANGELOG, не в тексте скилла; следов стенда в скилле нет; примеры — разных стеков.
- Каждый срез — своя запись CHANGELOG и поднятие версии; коммит — по слову владельца, явными путями.
- Скрипты — Python 3.8+, только стандартная библиотека: без pip, venv, `requirements.txt`; YAML и OpenAPI — построчно,
  как сейчас. Без `match`, `str.removeprefix`, `zip(strict=)`; `list[str]` и `X | Y` в аннотациях — только с
  `from __future__ import annotations`.
- Ввод-вывод — одинаково во всех скриптах:
  - stdout — в UTF-8, приёмом `peek.py` (`sys.stdout.reconfigure`): при перенаправлении Windows даёт cp866/cp1251, и `«`,
    `—`, `⇥` роняют скрипт с `UnicodeEncodeError`. Результат — в файл; строка, по которой решает агент, — ASCII.
  - Запись файлов — `encoding="utf-8"`, `newline="\n"` (иначе Windows ставит `\r\n`); чтение своих — `utf-8-sig`,
    `newline=""`; чужой код — `errors="replace"` (cp1251, бинарные).
  - Пути в выводе — через `/`; обход папок — с сортировкой (порядок `os.walk` не гарантирован).
  - Файл не прочитался (путь длиннее 260, нет доступа) — не молчать и не падать: строка «не прочитано N» в отчёт
    (потеря 128 файлов Apollo 01.11 была тихой).
  - `sys.dont_write_bytecode = True` — до `import keys`, иначе `__pycache__` в папке скилла.
  - Регэксп — только из файла, никогда аргументом команды (PowerShell и cmd портят `|`, `^`, `"`).

## [ДЕЛАЕМ] Срез П — порт скриптов на Python 1:1 (до среза 0)

Решение владельца 2026-11-24: скрипты скилла — на Python, только стандартная библиотека. У пользователей Python 3.13.
Срез согласован с архитектором 2026-11-24: сначала порт, потом срезы 0–3 — поведение и язык разом не меняются.

1. `plan.sh`, `check.sh`, `assemble.sh`, `promote.sh`, `edges.sh` → `.py` с той же логикой, аргументами и форматами
   файлов (`counts.txt`, план, `.check.txt`, черновик); `keys.awk` → `keys.py`, общий модуль, его импортируют остальные.
   В порте ничего не улучшается, даже то, что упростили бы потом; `parse_opis` портируется 1:1 и остаётся.
2. Команда — как в peek и coddoc-settings, дословно: `python3 "<…/reference/X.py>" <аргументы>`, на Windows — `python`;
   та же строка в таблице ошибок («Нужен Python 3 …»); `py -3` не вводить. Переменные перед командой (`CHECK_PLAN=…`)
   становятся аргументами; вывод в файл — `--out`, а не `>`. Абзац «На Windows» в `SKILL.md` и условие «Git for Windows
   у пользователей» снимаются; `run.ps1` — только после самотеста запуска (ниже).
3. Регэксп разведчика компилирует `re` с `re.ASCII` (как `[[:alnum:]_]` под `LC_ALL=C`); перевод `awkre` не нужен —
   п. 2 среза 0 закрывается здесь.
4. **Байтовая семантика.** Под `LC_ALL=C` `length`, `substr`, ширина `printf` (`%-Ns`), `.` в регэкспе — байты, в
   Python — символы. Все такие места (грепом `length(`, `substr(`, `%-`, обрезка `check.sh:709`) — каждое: считать по
   `.encode()` (совпадёт) или строкой в список расхождений. `sort` под C = порядок кодпоинтов в Python — совпадает.
5. **Диалект своих регэкспов** (не разведчика):
   - `[[:space:]]`, `[[:alnum:]]` Python не понимает и молча матчит не то.
   - Альтернация: awk берёт самое длинное совпадение, Python — первое слева (`a|ab`); у всех `match`/`sub`/`gsub` с `|` —
     проверить порядок ветвей.
   - `$` в Python совпадает и перед хвостовым `\n` — строки резать `rstrip("\n")`; `\r` снимать там же, где снимал bash
     (`sed 's/\r$//'`), и только там.

- Уходят ловушки: `toupper`/`tolower` gawk на кириллице (`k_up`/`k_low`), перезапись путей `/x` в MSYS, `grep -P` под `LC_ALL=C`.
- **Список допустимых расхождений — до сверки.** По сохранённым строкам разведчика из `runs/` выписать, что `awkre` делал
  с `[\w, ]`, ленивыми `.*?`, `(?:…)`, `\b`, `\d` вне скобок. Разойтись могут только счёт у строк разведчика с
  конструкцией, которую `awkre` переводил с потерей, и места из п. 4, записанные в список; каждая такая строка названа в
  отчёте сверки. Остальное — байт в байт.
- **Сверка:** старый bash и новый Python на одном корпусе — самотесты, сохранённые входы из `runs/` и входы Windows (CRLF,
  BOM, файл cp1251, путь с пробелом и кириллицей); сверяются stdout, файлы и код выхода.
  - Покрытие: виды строк отчёта `check` (MISS, MISSRC, NOSRCPAIR, EXTRA, EMPTY, DUP, NOFACT, PARTEMPTY, NOKEY, NOPFX,
    DECL, MISSED, BROKER …) и коды выхода; вид, которого нет в выводе старого bash на корпусе, — случай в самотест или
    строка «не сверено».
  - Не вхолостую: сломать одну ветку в `.py` на копии — сверка обязана упасть.
- Самотесты зовут `.py`; `SM_RUNNER=ps1` снимается; синтаксис 3.8 у всех `.py` (`ast.parse(..., feature_version=(3, 8))`);
  в `.py` нет `[[:`; SM-PLAN-TYPES — регэксп с `[\w, ]`. API под 3.8 `ast` не ловит: есть 3.8 на машине — самотесты один
  раз под ним; нет — в CHANGELOG «API под 3.8 не проверено, у пользователей 3.13».
- **Самотест запуска вместо `selftest-sm-run-ps1.mjs`** (бесплатно): каждая командная строка из `SKILL.md` дословно
  запускается из PowerShell 5.1 в обёртке CLM (как в `selftest-to-html-pack.mjs`) и из Git Bash, путь с пробелом и
  кириллицей; выходные файлы совпадают байт в байт. Стенд ходит через Git Bash, пром — через PowerShell; без этого
  самотеста `run.ps1` не снимается.
- Стенд: SM-GAPS ×4 по одному прогону (≈ $10, одобрено архитектором), грейд после всех четырёх. Условие: по журналам
  каждый из пяти скриптов вызван агентом хотя бы раз; не дошёл до `promote` или `edges` — их закрывает самотест запуска,
  платных прогонов не добавлять.
- `.sh` удаляются тем же коммитом, что появляются `.py`, после зелёного стенда — не раньше.
- Дальше, если: расхождения — только из списка, самотесты зелёные, стенд в порогах. Иначе — откат среза, bash остаётся.
