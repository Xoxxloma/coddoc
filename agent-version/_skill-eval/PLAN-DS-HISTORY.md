# PLAN-DS-HISTORY — `deep-search`: откуда взялось поведение

Статус: выполнен, запись 5.87 в CHANGELOG, ветка `feat/deep-search-history`.

Основа: идея `/why` из отбора плагинов 2026-10-30. Отдельного скилла нет: всё лежит в Шаге 6 `deep-search`.

## 0. Что решено

| Вопрос | Решение |
|---|---|
| Форма | Шаг 6 в `deep-search`, версия 1.3.0. Команды `/why` нет |
| Обещание | Откуда поведение взялось и какой задачей пришло. Не причина: она часто нигде не записана |
| Основа ответа | История git. Спеки может не быть: код бывает старше неё |
| Конец цепочки | Номер задачи. Трекер не читаем |
| Причина | Только дословная цитата из комментария в коде, текста коммита или документа задачи. Нет цитаты → «не записана» |
| Документ | Дополнение: нашёлся — читаем, нет — «документа нет» |
| Номер | Только из текста коммита-источника. Нет → отдаём, что есть, и дальше не идём: слияния и ветки не смотрим |
| Обрезанный клон | Одна строка отказа с подсказкой `git fetch --unshallow`, история не читается |
| Скрипты | Нет. Агент сам запрашивает историю у git, файлов не пишет |
| git | Только чтение истории на Шаге 6, без `fetch` |
| Разведчик | `reference/brief.md` без правок |
| Спека | `from-spec.md` берёт разведчика и раздел «Шаг 3 — сверка ссылок»; номер и заголовок шага не меняем |
| `docs/` | Не читаем, правило 5.71 в силе |

## 1. Маршрут в Шаге 1

| Вопрос | Что делает скилл |
|---|---|
| О решении: «почему так сделали», «откуда это взялось», «так задумано?» | Шаги 2–3, затем Шаг 6; ответ и блок истории одним сообщением |

| Уточнение после ответа: «а почему так?» | Сразу Шаг 6 по строкам этого ответа |

Шаги истории и форма ответа — в `reference/history.md`.

## 2. Что упрощено 2026-11-02

Три круга ревью до первого прогона дали 7 находок, из них 3 про поиск номера в слияниях и 2 про обрезанный клон.
Обе темы убраны из текста, а не дочинены:

- Поиск номера в слияниях убран: определить, какое слияние принесло коммит, можно только угадыванием. Проверенные и
  отвергнутые варианты: первое слияние после коммита, проверка `rev-list --count`, `name-rev`.
- Разбор границы обрезанного клона заменён отказом: самому старому коммиту клона git приписывает весь файл.

## 4. Открыто

- Данные с прода: обрезаны ли клоны, доля коммитов с номером, цела ли кириллица. Клоны обрезаны → шаг без
  `git fetch --unshallow` не работает.
- Перенос кода между файлами: история строки может оборваться, ответ кончается этим коммитом. Отдельно не лечим.
- Вызов из спеки с новой строкой запрета не мерили.

## 5. Не входит

- Чтение трекера.
- «Почему этого нет, кто убрал».
- Вход готовой ссылкой `файл:строка`.
- История из интервью спеки.
- Строки «выбрали X, не Y» из `PLAN-FROM-POCOCK.md`, п.6.
