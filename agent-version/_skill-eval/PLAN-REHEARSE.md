## 0. Что решено

| Вопрос | Решение |
|---|---|
| Форма | Отдельный скилл `agent-version/rehearse/`, вызов вручную: `/rehearse <файл> [роль]` |
| Обещание | Вопросы, которые зададут на встрече, и список слабых мест по ответам аналитика. Не оценка документа |
| Чем не `spec-review` / `spec-readiness` | Приёмка — форма; готовность — исполнители (бэкенд, фронтенд, стык), списком. Репетиция — принимающая сторона, диалогом |
| Роли | Заказчик, архитектор, безопасник. Одна роль за запуск. Роль не названа → гипотеза по типу: БТ → заказчик, спека → архитектор, прочее → спросить с вариантами |
| Документ | Любой документ задачи (`.md`) |
| Кто готовит вопросы | Субагент с чистым контекстом: документ, контекст, задание, карточка роли. Ведущий документ не читает: писал его в той же сессии → вопросы мягкие |
| Контекст | Документ; у спеки — документ сверху (БТ, баг-репорт или запрос на правку, как в `spec-review`); `context/`; карточки `services/` сервисов, названных в документе |
| Опора вопроса | Цитата с путём и номером строки — из документа или контекста. Про чужой сервис — только то, что в его карточке; контракт чужого сервиса не требовать |
| Ход | 5–7 вопросов, по одному. На уклончивый ответ — одно уточнение. «Хватит» → сразу итог |
| Итог | По ответам: назван раздел, где ответ есть → снят; посылка вопроса опровергнута → снят; ответ словами → «впишите в документ»; «не знаю», «уточню» → «решить до встречи» |
| Выход | Только чат. Файлов нет, документ не правится |
| Безопасник | Спрашивает и про персональные данные, журналы, доступ: вычеркнутое из шаблона спеки к репетиции не относится |
| Сверка опор | Ведущий открывает строку каждой опоры (±2 строки, как Шаг 3 `deep-search`); цитаты нет — вопрос убран, в итоге число убранных |
| Скрипты | Нет в 1.0.0. Скрипт сверки (как в `retro`) — только если стенд покажет, что ведущий сверку пропускает |

## 2. Стенд (С3)

- Модель `claude-sonnet-5`. Пилот — по одному прогону на пробу; пул — после пилота, «N проб × M прогонов ≈ $X».
- Двойник аналитика — карточка в стиле `twin-objector.md`: что аналитик знает сверх документа, где в документе ответ,
  по умолчанию — «не знаю». Карточки до пула — слепому прочтению свежим субагентом.
- Документы — готовые БТ и спека из фикстур; подобрать так, чтобы спека называла соседний сервис с карточкой.
- Документы не из медицины (не CHN-4, не MED-77 и подобные): пример в `brief.md` — про врача и анализы, на таком
  документе не отличить вопрос по документу от списанного с примера.
- Ловушка выдумки: в карточке соседнего сервиса нет «очевидного» факта. Считаем вопросы, которые его утверждают.
- Скриптом: цитата каждого вопроса есть в названном файле; один вопрос на сообщение; пункт итога с ответом двойника
  «не знаю» стоит в «решить до встречи».

**Собрано (2026-11-03).** Фикстура `REH-SHT`: спека и БТ `SHT-410` (шаттл, проверка пропуска), карточки `badge-service`,
`shuttle-api`, `shuttle-web`; у `org-directory` карточки нет; `context/access-rules.md` — для безопасника. Пробы
`reh-arch`, `reh-sec`, `reh-cust`, `reh-stop` в `run-ctx-v2.sh`; конец диалога — строка «Задано вопросов» в ответе
(`RT_DONE_ANSWER`, новая переменная пула, пусто — как было). Оценщик `grade-reh.mjs`, `--selftest` 6/6. Ловушки:
служба пропусков «шлёт события», «знает офис», «отдаёт ФИО» — в карточке этого нет.

**Зелёный прогон** (записано до прогонов): субагент запущен; ведущий документ целиком не читал; записей нет; вызовов
за песочницу нет (иначе «не измерено»); вопросов 5–7, по одному на сообщение; каждая показанная опора есть в файле
(±2 строки); итог есть, группы сходятся с ответами двойника; у `reh-stop` итог сразу после «Хватит», «задано 3».
Справочно: дословность вопросов из блока субагента, опоры блока мимо сверки, опоры на `context/` и `services/`,
вопросы с признаками ловушки — глазами.

**Пилот 1** (`runs/2026-11-03-reh-p1-{arch,sec,cust,stop}`, 4 × 1, `claude-sonnet-5`, $2.81 + двойник $0.54). После

ответил по карточке не на тот вопрос, скилл положил в «решить до встречи» вместо «вписать» — по существу спорно.
Субагент запущен везде, документ ведущий не читал, опоры сверял (`Read` по 5 строк), вопросы дословно из блока
6 из 6, выдумок про чужой сервис нет.

- **Дефект скилла (основной путь):** у вопроса две опоры — показана одна. У `sec` так у 4 вопросов из 6, все три опоры
  на `context/` до аналитика не дошли; у `arch` — опора на `services/shuttle-api.md`. Ведущий сверил обе, показал первую:
  в шаблоне Шага 4 одна строка «Опора:». Ревью называло это боковым стыком.
- **Стенд:** `twin-objector.md` смешивал разделы карточки и досочинял («уникальный индекс»), в `stop` остановил на 2-м
  вопросе → свой строгий промпт `twin-rehearse.md` (один раздел дословно, первый подходящий сверху), признак в
  `twin-stop.md` — только номер «3/». Оценщик: ответ фонового субагента — из уведомления `task_notification`;
  «Нет, …, не знаю» — это «не знаю»; смешанный ответ — любая группа; у `stop` «задано» = вопросов до остановки.
