# Фикстура OCC-CR-VAL — мелкая правка меняет ЗНАЧЕНИЕ, которое отдают четыре места

Проба `occ-cr-val`, kind `positive`, серия OCC («места того же события»). Проверка, что поведение
«§6.2 перечисляет места по карточке» не подогнано под события: здесь меняется не поле события, а
вычисляемое значение `availability`, которое `catalog-api` отдаёт из трёх ручек и ночной выгрузки.
Режим — мелкая правка (образец `TS-CR`), спека пишется одним ходом.

## Поле, правило, места

Поле — `availability`: `available` \| `reserved` \| `temporarily_unavailable` \| `unavailable`.
Правило вычисления — одно место: «Бизнес-правила» → `Copy`, `services/catalog-api.md:86-91`, словами
(«читателю — „недоступен“»); случай правки — `:89` (`in_restoration`). В блоках ручек правила нет —
только перечень значений и фраза «доступность экземпляра для читателя».

| id | Место (как в карточке) | Строки | Что карточка говорит о значении у места | От правила `:89` |
|---|---|---|---|---|
| `copy-card` | `GET /v1/copies/{copyId}` | блок `:250`, поле `:253` | ничего сверх общего перечня | 161 |
| `search` | `GET /v1/search` | блок `:300`, поле `:305-306` | ничего сверх общего перечня | 211 |

## Ловушки и шум

1. **Похожее имя, другое поле (`trap`).** `GET /v1/me/holds` (`:281`), поле `expectedAvailability` (`:285`)
   — «ожидаемая дата готовности брони», дата, правилом доступности не считается. `grep -i availability`
   его находит — так и задумано.
2. **Тот же путь, не место.** `PATCH /v1/copies/{copyId}` (`:358`) — правка шифра; регэксп `copy-card`
   отсекает его по методу.
3. **Похожие ручки без `availability`.** `GET /v1/copies/by-inventory/{inventoryNo}` (`:243`) — экземпляр
   для стойки, со статусом фонда; `GET /v1/search/suggest` (`:310`) — подсказки без экземпляров;
   регэкспы мест их не ловят.
4. **Вторая выгрузка.** `exportCirculationStats` (`:599`) — статистика выдач для управления культуры, без
   доступности; регэксп `partner-feed` её не ловит.
5. **Тот же случай, но не место.** Ручки реставрации `:449`, `:456` — про реставрацию, `availability` не
   отдают. Строка «передача и приём прежние» в §6.2 законна (из «Что рядом остаётся прежним»).
6. **Место, которого нет нигде, кроме карточки.** Выгрузку не называет ни запрос, ни аналитик. Её
   пропуск — ровно прод-срыв.

## Значения (`valueTokens` и `allow`)

`valueTokens`: `unknown`, `temporarily_unavailable`, «временно недоступ…». Законны: у трёх ручек —
`temporarily_unavailable` / «временно недоступен» (требование документа сверху + общее правило); у
выгрузки — `unknown` (карточка `:610`). Выдумка: `unknown` у ручки; `temporarily_unavailable` у выгрузки —
правка её содержимое не меняет, реставрация уходила `unknown` и уходит `unknown`.

Текущий `grade-occ.mjs` проверяет «выдумано» и у места `valued` через его `allow`: строка выгрузки «в файле
`unknown`; после правки — `temporarily_unavailable`» краснеет («выдумано 0: partner-feed»). Обратный риск:
верная строка «`temporarily_unavailable` в файл не попадает» тоже покраснеет — токен стоит в строке выгрузки.

Регэксп `partner-feed` — только выгрузка, фид, сводный каталог, `regcat-sftp` и имя задачи; голого
«партнёр» нет (иначе местом засчитается строка про читателя-партнёра), `regcatCode` у ручек филиалов и
«реестр сводного каталога» у `Branch` не ловятся.

## Исход

| | Что в спеке |
|---|---|
| **Красный** | §6.2 без хотя бы одного из четырёх мест (обычно без выгрузки или без поиска/списка — приёмка называет только «экземпляр»); `unknown` у ручки; `temporarily_unavailable` у выгрузки; `GET /v1/me/holds` / `expectedAvailability` в перечне мест |
| **Зелёный** | §6.2 перечисляет четыре места, каждое своей строкой, 🔵 и ссылка на `services/catalog-api.md`; одна общая проверка — «на реставрации — `temporarily_unavailable`, остальные состояния — как до правки»; у выгрузки — `unknown` по карточке |

Регэкспы проверены через `parseTruth` / `gradeSpec` на синтетических §6.2: зелёный, красный (одно место
+ ловушка), `unknown` у поиска («выдумано 0: search: unknown»).

## Рукопись, а не выход скилла

Запрос написан руками по шаблону `change-request-doc/SKILL.md` (конец файла). «Интерфейс — нет»
поставлено нарочно: подпись «Временно недоступен» у фронтов уже есть, иначе спека уйдёт в §4 и вопросы
по экранам `opac-web` без карточки. `_manifest.txt` не заведён — его заводит раннер.

Строка раннера: `  occ-cr-val) FIXTURE=OCC-CR-VAL; PROMPT_FILE=w-prompt.txt; SKILL=technical-spec-doc ;;`
