# notify-service — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Заметки команды

> Скопировано из `services/manifest.yaml`, поле `notes`. Ведёт человек; `service-map` копирует
> при каждом скане дословно.

Тексты уведомлений ведёт контент-команда через админку шаблонов.
Мобильные приложения ученика и наставника в манифест не входят; токены устройств они регистрируют здесь.

## Назначение

Сервис доносит до ученика и наставника то, что произошло на курсе и с домашними заданиями, не заставляя их держать приложение открытым: пуш на телефон, запись в ленте уведомлений и еженедельное письмо. Он поддерживает регистрацию устройств, сборку пушей из событий соседних сервисов по шаблонам, склейку частых уведомлений, тихие часы и отключение отдельных видов уведомлений получателем, повторную доставку и журнал доставки для поддержки. Главные объекты — устройства получателей, уведомления с попытками доставки, настройки получателя и шаблоны текстов.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Получать пуши на телефон после входа в приложение | Ученик, наставник |

| Перестать получать пуши на устройство после выхода из приложения | Ученик, наставник |

| Отметить все уведомления прочитанными | Ученик, наставник |
| Отключить отдельный вид уведомлений — в ленту он всё равно попадает | Ученик, наставник |
| Задать тихие часы — пуши копятся и приходят одним пакетом после | Ученик, наставник |
| Получать еженедельное письмо со сводкой | Ученик |
| Отписаться от письма по ссылке без входа | Любой получатель письма |
| Отредактировать текст шаблона уведомления | Контент-редактор |

| Посмотреть, дошло ли уведомление до конкретного человека | Поддержка |

## Бизнес-правила

### `Device` — устройство для пушей
- активно (`active`) — при входе в приложение ученика или наставника; один токен — одно устройство, до 5 активных на человека, шестое вытесняет самое старое
- отозвано (`revoked`) — при выходе из приложения, при ответе службы пушей «токен недействителен» или после 60 дней без открытия приложения

### `Notification` — уведомление получателю
- в очереди (`queued`) — создано из события; ждёт склейки или конца тихих часов
- отправлено (`sent`) — принято хотя бы одним устройством или почтой
- заглушено (`muted`) — получатель отключил этот вид; запись в ленте есть, на устройство не уходит
- не доставлено (`failed`) — ни одно устройство не приняло за три попытки
- открыто (`opened`) — получатель нажал на пуш или открыл запись в ленте

### сообщение «пуш „Работа проверена“»
- по вердикту наставника из `homework-service`; получает ученик; без склейки

### сообщение «пуш „Работа ждёт проверки“»
- по событию `homework-service`; получает наставник; не больше одного пуша в час, остальные склеиваются в «N работ ждут проверки»

### сообщение «пуш „Скоро срок сдачи“»
- по событию `homework-service` за сутки до срока; получает ученик; в тихие часы не копится, а отбрасывается — к утру он неактуален

### сообщение «пуш „Новый комментарий к работе“»
- по событию `homework-service`; получает каждый из адресатов комментария; склейка 5 минут по одной работе

### сообщение «пуш „Апелляция рассмотрена“»
- по событию `homework-service`; получают ученик и, если балл изменён, наставник

### сообщение «пуш „Новый урок“»
- по публикации урока в `course-service`; получают ученики группы; склейка 30 минут по курсу

### сообщение «пуш „Вебинар через 15 минут“»
- за 15 минут до начала вебинара; получают ученики группы и наставник; в тихие часы тоже уходит

### сообщение «еженедельная сводка»
- письмо ученику по понедельникам: новые уроки, близкие сроки, проверенные работы за неделю; не уходит, если за неделю ничего не было или ученик отписался

### сообщение «пуш открыт» (`notify.push.opened`)
- при открытии пуша или записи ленты; уходит в шину для аналитики, людям не адресовано

### ограничение «тихие часы»
- условием управляет сам получатель (роли `student` и `mentor`): в тихие часы пуши копятся и уходят одним пакетом по их окончании, лента пополняется сразу; пуш о вебинаре уходит и в тихие часы

## Публичный контракт

### `GET /health`
Проверка живости для балансировщика.

### `GET /ready`
Готовность к трафику: база, Redis и брокер доступны.

### `GET /v1/admin/deliveries`
Журнал доставки по получателю.
сущности: → список `Notification` с `DeliveryAttempt[]`
- фильтр по `userId` обязателен; период — не больше 30 дней
- доступно роли `support`
- текст уведомления отдаётся как ушёл, после подстановки в шаблон

### `GET /v1/admin/templates`
Шаблоны текстов уведомлений.
сущности: → список `Template`
- доступно роли `content_editor`

### `PUT /v1/admin/templates/{kind}`
Правка шаблона вида уведомления.
сущности: ← `title`, `body` · → `Template`
- в шаблоне можно использовать только переменные вида; неизвестная переменная — `400`
- заголовок до 50 знаков, текст до 180; длиннее — `400`: служба пушей обрежет
- новый текст действует для уведомлений, созданных после сохранения
- доступно роли `content_editor`

### `POST /v1/admin/test-push`
Пробный пуш по шаблону на свои устройства.
сущности: ← `kind`, `sample` · → не сущность, ответ (`delivered: int`)
- уходит только на устройства вызывающего; в ленту не пишется
- доступно роли `content_editor`

### `POST /v1/devices`
Регистрация устройства для пушей.
сущности: ← `token`, `platform`, `app` · → `Device`
- `app`: `student` \| `mentor` — в какое приложение придут пуши этого устройства
- тот же токен у другого человека — переезжает к вызывающему, у прежнего отзывается
- шестое активное устройство вытесняет самое давно открытое

### `DELETE /v1/devices/{deviceId}`
Отзыв устройства при выходе из приложения.
сущности: → —
- только своё устройство; чужое — `404`
- повтор по отозванному безопасен

### `GET /v1/email/unsubscribe/{token}`
Отписка от еженедельного письма по ссылке из письма.
сущности: → не сущность, страница «Вы отписаны»
- без входа: токен одноразовый, живёт 90 дней
- отписывает только от письма; пуши и лента не меняются

### `GET /v1/inbox`
Лента уведомлений вызывающего.
сущности: → список `Notification`, без `DeliveryAttempt`
- последние 180 дней, по убыванию времени, страницами по 50
- заглушённые виды в ленте есть
- `link` у записи — та же ссылка, что ушла в пуш

### `POST /v1/inbox/read-all`
Отметить всё прочитанным.
сущности: → не сущность, ответ (`updated: int`)
- открытыми записи при этом не считаются: `notify.push.opened` не шлётся

### `POST /v1/inbox/{notificationId}/open`
Отметка открытия уведомления.
сущности: → `Notification`
- переводит в `opened`; повтор безопасен и второго события не даёт
- после коммита публикует `notify.push.opened`

### `GET /v1/preferences`
Настройки уведомлений вызывающего.
сущности: → `Preference`, `QuietHours`
- записи нет — всё включено, тихих часов нет

### `PUT /v1/preferences`
Включение и отключение видов уведомлений.
сущности: ← `muted[]` · → `Preference`
- вид «Вебинар через 15 минут» отключить нельзя — `400`
- отключение не трогает уже отправленное

### `PUT /v1/preferences/quiet-hours`
Тихие часы получателя.
сущности: ← `from`, `to`, `timezone` · → `QuietHours`
- интервал может переходить через полночь; длиннее 12 часов — `400`
- `timezone` — из списка IANA; неизвестная — `400`

## События

### потребляет `homework.check.done`
Вердикт по работе — пуш ученику «Работа проверена».
- группа `notify-homework`, offset коммитится после записи уведомления в БД
- читает `checkId`, `studentId`, `verdict`, `score`, `deeplink`; остальные поля игнорирует
- по нажатию на пуш открывается `deeplink` из события; та же ссылка — у записи в ленте
- текст по шаблону: «Зачтено, N баллов» у `accepted`, «Нужна доработка» у `revision`
- повтор безопасен: дубль по `checkId` за сутки отбрасывается

### потребляет `homework.check.due`
Работа ждёт проверки — пуш наставнику.
- группа `notify-homework`, offset коммитится после записи уведомления в БД
- читает `mentorId`, `submissionId`, `deeplink`
- пуш уходит только на устройства с `app: mentor`
- склейка — не больше одного пуша в час одному наставнику

### потребляет `homework.comment.added`
Новый комментарий к работе — пуш адресатам.
- группа `notify-homework`, offset коммитится после записи уведомлений в БД
- читает `submissionId`, `authorRole`, `recipientIds`
- ученику пуш открывает его работу, наставнику и куратору — работу в приложении наставника
- склейка 5 минут по паре работа + получатель

### потребляет `homework.appeal.resolved`
Решение по апелляции — пуш ученику и наставнику.
- группа `notify-homework`, offset коммитится после записи уведомлений в БД
- читает `appealId`, `studentId`, `mentorId`, `decision`, `newScore`
- наставнику — только при `upheld`

### потребляет `homework.deadline.soon`
Близкий срок сдачи — пуш ученику.
- группа `notify-homework`, offset коммитится после записи уведомления в БД
- название задания берёт ручкой `homework-service` по `assignmentId`; не ответил — пуш уходит без названия
- `hasDraft: true` меняет текст на «Черновик ждёт отправки»

### потребляет `course.lesson.published`
Опубликован урок — пуш ученикам группы.
- группа `notify-course`, offset коммитится после записи уведомлений в БД
- читает `lessonId`, `courseId`, `cohortIds`, `title`
- склейка 30 минут по курсу: несколько уроков подряд — один пуш «Новые уроки: N»

### потребляет `course.webinar.scheduled`
Назначен вебинар — запоминаем время для пуша.
- группа `notify-course`, offset коммитится после записи в БД
- читает `webinarId`, `courseId`, `cohortIds`, `startsAt`; перенос вебинара приходит тем же событием и заменяет время
- сам пуш ставит задача `scheduleWebinarPushes`

### публикует `notify.push.opened`
Получатель открыл уведомление.
- `notificationId: string`, `userId: string`, `kind: string`, `openedAt: iso8601`
- ключ партиции — `userId`
- шлётся после коммита отметки, один раз на уведомление
- при «прочитать все» не шлётся

## Фоновые задачи

### `flushCoalesced`
Отправляет склеенные уведомления.
- расписание — каждые 30 секунд
- берёт из Redis группы склейки, у которых истекло окно вида, и отправляет одним пушем со счётчиком
- окно истекло во время тихих часов — группа переходит в очередь тихих часов

### `releaseQuietHours`
Отправляет накопленное за тихие часы.
- расписание `*/5 * * * *`
- берёт получателей, у которых тихие часы закончились, и отправляет накопленное одним пакетом: до 3 последних пушей, остальное — счётчиком «и ещё N»
- «Скоро срок сдачи», накопленный за ночь, отбрасывается

### `retryFailedPushes`
Повторяет недоставленные пуши.
- расписание `*/2 * * * *`
- до трёх попыток с паузой 2, 10 и 30 минут; после третьей — `failed`
- ответ «токен недействителен» не повторяется: устройство сразу отзывается

### `pruneDevices`
Отзывает заброшенные устройства.
- расписание `0 5 * * *`
- отзывает устройства без открытия приложения 60 дней
- событий не публикует

### `purgeInbox`
Чистит ленту.
- расписание `0 4 * * *`
- удаляет уведомления и попытки доставки старше 180 дней

### `scheduleWebinarPushes`
Пуши о начале вебинара.
- расписание — каждую минуту
- берёт вебинары, которые начинаются через 15 минут, и шлёт пуш ученикам групп и наставнику; пуш ведёт на страницу вебинара `eduapp://webinar/<webinarId>`
- тихие часы и отключённые виды не учитываются
- пропущенная минута не догоняется: если сервис лежал, пуш о вебинаре не уйдёт

### `sendWeeklyDigest`
Еженедельное письмо ученику.
- расписание `0 10 * * 1`
- собирает за неделю по ленте ученика: новые уроки, проверенные работы, близкие сроки
- пустую неделю и отписавшихся пропускает
- пачками по 500 писем, пауза 1 секунда между пачками — лимит SMTP-шлюза

## Владеет данными

### `Device`
Устройство получателя.
- `id`: `uuid`
- `userId`: `uuid`
- `token`: `string`
- `platform`: `android` \| `ios`
- `app`: `student` \| `mentor`
- `status`: `active` \| `revoked`
- `lastOpenedAt`: `timestamp`
— уникальность по `token`

### `Notification`
Уведомление одному получателю.
- `id`: `uuid`
- `userId`: `uuid`
- `kind`: `string` — вид уведомления, ключ шаблона
- `title`: `string`
- `body`: `string`
- `link`: `string?` — ссылка, которую откроет приложение; `null` у письма
- `status`: `queued` \| `sent` \| `muted` \| `failed` \| `opened`
- `sourceEventKey`: `string` — ключ дубля: `checkId`, `appealId` и т. п.
- `createdAt`: `timestamp`

### `DeliveryAttempt`
Попытка доставки на устройство или почту.
- `id`: `uuid`
- `notificationId`: `uuid`
- `deviceId`: `uuid?` — `null` у письма
- `result`: `accepted` \| `rejected` \| `token_invalid` \| `timeout`
- `attemptedAt`: `timestamp`

### `Preference`
Отключённые виды уведомлений получателя.
- `userId`: `uuid`
- `muted`: `string[]`
- `emailUnsubscribed`: `boolean`

### `QuietHours`
Тихие часы получателя.
- `userId`: `uuid`
- `from`: `time`
- `to`: `time`
- `timezone`: `string`

### `Template`
Шаблон текста вида уведомления.
- `kind`: `string`
- `title`: `string`
- `body`: `string`
- `variables`: `string[]` — допустимые подстановки, задаются кодом
- `updatedBy`: `uuid`
- `updatedAt`: `timestamp`

### `WebinarSlot`
Копия времени вебинара для пуша.
- `webinarId`: `uuid`
- `courseId`: `uuid`
- `cohortIds`: `uuid[]`
- `startsAt`: `timestamp`
- `pushedAt`: `timestamp?`
— источник правды — `course-service`; здесь меняется только событием `course.webinar.scheduled`

## Зависит от
| Сервис или система | Зачем |

| `homework-service` | название задания для пуша о близком сроке |

| `smtp-gateway` | отправка еженедельного письма; вне манифеста |

## Роли и доступ
| Роль | Что может |
|---|---|
| `student` | регистрировать свои устройства, читать свою ленту, менять свои настройки и тихие часы |
| `mentor` | то же, что ученик, для приложения наставника |
| `content_editor` | менять шаблоны текстов, слать пробный пуш себе |
| `support` | смотреть журнал доставки по любому получателю |
| без входа | отписаться от письма по одноразовой ссылке; больше ничего не видно |
