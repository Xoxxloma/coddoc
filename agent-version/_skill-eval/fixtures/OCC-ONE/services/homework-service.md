# homework-service — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Заметки команды

> Скопировано из `services/manifest.yaml`, поле `notes`. Ведёт человек; `service-map` копирует
> при каждом скане дословно.

Канонический владелец домашних заданий, работ учеников и проверок.
Закрепление наставников за группами ведёт mentor-service; здесь — только его копия для очереди проверки.
Порог заимствований задаётся на курс в course-service; здесь он только читается.

## Назначение

Сервис даёт онлайн-школе довести домашнее задание урока от публикации методистом до зачёта: ученик сдаёт работу к сроку, наставник её проверяет по критериям задания и либо зачитывает с баллом, либо возвращает на доработку, а ученик сдаёт снова. Он поддерживает публикацию и копирование заданий между запусками курса, автосохранение черновика работы, сдачу и повторную сдачу работ с файлами, проверку текста на заимствования, очередь проверки наставника и передачу работы другому наставнику, переписку ученика и наставника по работе, апелляции на балл, продление срока куратором и учёт пропущенных сроков. Главные объекты — домашние задания уроков с критериями оценки, работы учеников с попытками, проверки наставников и апелляции; о вердикте, комментариях, близком сроке и решении по апелляции сервис сообщает ученику, а о работах, которые ждут проверки, — наставнику.

## Бизнес-правила

### `Assignment` — домашнее задание к уроку
- черновик (`draft`) — при создании методистом или копировании из прошлого запуска; ученикам не видно, можно удалить
- опубликовано (`published`) — методист опубликовал; ученики группы видят задание и могут сдавать работу до срока; удалить нельзя, снять с публикации — пока нет сдач
- в архиве (`archived`) — курс завершён; новые работы не принимаются, проверка уже сданных продолжается

### `Submission` — работа ученика по заданию
- сдана (`submitted`) — ученик сдал работу или сдал её повторно; попадает в очередь проверки наставника группы
- в проверке (`checking`) — наставник взял работу в проверку; ученик отозвать её уже не может
- зачтена (`accepted`) — наставник зачёл работу с баллом; дальше работу не меняют, повторная сдача невозможна, балл меняется только апелляцией
- на доработке (`revision`) — наставник вернул работу с комментарием; ученик может сдать новую попытку, срок сдачи прежний
- отозвана (`recalled`) — ученик отозвал работу до проверки; может сдать заново
- снята (`withdrawn`) — ученика отчислили с курса; непроверенные работы снимаются без вердикта

### `Appeal` — апелляция ученика на балл
- открыта (`open`) — ученик оспорил балл зачтённой работы в течение 7 дней после вердикта; одна апелляция на проверку
- удовлетворена (`upheld`) — куратор изменил балл; работа остаётся зачтённой, проверка наставника хранит прежний балл рядом с новым
- отклонена (`rejected`) — куратор оставил балл; повторная апелляция по той же проверке невозможна

### `SimilarityCheck` — проверка работы на заимствования
- ждёт результата (`pending`) — при сдаче попытки с текстом от 500 знаков; на сдачу и проверку наставником не влияет
- чисто (`clean`) — доля заимствований не выше порога курса
- помечена (`flagged`) — доля выше порога курса; работа попадает в список куратора, наставник видит пометку в очереди
- ошибка (`failed`) — внешний сервис не ответил за сутки; повторно не запускается, наставник видит «не проверено»

### сообщение «работа проверена»
- при вердикте наставника по работе (`homework.check.done`); получает ученик пушем в приложении ученика, наставник — нет
- без склейки: каждый вердикт — отдельный пуш

### сообщение «работа ждёт проверки»
- работа ждёт наставника, а он о ней ещё не знает (`homework.check.due`); получает наставник пушем в приложении наставника, ученик — нет
- по одной работе — не чаще раза в сутки

### сообщение «скоро срок сдачи»
- за сутки до срока задания ученику, который ещё не сдал работу (`homework.deadline.soon`); при продлении — за сутки до продлённого срока
- один раз на пару задание + ученик; ученику с черновиком тоже уходит

### сообщение «срок сдачи пропущен»
- ученик не сдал работу к сроку задания с учётом продления (`homework.deadline.missed`); получает журнал успеваемости, ученику пуш не шлётся

### сообщение «новый комментарий к работе»
- при комментарии ученика или наставника к работе (`homework.comment.added`); получает другая сторона, автор комментария — нет
- комментарий куратора получают и ученик, и наставник

### сообщение «апелляция рассмотрена»
- при решении куратора по апелляции (`homework.appeal.resolved`); получает ученик всегда, наставник, выставивший балл, — только если балл изменён

### ограничение «приём работ по курсу закрыт»
- условием управляет `course-service`: курс завершён — сдача и повторная сдача отвергаются с сообщением «Курс завершён, приём работ закрыт»; проверка уже сданных продолжается

### ограничение «приём апелляций по курсу закрыт»
- условием управляет роль `curator`: приём закрыт — новые апелляции отвергаются с сообщением «Приём апелляций по курсу закрыт»; открытые рассматриваются как обычно

## Публичный контракт

### `GET /health`
Проверка живости для балансировщика.

### `GET /metrics`
Метрики для Prometheus.

### `GET /ready`
Готовность к трафику: база и брокер доступны.

### `GET /v1/appeals`
Апелляции курса для куратора.
сущности: → список `Appeal`
- фильтр по `courseId` обязателен, по `status` — по желанию
- доступно роли `curator`
- сортировка по дате подачи, старые сверху

### `POST /v1/appeals`
Подача апелляции учеником.
сущности: ← `checkId`, `reason` · → `Appeal` в `open`
- только по своей зачтённой работе и только по её последней проверке
- позже 7 дней после вердикта — `409` «Срок апелляции прошёл»
- по этой проверке апелляция уже была — `409`
- приём апелляций по курсу закрыт — `423` «Приём апелляций по курсу закрыт»
- `reason` от 20 до 2 000 знаков; иначе — `400`

### `GET /v1/appeals/{appealId}`
Апелляция с проверкой и баллами по критериям.
сущности: → `Appeal`, `Check`
- ученик видит только свои; куратор — по своим курсам

### `POST /v1/appeals/{appealId}/resolve`
Решение куратора по апелляции.
сущности: ← `decision`, `newScore?`, `comment` · → `Appeal`
- доступно роли `curator`
- `upheld` требует `newScore` от 0 до `maxScore` задания и не равный прежнему; `rejected` его не принимает
- при `upheld` пишет новый балл в проверку, прежний сохраняется в `Check.originalScore`; статус работы не меняется
- апелляция уже рассмотрена — `409`
- после коммита публикует `homework.appeal.resolved`

### `DELETE /v1/assignments/{assignmentId}`
Удаление задания.
сущности: ← `assignmentId` · → —
- только в статусе `draft`; опубликованное — `409`
- критерии задания удаляются вместе с ним
- доступно роли `methodist`

### `GET /v1/assignments/{assignmentId}`
Карточка задания.
сущности: → `Assignment`, `RubricCriterion[]`
- ученику черновик не отдаётся — `404`, как будто задания нет
- `dueAt` отдаётся с учётом продления, если оно есть у вызывающего ученика
- сервисному клиенту `notify-service` отдаются только `title` и `dueAt`

### `PATCH /v1/assignments/{assignmentId}`
Изменение описания и срока задания.
сущности: ← `title?`, `description?`, `dueAt?` · → `Assignment`
- `dueAt` в прошлом — `400`
- перенос срока не трогает выданные продления: у ученика с продлением действует продление
- перенос срока сбрасывает отметку «скоро срок сдачи» у тех, кто ещё не сдал
- доступно роли `methodist`

### `GET /v1/assignments/{assignmentId}/draft`
Черновик работы вызывающего ученика.
сущности: → `SubmissionDraft`
- черновика нет — `204`, а не `404`

### `PUT /v1/assignments/{assignmentId}/draft`
Автосохранение черновика работы.
сущности: ← `text`, `fileIds[]` · → `SubmissionDraft`
- последняя запись выигрывает: версия не проверяется, два устройства перезаписывают друг друга
- после сдачи работы черновик удаляется
- текст до 100 000 знаков; длиннее — `413`

### `POST /v1/assignments/{assignmentId}/extensions`
Продление срока сдачи ученику.
сущности: ← `studentId`, `newDueAt`, `reason` · → `Extension`
- доступно роли `curator`
- повторное продление тому же ученику заменяет прежнее, а не складывается
- `newDueAt` раньше срока задания — `400`
- работа ученика уже сдана — `409`: продлевать нечего

### `POST /v1/assignments/{assignmentId}/files/presign`
Ссылка на загрузку файла работы.
сущности: → не сущность, ответ (`uploadUrl`, `fileId`)
- до 10 файлов на попытку, до 50 МБ каждый; сверх — `400`
- разрешены pdf, docx, png, jpg, zip; прочее — `415`
- файл, так и не попавший в сдачу, живёт двое суток, потом его удаляет `purgeOrphanFiles`

### `POST /v1/assignments/{assignmentId}/publish`
Публикация задания.
сущности: → `Assignment`
- переводит `draft` → `published`; повтор по опубликованному безопасен и ничего не меняет
- задание без срока сдачи не публикуется — `400`
- задание с критериями, сумма весов которых не равна `maxScore`, не публикуется — `400`

### `GET /v1/assignments/{assignmentId}/rubric`
Критерии оценки задания.
сущности: → список `RubricCriterion`
- у задания без критериев — пустой список: наставник ставит один общий балл

### `PUT /v1/assignments/{assignmentId}/rubric`
Замена критериев оценки целиком.
сущности: ← список `RubricCriterion` без `id` · → список `RubricCriterion`
- по заданию уже есть проверка — `409`: критерии заморожены
- сумма весов не равна `maxScore` задания — `400`
- доступно роли `methodist`

### `GET /v1/assignments/{assignmentId}/stats`
Сводка по заданию.
сущности: → не сущность, агрегат по `Submission`
- `submitted: int`, `checking: int`, `accepted: int`, `revision: int`, `notSubmitted: int`
- `avgScore: number|null` — `null`, пока нет зачтённых; считается по последней проверке с учётом апелляций
- доступно ролям `methodist` и `curator`

### `POST /v1/assignments/{assignmentId}/submissions`
Сдача работы учеником.
сущности: ← `text?`, `fileIds[]` · → `Submission`
- первая сдача — до `dueAt` с учётом продления; после срока — `409` «Срок сдачи прошёл»
- повторная сдача — только из `revision` или `recalled`; это новая попытка (`attempt` + 1), срок не проверяется
- курс завершён — `423` «Курс завершён, приём работ закрыт»
- ученик не записан на курс по данным `course-service` — `403`
- ни текста, ни файлов — `400`
- текст от 500 знаков отправляется на проверку заимствований; результата сдача не ждёт
- наставнику при сдаче пуш не шлётся: работа появляется в его очереди

### `POST /v1/assignments/{assignmentId}/unpublish`
Снятие задания с публикации.
сущности: → `Assignment` в `draft`
- по заданию есть хотя бы одна сдача, включая отозванные — `409`
- доступно роли `methodist`

### `POST /v1/checks`
Вердикт наставника по работе.
сущности: ← `submissionId`, `verdict`, `score?`, `scores[]?`, `comment?` · → `Check`
- доступно наставнику, который взял работу в проверку; чужая работа — `403`
- работа не в `checking` — `409`; вердикт по одной попытке выносится один раз
- `accepted` требует балл от 0 до `maxScore` задания; `revision` требует `comment` и балла не принимает
- у задания с критериями балл — сумма `scores[]` по всем критериям, переданный `score` игнорируется; критерий пропущен — `400`
- пометка о заимствованиях вердикт не блокирует
- переводит работу в `accepted` или `revision` в одной транзакции с записью проверки
- после коммита публикует `homework.check.done`; в `deeplink` кладёт ссылку на урок задания `eduapp://lesson/<lessonId>` при любом вердикте

### `PUT /v1/courses/{courseId}/appeal-settings`
Приём апелляций по курсу.
сущности: ← `appealsOpen` · → не сущность, ответ (`courseId`, `appealsOpen`)
- доступно роли `curator`
- по умолчанию приём открыт; закрытие не трогает уже открытые апелляции

### `GET /v1/courses/{courseId}/assignments`
Все задания курса.
сущности: → список `Assignment`
- методисту — все, включая `draft`; куратору и наставнику — без `draft`
- группировка по `lessonId` в порядке уроков из `course-service`

### `POST /v1/courses/{courseId}/assignments/copy`
Копирование заданий из прошлого запуска курса.
сущности: ← `fromCourseId` · → список `Assignment` в `draft`
- копируются описание, `maxScore` и критерии; сроки не копируются — у копий `dueAt` пустой
- урок сопоставляется по порядковому номеру в курсе; урока с таким номером нет — задание пропускается и попадает в ответ в `skipped[]`
- повторное копирование создаёт новые черновики, а не обновляет прежние
- доступно роли `methodist`

### `GET /v1/curator/overdue`
Ученики с пропущенными сроками.
сущности: → не сущность, агрегат по `Assignment` и `Submission`
- `studentId: string`, `missed: int`, `lastMissedAt: iso8601`
- только по курсам, где вызывающий куратор
- ученик с продлением не считается пропустившим до конца продления

### `GET /v1/curator/similarity-flags`
Работы с пометкой о заимствованиях.
сущности: → список `SimilarityCheck` в `flagged` с работой
- только по курсам, где вызывающий куратор
- доля заимствований отдаётся процентом, источники — ссылками внешнего сервиса как есть

### `GET /v1/lessons/{lessonId}/assignments`
Задания урока.
сущности: → список `Assignment`
- ученику — только `published` и `archived`; методисту — все, включая `draft`
- порядок — по `dueAt`, задания без срока в конце

### `POST /v1/lessons/{lessonId}/assignments`
Создание задания к уроку.
сущности: ← `title`, `description`, `dueAt?`, `maxScore` · → `Assignment` в `draft`
- `courseId` берётся из урока в `course-service`, клиент его не передаёт
- урок не найден в `course-service` — `404`
- `maxScore` от 1 до 100; иначе — `400`
- доступно роли `methodist`

### `GET /v1/mentor/checks`
История проверок наставника.
сущности: → список `Check`, только вынесенные вызывающим
- период — не больше 90 дней; шире — `400`
- проверки по работам, переданным потом другому наставнику, остаются в истории автора
- балл, изменённый апелляцией, отдаётся рядом с исходным

### `GET /v1/mentor/queue`
Очередь проверки наставника.
сущности: → список `Submission`, только `submitted` и `checking`; только группы, закреплённые за вызывающим
- сортировка по `submittedAt`, старые сверху
- работа, взятая другим наставником, в очереди видна, но помечена `takenBy`
- у работы с `flagged` — пометка о заимствованиях; с `failed` — «не проверено»

### `POST /v1/mentor/queue/{submissionId}/release`
Вернуть взятую работу в очередь.
сущности: → `Submission`
- только свою работу в `checking`; переводит её в `submitted` и снимает `mentorId`
- событий не шлёт: работа просто снова видна в очереди группы

### `POST /v1/mentor/queue/{submissionId}/take`
Взять работу в проверку.
сущности: → `Submission`
- переводит `submitted` → `checking` и ставит `mentorId` вызывающего
- работа уже в `checking` у другого наставника — `409`; у того же — повтор безопасен

### `GET /v1/mentor/stats`
Статистика наставника за месяц.
сущности: → не сущность, агрегат по `Check`
- `checked: int`, `accepted: int`, `revision: int`, `avgHoursToCheck: number|null`, `appealsUpheld: int`
- `avgHoursToCheck` — от сдачи до вердикта; `null`, если проверок за месяц нет
- месяц — календарный, по времени школы (Europe/Moscow)

### `POST /v1/similarity/callback`
Результат проверки заимствований от внешнего сервиса.
сущности: ← `externalId`, `percent`, `sources[]` · → `SimilarityCheck`
- запрос без верной подписи — `401`
- неизвестный `externalId` — `404`; повтор по уже записанному результату безопасен и ничего не меняет
- порог берётся из настроек курса в `course-service` на момент ответа, а не на момент сдачи

### `GET /v1/students/{studentId}/deadlines`
Ближайшие сроки сдачи ученика.
сущности: → не сущность, агрегат по `Assignment`, `Extension` и `Submission`
- задания с несданной работой и сроком в ближайшие 14 дней, по возрастанию срока
- срок — с учётом продления
- ученик видит только свои; чужой `studentId` — `403`

### `GET /v1/students/{studentId}/extensions`
Действующие продления ученика.
сущности: → список `Extension`
- доступно роли `curator` и самому ученику

### `GET /v1/students/{studentId}/homework-summary`
Сводка по домашним заданиям ученика для журнала успеваемости.
сущности: → не сущность, агрегат по `Submission` и `Assignment`
- `accepted: int`, `revision: int`, `missed: int`, `avgScore: number|null` — `null`, если зачтённых работ нет
- пропущенные сроки считаются по заданиям без сдачи после `dueAt` с учётом продлений
- балл — с учётом удовлетворённых апелляций
- доступно роли `curator` и сервисному клиенту `progress-service`

### `GET /v1/students/{studentId}/submissions`
Работы ученика.
сущности: → список `Submission` с последней `Check` по каждой
- ученик видит только свои; чужой `studentId` — `403`
- комментарий наставника отдаётся только у `revision` и `accepted`
- пометка о заимствованиях ученику не отдаётся

### `GET /v1/submissions/{submissionId}`
Работа со всеми попытками и проверками.
сущности: → `Submission`, `Check[]`, `SubmissionFile[]`
- ссылки на файлы подписанные, живут 15 минут
- баллы по критериям — у каждой проверки

### `GET /v1/submissions/{submissionId}/comments`
Переписка по работе.
сущности: → список `SubmissionComment`
- доступно ученику-автору, наставнику группы и куратору курса
- по возрастанию времени; удалённые не отдаются

### `POST /v1/submissions/{submissionId}/comments`
Комментарий к работе.
сущности: ← `text` · → `SubmissionComment`
- до 4 000 знаков; пустой — `400`
- по снятой работе (`withdrawn`) — `409`
- после коммита публикует `homework.comment.added`

### `GET /v1/submissions/{submissionId}/files/{fileId}`
Скачивание файла работы.
сущности: → не сущность, редирект `302` на подписанную ссылку
- ссылка живёт 15 минут
- файл чужой работы — `403`

### `POST /v1/submissions/{submissionId}/handover`
Передача работы другому наставнику.
сущности: ← `toMentorId` · → `Submission`
- доступно роли `curator`
- работа должна быть в `submitted` или `checking`; из `checking` возвращается в `submitted` и снимается с прежнего наставника
- новый наставник должен вести этот курс по копии закрепления — иначе `400`
- после коммита шлёт `homework.check.due` новому наставнику

### `POST /v1/submissions/{submissionId}/recall`
Отзыв работы учеником.
сущности: → `Submission`
- только из `submitted`; взятую в проверку отозвать нельзя — `409`
- файлы отозванной попытки остаются в истории работы
- проверка заимствований по отозванной попытке не отменяется, но её результат никому не показывается

### `GET /v1/submissions/{submissionId}/similarity`
Результат проверки заимствований по последней попытке.
сущности: → `SimilarityCheck`
- доступно наставнику группы и куратору; ученику — `403`
- проверки не было (текст короче 500 знаков) — `204`

## События

### потребляет `course.course.finished`
Курс завершён — закрываем приём работ.
- группа `homework-course-events`, offset коммитится после записи в БД
- переводит все `published` задания курса в `archived`; работы в `submitted` и `checking` остаются в очереди проверки
- повтор безопасен: архивирование идемпотентно по `courseId`
- из тела читается только `courseId`

### потребляет `course.enrollment.cancelled`
Ученика отчислили с курса — снимаем его непроверенные работы.
- группа `homework-course-events`, offset коммитится после записи в БД
- работы ученика по курсу в `submitted` и `checking` переводятся в `withdrawn`; зачтённые и на доработке остаются как есть
- открытые апелляции ученика по курсу остаются открытыми
- событий при этом не публикует: ни ученику, ни наставнику
- из тела читаются `studentId` и `courseId`, остальные поля игнорируются
- после пяти неудачных попыток сообщение уходит в `course.enrollment.cancelled.dlq`

### потребляет `course.lesson.deleted`
Урок удалён из курса — убираем его черновики заданий.
- группа `homework-course-events`, offset коммитится после записи в БД
- черновики заданий урока удаляются вместе с критериями
- опубликованные задания урока остаются и видны в «Все задания курса» с пометкой «урок удалён»; работы по ним принимаются до срока
- повтор безопасен: удалять нечего

### потребляет `mentor.cohort.reassigned`
Группе сменили наставника — переносим очередь проверки.
- группа `homework-mentor-events`, offset коммитится после записи в БД
- обновляет копию закрепления группы и переводит непроверенные работы группы (`submitted`, `checking`) на нового наставника; `checking` возвращается в `submitted`
- шлёт `homework.check.due` новому наставнику по каждой перенесённой работе, после коммита
- повтор безопасен по паре `cohortId` + `mentorId`: повторное сообщение работ не находит и ничего не шлёт
- из тела читаются `cohortId`, `courseId`, `mentorId`

### публикует `homework.appeal.resolved`
Куратор рассмотрел апелляцию.
- `appealId: string`, `checkId: string`, `studentId: string`, `mentorId: string`
- `decision: upheld` \| `rejected`
- `newScore: int|null` — `null` у `rejected`
- ключ партиции — `studentId`
- шлётся после коммита решения, отдельным вызовом: при ретрае возможен дубль

### публикует `homework.check.done`
Наставник вынес вердикт по работе.
- `checkId: string`, `submissionId: string`, `studentId: string`, `lessonId: string`
- `verdict: accepted` \| `revision`
- `score: int|null` — `null` у `revision`
- `comment: string|null` — у `revision` не пустой
- `deeplink: string` — экран приложения ученика, который открывается по нажатию на пуш
- `checkedAt: iso8601`
- ключ партиции — `studentId`: порядок гарантирован по ученику
- шлётся после коммита вердикта, отдельным вызовом: при ретрае возможен дубль, потребитель склеивает по `checkId`
- при снятии работы отчислением и при решении по апелляции не шлётся — вердикта нет

### публикует `homework.check.due`
Работа ждёт проверки наставника.
- `submissionId: string`, `mentorId: string`, `courseId: string`, `waitingSince: iso8601`
- `deeplink: string` — куда ведёт пуш наставнику; в приложении наставника открывает работу
- ключ партиции — `mentorId`: порядок гарантирован по наставнику
- шлётся после коммита, отдельным вызовом: при ретрае возможен дубль
- при первой сдаче работы не шлётся — наставник видит её в очереди

### публикует `homework.comment.added`
Новый комментарий к работе.
- `commentId: string`, `submissionId: string`, `authorId: string`, `authorRole: student` \| `mentor` \| `curator`
- `recipientIds: string[]` — все стороны работы, кроме автора
- `length: int` — длина комментария; сам текст в событие не кладётся, получатель читает его ручкой переписки
- ключ партиции — `submissionId`
- шлётся после коммита, отдельным вызовом: при ретрае возможен дубль

### публикует `homework.deadline.missed`
Ученик пропустил срок сдачи задания.
- `assignmentId: string`, `studentId: string`, `courseId: string`, `dueAt: iso8601`
- ключ партиции — `studentId`
- продление, выданное после пропуска, событие не отменяет
- читает журнал успеваемости `progress-service`

### публикует `homework.deadline.soon`
До срока сдачи осталось меньше суток.
- `assignmentId: string`, `studentId: string`, `dueAt: iso8601`, `hasDraft: boolean`
- ссылки в теле нет: пуш собирает получатель по `assignmentId`
- ключ партиции — `studentId`
- шлётся один раз на пару задание + ученик; перенос срока методистом разрешает повтор

## Фоновые задачи

### `expireDrafts`
Чистит заброшенные черновики работ.
- расписание `0 4 * * *`
- удаляет черновики, которые не менялись 30 дней, и черновики по заданиям в `archived`
- файлы черновика удаляются вместе с ним
- событий не публикует

### `markMissedDeadlines`
Фиксирует пропущенные сроки сдачи.
- расписание `0 * * * *`
- берёт опубликованные задания, срок которых прошёл за последний час, и учеников группы без сдачи с учётом продлений
- публикует `homework.deadline.missed` по каждой паре задание + ученик
- пропущенный прогон не догоняется: пропуски сроков за этот час не публикуются

### `nudgeStaleChecks`
Напоминает наставнику о непроверенных работах.
- расписание `*/30 * * * *`
- берёт работы в `submitted` и `checking`, которые ждут дольше 24 часов
- шлёт `homework.check.due` закреплённому наставнику, не чаще раза в сутки на работу — по `lastNudgedAt`
- пачками по 200, за прогон не больше 2 000 — остаток ждёт следующего
- снятые и отозванные работы не трогает

### `pollSimilarityResults`
Дозапрашивает результаты проверки заимствований.
- расписание `*/10 * * * *`
- берёт `pending` старше часа, по которым не пришёл ответ, и спрашивает внешний сервис по `externalId`
- `pending` старше суток переводит в `failed` без запроса
- событий не публикует

### `purgeOrphanFiles`
Чистит файлы, загруженные без сдачи.
- расписание `0 3 * * *`
- удаляет из объектного хранилища и из `SubmissionFile` файлы без попытки и без черновика старше двух суток
- событий не публикует

### `remindUpcomingDeadlines`
Предупреждает учеников о близком сроке.
- расписание `0 */2 * * *`
- берёт опубликованные задания со сроком в ближайшие 24 часа (с учётом продлений) и учеников группы без сдачи
- публикует `homework.deadline.soon`; отметка в `DeadlineNotice` не даёт отправить второй раз
- ученик с отозванной работой считается не сдавшим

## Владеет данными

### `Assignment`
Домашнее задание к уроку.
- `id`: `uuid`
- `lessonId`: `uuid`
- `courseId`: `uuid`
- `title`: `string`
- `description`: `text`
- `dueAt`: `timestamp?` — `null` у черновика и у копии из прошлого запуска
- `maxScore`: `int`
- `status`: `draft` \| `published` \| `archived`
- `copiedFrom`: `uuid?`
- `createdBy`: `uuid`
- `publishedAt`: `timestamp?`
— `courseId` копируется из урока при создании и потом не меняется
— `archived` ставит только событие `course.course.finished`, руками не ставится

### `RubricCriterion`
Критерий оценки задания.
- `id`: `uuid`
- `assignmentId`: `uuid`
- `title`: `string`
- `weight`: `int`
- `position`: `int`
— сумма `weight` по заданию равна `Assignment.maxScore`; проверяется при публикации и при замене критериев

### `Submission`
Работа ученика по заданию; одна запись на ученика и задание, попытки — внутри.
- `id`: `uuid`
- `assignmentId`: `uuid`
- `studentId`: `uuid`
- `cohortId`: `uuid`
- `attempt`: `int`
- `status`: `submitted` \| `checking` \| `accepted` \| `revision` \| `recalled` \| `withdrawn`
- `mentorId`: `uuid?` — `null`, пока работу никто не взял
- `text`: `text?` — текст последней попытки
- `submittedAt`: `timestamp`
- `lastNudgedAt`: `timestamp?`
— уникальность по паре `assignmentId` + `studentId`: повторная сдача — новая попытка в той же записи, а не новая запись
— `attempt` растёт только при повторной сдаче из `revision` или `recalled`

### `SubmissionDraft`
Черновик работы до сдачи.
- `assignmentId`: `uuid`
- `studentId`: `uuid`
- `text`: `text`
- `fileIds`: `uuid[]`
- `updatedAt`: `timestamp`
— ключ — пара `assignmentId` + `studentId`; удаляется при сдаче

### `SubmissionFile`
Файл попытки.
- `id`: `uuid`
- `submissionId`: `uuid?` — `null`, пока файл загружен, а работа не сдана
- `attempt`: `int?`
- `storageKey`: `string`
- `sizeBytes`: `int`
- `mime`: `string`
- `uploadedAt`: `timestamp`

### `Check`
Проверка попытки наставником.
- `id`: `uuid`
- `submissionId`: `uuid`
- `attempt`: `int`
- `mentorId`: `uuid`
- `verdict`: `accepted` \| `revision`
- `score`: `int?` — `null` у `revision`
- `originalScore`: `int?` — балл наставника до удовлетворённой апелляции; `null`, если апелляции не было
- `comment`: `text?`
- `createdAt`: `timestamp`
— одна проверка на попытку: уникальность по `submissionId` + `attempt`

### `CheckScore`
Балл проверки по критерию.
- `checkId`: `uuid`
- `criterionId`: `uuid`
- `score`: `int`
— не больше веса критерия; у проверки задания без критериев строк нет

### `Appeal`
Апелляция ученика на балл.
- `id`: `uuid`
- `checkId`: `uuid`
- `studentId`: `uuid`
- `reason`: `text`
- `status`: `open` \| `upheld` \| `rejected`
- `resolvedBy`: `uuid?`
- `resolutionComment`: `text?`
- `createdAt`: `timestamp`
- `resolvedAt`: `timestamp?`
— уникальность по `checkId`: одна апелляция на проверку

### `SimilarityCheck`
Проверка попытки на заимствования.
- `id`: `uuid`
- `submissionId`: `uuid`
- `attempt`: `int`
- `externalId`: `string`
- `status`: `pending` \| `clean` \| `flagged` \| `failed`
- `percent`: `int?` — `null`, пока нет результата
- `sources`: `jsonb?`
- `createdAt`: `timestamp`
— `flagged` и `clean` ставит только ответ внешнего сервиса, `failed` — только задача `pollSimilarityResults`

### `SubmissionComment`
Комментарий к работе.
- `id`: `uuid`
- `submissionId`: `uuid`
- `authorId`: `uuid`
- `authorRole`: `student` \| `mentor` \| `curator`
- `text`: `text`
- `createdAt`: `timestamp`
- `deletedAt`: `timestamp?`

### `Extension`
Продление срока сдачи ученику.
- `id`: `uuid`
- `assignmentId`: `uuid`
- `studentId`: `uuid`
- `newDueAt`: `timestamp`
- `reason`: `string`
- `grantedBy`: `uuid`
— одно действующее продление на пару задание + ученик: новое заменяет прежнее

### `DeadlineNotice`
Отметка, что ученика предупредили о близком сроке.
- `assignmentId`: `uuid`
- `studentId`: `uuid`
- `dueAt`: `timestamp` — срок, о котором предупредили
- `sentAt`: `timestamp`
— перенос срока даёт новый `dueAt`, и предупреждение уходит снова

### `CourseAppealSettings`
Приём апелляций по курсу.
- `courseId`: `uuid`
- `appealsOpen`: `boolean`
- `changedBy`: `uuid`
- `changedAt`: `timestamp`
— записи нет — приём открыт

### `CohortMentor`
Копия закрепления наставника за группой — для очереди проверки.
- `cohortId`: `uuid`
- `courseId`: `uuid`
- `mentorId`: `uuid`
- `since`: `timestamp`
— источник правды — `mentor-service`; здесь меняется только событием `mentor.cohort.reassigned`

## Роли и доступ
| Роль | Что может |
|---|---|
| `student` | сдавать и отзывать свои работы, вести черновик, видеть свои работы и вердикты, подавать апелляции, комментировать свои работы |
| `mentor` | видеть очередь своих групп, брать работы в проверку и возвращать в очередь, выносить вердикт, комментировать работы своих групп |
| `curator` | передавать работу другому наставнику, продлевать срок, рассматривать апелляции, закрывать приём апелляций, смотреть пропуски и заимствования по своим курсам |
| `methodist` | создавать, менять, копировать, публиковать, снимать с публикации и удалять задания, задавать критерии |
| `notify-service` (сервисный клиент) | читать название и срок задания |
| `progress-service` (сервисный клиент) | читать сводку по ученику |
| `antiplagiat-api` (подпись запроса) | присылать результат проверки заимствований |
