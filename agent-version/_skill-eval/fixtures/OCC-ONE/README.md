# Фикстура OCC-ONE — правка события с одним местом публикации (ложное срабатывание)

Проба `occ-one`, `kind: one-place`. Серия OCC: правка меняет поле существующего события в одном названном
случае; спека в §6.2 перечисляет места публикации этого события по карточке. Здесь место у события **одно** —
мерим, что спека не выдумывает других мест и не тянет места похожего события.

Режим мелкой правки, как `TS-CR`: флаг изображён промптом, ответы аналитика — заранее («ПРОДОЛЖЕНИЕ»), один ход.
Предметная область — онлайн-школа (домашние задания, проверка работ наставником).

## Дерево

| Что | Зачем |
|---|---|
| `coddoc/EDU-940/change_request.md` | запрос на правку: у работы, возвращённой на доработку, пуш «Работа проверена» ведёт на урок → на форму сдачи задания. Изменение названо через случай (вердикт «на доработку»), без топика, ручки и поля. «Контракт — да», остальное «нет». Приёмка — одна строка |
| `w-prompt.txt` | ответы аналитика: поле `deeplink` события `homework.check.done`, новое значение `eduapp://homework/<assignmentId>` у «на доработку», прежнее `eduapp://lesson/<lessonId>`; потребитель — `notify-service`, правка ему не нужна; данные, доступ, нагрузка не меняются; выкат и откат. Тех-гейты закрыты, спека пишется одним ходом |
| `services/homework-service.md` | карточка-публикатор, 759 строк, по `card.template.md`: 12 блоков правил, контракт (45 ручек), события (4 потребляет, 6 публикует), 6 задач, 14 сущностей |
| `services/notify-service.md` | шум, 375 строк: потребитель пушей. Правленое событие и ловушку только **потребляет** (`:185`, `:193`) — мест публикации в ней нет. Своя ссылка одного вида пуша — `eduapp://webinar/<webinarId>` (`:272`) — правдоподобное выдуманное значение |
| `services/manifest.yaml` | `homework-service` и `notify-service` с `notes`; `cabinet-web`, `course-service`, `mentor-service`, `progress-service` без карточек |
| `truth-occ.json` | ожидания для `grade-occ.mjs` |

## Событие, поле, место

- Событие — `homework.check.done`, блок `### публикует` на `homework-service.md:474`; поле `deeplink` описано одной
  фразой на `:480` («экран приложения ученика, который открывается по нажатию на пуш»). Что `notify-service`
  ссылку не разбирает, говорит только ответ аналитика (`w-prompt.txt:6`); в карточках этой фразы нет.
- Место — одно: ручка `POST /v1/checks` (вердикт наставника), блок `:262`, строка публикации `:271`. Она же называет
  значение поля: «в `deeplink` кладёт ссылку на урок задания `eduapp://lesson/<lessonId>` при любом вердикте».
  От места до блока события — 203 строки, до строки поля — 209.
- В truth `valued: null` нарочно: `grade-occ.mjs` проверяет `valueTokens` только в строках мест, кроме места
  `valued`, — с единственным местом в `valued` метрика «выдумано 0» ослепла бы.
- `grep -n "homework.check.done" services/*.md`: `homework-service.md:92` (сообщение «работа проверена» в
  «Бизнес-правилах» — описание, не место), `:271` (место), `:474` (блок события); `notify-service.md:185`
  (потребление). Других мест нет.

## Ловушка

`homework.check.due` («работа ждёт проверки», пуш наставнику) — топик отличается двумя буквами, тело тоже несёт
`deeplink`, блок стоит сразу под блоком правленого события (`:486`, поле `:489`). Публикуется из трёх мест:

| id | Место | Строка |
|---|---|---|
| `handover` | ручка `POST /v1/submissions/{submissionId}/handover` — куратор передаёт работу другому наставнику | блок `:412`, публикация `:418` |
| `cohort-reassigned` | потребляет `mentor.cohort.reassigned` — группе сменили наставника | блок `:458`, «шлёт» `:462` |
| `nudge-task` | задача `nudgeStaleChecks` — работа ждёт дольше суток | блок `:532`, публикация `:536` |

`grep -n "homework.check.due" services/*.md`: `homework-service.md:96` (сообщение), `:418`, `:462`, `:486` (блок),
`:536`; `notify-service.md:193` (потребление).

Повторная сдача (`POST /v1/assignments/{assignmentId}/submissions`, `:245`) — куда ведёт новая ссылка — нарочно
**не** публикует ни одно из двух событий (`:254`), чтобы упоминание формы сдачи в §6.2 не задевало ловушку.

## Исходы

| | §6.2 спеки |
|---|---|
| Зелёный | нет ни одного места ловушки (`trap`); нет значений поля, которых не называют карточка или ответы аналитика (`valueTokens`). Строка про единственное место `POST /v1/checks` — допустима, но не обязательна: «у события одно место — лишних строк нет» |
| Красный | любое место `homework.check.due` в перечне — ручка передачи, событие смены наставника группы, задача напоминаний (по пути/имени или словами); выдуманная ссылка или id у места: другая схема `eduapp://…` кроме `lesson/` и `homework/` (в том числе ссылка вебинара из `notify-service`), `homework/` не с `<assignmentId>`, `lesson/` не с `<lessonId>`, плейсхолдер `<submissionId>`/`<checkId>`/`<courseId>`/…, «ссылка на работу/курс/разбор» |
| Не красный | упоминание самого `homework.check.due` как соседа без мест («пуш наставнику не трогаем»); `notify-service` как потребитель; прочие поля события (`checkId`, `submissionId`, `score`) как неизменные; `eduapp://lesson/<lessonId>` у «зачтено» |

## Регэкспы — проверены

На образцах строк §6.2 (зелёный; по красному на каждое место ловушки, путь и словами; пять выдуманных значений):
зелёный — 0 срабатываний `trap`/`valueTokens`, место ловится; каждый красный ловится своим регэкспом. Через
`gradeSpec` из `grade-occ.mjs`: зелёный с местом и без места — ✓; ловушка в перечне — только «ловушка 0»;
`eduapp://homework/<submissionId>` у `POST /v1/checks` — только «выдумано 0». Выдуманное значение в строке без
места грейдер не меряет (так устроена метрика «выдумано 0»).
`change_request.md` и `w-prompt.txt` — 0 срабатываний. В `homework-service.md` `trap` ловит только строки ловушки
(и её упоминания в «Назначении», «Владеет данными», «Зависит от», «Кто меня потребляет» — §6.2 их не касается);
в `notify-service.md` — 0 срабатываний `trap` и места, `valueTokens` — только на ссылке вебинара (`:272`). Кириллица в регэкспах — через `[а-яё]*`: `\w` в JS кириллицу не ловит.

Строка раннера: `  occ-one) FIXTURE=OCC-ONE; PROMPT_FILE=w-prompt.txt; SKILL=technical-spec-doc ;;`
