Напиши техническую спецификацию по БТ coddoc/CLN-610/business_requirements.md.

Это ПРОДОЛЖЕНИЕ: ты уже задал вопросы по тех-гейтам, аналитик отвечает.

ОТВЕТЫ АНАЛИТИКА:
- Номер задачи: CLN-610, спеку клади рядом с БТ.
- Правка только в booking-core, владелец — команда «Запись». Фронт не трогаем. insurer-gateway тоже не трогаем: он пересылает страховой сообщение о записи как есть.
- Сообщение о записи, которое получает страховая, — существующее событие booking-core об изменении записи, оно есть в его карточке. Новых событий и новых полей не заводим: страховая ищет номер письма в поле основания, меняем то, что туда кладётся.
- Номер гарантийного письма у записи уже хранится — это то, что присылает страховая.
- Номер — строка, как в письме, по длине как прежние значения основания; формат поля не меняется.
- Поле основания из этого события читает только insurer-gateway; сервис уведомлений и SMS его не используют.
- Если гарантийного письма у записи нет — оставляем как сейчас.
- При неявке по ДМС номер письма встаёт в основание вместо того, что там сейчас.
- Миграций нет, хранение не меняется.
- Нагрузка: неявок по ДМС — десятки в день по всей сети.
- Доступ: событие внутреннее, ролей и прав не добавляем.
- Выкат: обычный релиз booking-core, без фиче-флага; откат — откатом сервиса.
- Приёмку тестировщик делает на стенде: смотрит сообщение в обменнике и что ушло страховой через insurer-gateway.

Дальше действуй по скиллу.
