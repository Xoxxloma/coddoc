# staff-registry — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Заметки команды

> Скопировано из `services/manifest.yaml`, поле `notes`. Ведёт человек; `service-map` копирует
> при каждом скане дословно.

Кадровый учёт врачей — отпуска, больничные; команда «Персонал».
Больничные приходят из внешнего кадрового учёта hr-core, он вне манифеста.

## Назначение

Сервис даёт кадровой службе и заведующим отделениями вести медперсонал сети клиник: кто работает в какой клинике и отделении, когда сотрудник отсутствует и допущен ли врач к приёму. Поддерживает приём на работу и увольнение, заведение и согласование отпусков, командировок и срочных выездов, приём больничных из внешнего кадрового учёта, учёт сертификатов специалистов с предупреждением об их истечении. Главные объекты — сотрудники, их отсутствия и допуски к приёму.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Принять сотрудника на работу в клинику и отделение | Кадровик |
| Изменить должность, отделение или клинику сотрудника | Кадровик |
| Уволить сотрудника — уволенного нельзя вернуть, только принять заново | Кадровик |
| Завести отпуск, командировку или срочный выезд сотрудника | Кадровик, заведующий отделением |
| Согласовать отсутствие — только заведующий отделением этого сотрудника | Заведующий отделением |
| Отменить отсутствие — только до его начала | Кадровик, заведующий отделением |
| Сократить отсутствие — сотрудник вышел раньше; продлить нельзя, только завести новое | Кадровик |
| Посмотреть отсутствия отделения на месяц вперёд | Заведующий отделением |
| Посмотреть свои отсутствия и допуски | Сотрудник |
| Добавить сертификат специалиста врачу | Кадровик |
| Посмотреть допуски, истекающие в ближайшие 60 дней | Кадровик, заведующий отделением |

## Бизнес-правила

### `Employee` — сотрудник
- работает (`active`) — принят кадровиком в клинику и отделение
- в длительном отпуске (`on_leave`) — отпуск по уходу или длительный без сохранения; отсутствий по нему не заводят
- уволен (`dismissed`) — кадровиком; вернуть нельзя, повторный приём создаёт нового сотрудника

### `Absence` — отсутствие сотрудника
- черновик (`draft`) — кадровик или заведующий завёл, соседи о нём не знают
- согласовано (`approved`) — заведующий отделением согласовал; больничный из внешнего кадрового учёта приходит сразу согласованным
- сокращено (`shortened`) — сотрудник вышел раньше; конец периода сдвинут на более ранний
- отменено (`cancelled`) — до начала периода; после начала отменить нельзя, только сократить

### `Certificate` — допуск врача к приёму
- действует (`valid`) — сертификат специалиста по этой специальности не истёк
- истекает (`expiring`) — до окончания меньше 60 дней; кадровику и заведующему уходит письмо
- истёк (`expired`) — по дате; врач по этой специальности к приёму не допускается

### сообщение «отсутствие согласовано»
- повод — отсутствие врача согласовано или пришёл больничный; адресовано графику врачей и записи на приём; по сотрудникам, которые не врачи, не уходит; токен `staff.absence.registered`

### сообщение «отсутствие отменено»
- повод — согласованное отсутствие врача отменено до начала; адресовано графику врачей; токен `staff.absence.cancelled`

### сообщение «отсутствие сокращено»
- повод — врач вышел раньше; адресовано графику врачей; токен `staff.absence.shortened`

### сообщение «сотрудник принят»
- повод — приём на работу; адресовано справочникам соседей; токен `staff.employee.hired`

### сообщение «сотрудник уволен»
- повод — увольнение; адресовано графику врачей и справочникам соседей; токен `staff.employee.dismissed`

### сообщение «допуск истекает»
- письмо кадровику и заведующему отделением за 60 и за 14 дней до окончания допуска; шаблон `certificate-expiring`

## Публичный контракт

### `DELETE /v1/absences/{id}`
Отмена отсутствия.
сущности: ← `id` · → `Absence`
- только до начала периода; переводит в `cancelled`
- согласованное отменённое шлёт `staff.absence.cancelled`, черновик — ничего
- ошибки: `409` — период уже начался

### `GET /health`
Проверка живости.

### `GET /internal/v1/doctors/{doctorId}/absences`
Отсутствия врача за период — для построения графика.
сущности: ← `doctorId`, `from`, `to` · → `Absence`, только `approved` и `shortened`
- период не больше 180 дней, иначе `422`

### `GET /v1/absences`
Отсутствия отделения.
сущности: ← `departmentId`, `from`, `to` · → `Absence`
- заведующий видит своё отделение, кадровик — все
- черновики видят только автор и заведующий

### `GET /v1/absences/{id}`
Одно отсутствие.
сущности: → `Absence`
- `reason` больничного не отдаётся никому, кроме кадровика

### `GET /v1/certificates/expiring`
Допуски, истекающие в ближайшие 60 дней.
сущности: ← `clinicId?` · → `Certificate`
- заведующий видит своё отделение, кадровик — все

### `GET /v1/employees`
Список сотрудников.
сущности: ← `clinicId?`, `departmentId?`, `position?` · → `Employee`, без паспортных данных
- уволенные не возвращаются, если не передан `status=dismissed`

### `GET /v1/employees/{id}`
Один сотрудник.
сущности: → `Employee`
- паспортные данные — только кадровику
- сотрудник видит только себя

### `PATCH /v1/absences/{id}`
Сокращение отсутствия.
сущности: ← `to` · → `Absence`
- только `approved`; новый конец периода — раньше прежнего, иначе `422`
- переводит в `shortened` и шлёт `staff.absence.shortened`

### `PATCH /v1/employees/{id}`
Изменение должности, отделения или клиники.
сущности: ← `position?`, `departmentId?`, `clinicId?` · → `Employee`
- только кадровик
- перевод в другую клинику не трогает отсутствия: они остаются за сотрудником

### `POST /v1/absences`
Заведение отсутствия.
сущности: ← `employeeId`, `kind`, `from`, `to`, `reason?` · → `Absence`
- `kind: vacation` \| `business_trip` \| `urgent`; больничный руками не заводится — он приходит из внешнего кадрового учёта
- пересечение с другим согласованным отсутствием того же сотрудника — `409`
- создаётся черновиком, событий не шлёт

### `POST /v1/absences/{id}/approve`
Согласование отсутствия.
сущности: → `Absence`
- только заведующий отделением этого сотрудника
- переводит в `approved` и шлёт `staff.absence.registered`, если сотрудник — врач
- `urgent` согласуется задним числом: период может уже идти

### `POST /v1/certificates`
Добавление сертификата специалиста.
сущности: ← `employeeId`, `specialtyId`, `validTo` · → `Certificate`
- только кадровик; дата окончания — в будущем, иначе `422`

### `POST /v1/employees`
Приём на работу.
сущности: ← ФИО, `position`, `clinicId`, `departmentId` · → `Employee`
- табельный номер выдаётся здесь и не меняется
- шлёт `staff.employee.hired`

### `POST /v1/employees/{id}/dismiss`
Увольнение.
сущности: ← `dismissedAt` · → `Employee`
- будущие согласованные отсутствия уволенного отменяются без отдельных событий
- шлёт `staff.employee.dismissed`

## События

### публикует `staff.absence.cancelled`
Согласованное отсутствие врача отменено.
- обменник `staff.events` (topic), ключ маршрутизации `staff.absence.cancelled`
- `absenceId: string`, `doctorId: string`, `from: date`, `to: date`
- шлётся после коммита; черновики события не дают

### публикует `staff.absence.registered`
Врач отсутствует.
- обменник `staff.events`, ключ маршрутизации `staff.absence.registered`
- `absenceId: string`, `doctorId: string` — табельный id сотрудника-врача
- `kind: vacation` \| `sick_leave` \| `business_trip` \| `urgent`
- `from: date`, `to: date` — обе даты включительно
- `approvedAt: iso8601`
- шлётся после коммита согласования или приёма больничного; по сотрудникам, которые не врачи, не шлётся
- при ретрае публикации возможен дубль: соседи отличают его по `absenceId`

### публикует `staff.absence.shortened`
Врач вышел раньше.
- обменник `staff.events`, ключ маршрутизации `staff.absence.shortened`
- `absenceId: string`, `doctorId: string`, `from: date`, `to: date` — новый конец периода

### публикует `staff.employee.dismissed`
Сотрудник уволен.
- обменник `staff.events`, ключ маршрутизации `staff.employee.dismissed`
- `employeeId: string`, `position: string`, `clinicId: string`, `dismissedAt: date`

### публикует `staff.employee.hired`
Сотрудник принят.
- обменник `staff.events`, ключ маршрутизации `staff.employee.hired`
- `employeeId: string`, `position: string`, `clinicId: string`, `departmentId: string`, `hiredAt: date`

### потребляет `hr.sick-leave.opened`
Во внешнем кадровом учёте открыт больничный.
- очередь `staff-registry.sick-leaves`; публикует `hr-core`, вне манифеста
- из тела читаются `personnelNo`, `from`, `toPlanned`
- создаёт сразу согласованное отсутствие `sick_leave` и шлёт `staff.absence.registered`
- повтор по тому же больничному безопасен: отсутствие ищется по номеру больничного

### потребляет `hr.sick-leave.closed`
Больничный закрыт.
- очередь `staff-registry.sick-leaves`
- закрытие раньше плановой даты сокращает отсутствие и шлёт `staff.absence.shortened`; позже — заводит новое отсутствие на продление

## Фоновые задачи

### `markExpiringCertificates`
Отмечает истекающие допуски.
- расписание `0 6 * * *`
- переводит в `expiring` допуски, до окончания которых меньше 60 дней, и в `expired` — истёкшие
- письма кадровику и заведующему уходят за 60 и за 14 дней; событий не публикует

### `syncDepartments`
Сверка справочника отделений с внешним кадровым учётом.
- не определено: расписание задаётся вне репозитория
- новые отделения заводит, исчезнувшие помечает закрытыми; сотрудников не переводит

## Владеет данными

### `Absence`
Отсутствия сотрудников.
- `id`: `string`
- `employeeId`: `string`
- `kind`: `vacation` \| `sick_leave` \| `business_trip` \| `urgent`
- `status`: `draft` \| `approved` \| `shortened` \| `cancelled`
- `from`: `date`
- `to`: `date`
- `reason`: `string?` — у больничного не заполняется
- `sickLeaveNo`: `string?` — номер больничного из внешнего кадрового учёта
- `approvedBy`: `string?`
— больничный приходит сразу в `approved`, `approvedBy` у него пуст

### `Certificate`
Сертификаты специалистов у врачей.
- `id`: `string`
- `employeeId`: `string`
- `specialtyId`: `string`
- `validTo`: `date`
- `status`: `valid` \| `expiring` \| `expired`

### `Department`
Отделения клиник.
- `id`: `string`
- `clinicId`: `string`
- `name`: `string`
- `headId`: `string?` — заведующий; `null`, пока не назначен
- `closedAt`: `date?`

### `Employee`
Сотрудники сети клиник.
- `id`: `string` — табельный id; для врачей он же `doctorId` у соседей
- `personnelNo`: `string` — номер во внешнем кадровом учёте
- `fullName`: `string`
- `position`: `doctor` \| `nurse` \| `registrar` \| `other`
- `clinicId`: `string`
- `departmentId`: `string`
- `status`: `active` \| `on_leave` \| `dismissed`
- `hiredAt`: `date`
- `dismissedAt`: `date?`
