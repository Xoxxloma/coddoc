## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего функционала: меняется содержание сообщения о записи, которое получает
страховая компания, когда пациент по ДМС не пришёл на приём. Сама неявка, правило её фиксации и
остальная работа с записями не меняются.

### 1.1. Описание проблемы
Сеть клиник принимает пациентов по полисам ДМС двенадцати страховых компаний. На каждый визит по
ДМС страховая заранее выдаёт гарантийное письмо — обязательство оплатить этот визит — и резервирует
под него часть лимита пациента по полису.

Когда пациент по ДМС не приходит на приём, страховая получает сообщение о записи и по нему должна
закрыть гарантийное письмо на этот визит: снять резерв и вернуть пациенту лимит. Номера
гарантийного письма в этом сообщении нет, поэтому страховая не может понять, какое письмо
закрывать. Страховые сопоставляют сообщение с письмами по дате, врачу и пациенту, и на пациентах с
несколькими визитами в день это не работает.

Последствия:
- письмо остаётся открытым до конца месяца, и всё это время лимит пациента заблокирован; пациенты
  звонят в клинику и в страховую с вопросом, почему им отказывают в записи на другой визит;
- в конце месяца страховая присылает акт сверки, в котором неявки по ДМС стоят расхождениями;
- специалисты отдела по работе со страховыми вручную подбирают к каждой неявке гарантийное письмо
  и отправляют страховой список писем на закрытие.

За сентябрь и октябрь неявок по ДМС было около 1 400 в месяц по всей сети; расхождений в актах
сверки — около 900 в месяц.

### 1.2. Конечные потребители
- Страховые компании — партнёры по ДМС: закрывают гарантийное письмо по сообщению о неявке.
- Специалисты отдела по работе со страховыми компаниями: ведут ежемесячные сверки.
- Пациенты по ДМС: лимит по полису возвращается вовремя.

### 1.3. Заказчик и стейкхолдеры
**Заказчик:** руководитель отдела по работе со страховыми компаниями.
**Эксперт для консультаций:** старший специалист отдела, который ведёт ежемесячные сверки.
**Принимает результат:** руководитель отдела по работе со страховыми компаниями вместе с двумя
страховыми, с которыми больше всего расхождений.

### 1.4. Как сейчас
1. Пациента записывают по ДМС — сам пациент в приложении или регистратор по звонку.
2. Страховая присылает на визит гарантийное письмо; его номер хранится у записи, регистратор видит
   его в карточке записи.
3. Пациент не пришёл. Через полчаса после начала приёма без отметки о приходе запись сама получает
   статус «неявка».
4. Страховой уходит сообщение о записи. Номера гарантийного письма в нём нет.
5. Страховая не находит письмо и оставляет его открытым.
6. В конце месяца специалист отдела получает акт сверки, вручную подбирает гарантийные письма к
   неявкам и отправляет страховой список писем на закрытие. На одну страховую уходит от двух часов
   до дня работы.

Если у записи по ДМС гарантийного письма к моменту неявки нет (страховая не успела его прислать или
отозвала), такая неявка разбирается по акту сверки — это редкий случай, около 3 % неявок по ДМС.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как специалист отдела по работе со страховыми компаниями должен быть уверен, что по неявке
пациента по ДМС страховая сама закрывает гарантийное письмо, чтобы не разбирать неявки вручную в
акте сверки.

### 2.2. Ценность для бизнеса
- Сверка неявок по ДМС без ручного подбора писем — сейчас на это уходит около двух рабочих дней в
  месяц на отдел.
- Расхождений по неявкам в актах сверки — не больше 5 % от нынешних.
- Лимит пациента по полису возвращается в день неявки, а не в конце месяца; меньше звонков пациентов
  в клинику с вопросом о заблокированном лимите.

### 2.3. Бизнес-риски и меры по снижению

| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Страховая закроет чужое гарантийное письмо | Низкая / высокое | Номер берётся из той самой записи, по которой зафиксирована неявка |
| Страховая не узнает номер, потому что он пришёл в изменённом виде | Средняя / высокое | Номер передаётся ровно в том виде, в каком его прислала страховая (FR-2) |
| Часть страховых ещё не готова закрывать письма по сообщению | Средняя / низкое | Две страховые с наибольшим числом расхождений подтвердили готовность; остальные продолжают сверку по акту |

## 3. Объём проекта

### 3.1. Входит в проект
- Номер гарантийного письма в сообщении страховой о неявке пациента по ДМС.
- Передача номера в том виде, в каком его прислала страховая.
- Неявка по ДМС без гарантийного письма.

### 3.2. Не входит в проект
- Изменение правила, когда запись считается неявкой, и срока, через который она фиксируется.
- Выставление страховой счетов или штрафов за неявки.
- Изменения на стороне страховых компаний и в форме акта сверки.
- Отчёт по неявкам для руководителя регистратуры.
- Повторная отправка страховым сообщений о неявках, случившихся до выпуска доработки.

### 3.3. Архитектурные изменения и интеграции
Затронуты запись на приём и обмен сообщениями о записях со страховыми компаниями. Новых интеграций
нет: страховые уже получают сообщения о записях.

### 3.4. Внешние зависимости
Внешних зависимостей нет.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса
После доработки процесс идёт так:
1. Пациента записывают по ДМС, страховая присылает гарантийное письмо — без изменений.
2. Пациент не пришёл, запись получает статус «неявка» — без изменений.
3. Страховой уходит сообщение о записи, и в нём есть номер гарантийного письма этой записи.
4. Страховая по номеру закрывает письмо и возвращает пациенту лимит.

**FR-1.** Когда запись пациента по ДМС получает статус «неявка» и у записи есть гарантийное письмо
страховой, в сообщении о записи, которое получает страховая, основанием указывается номер этого
гарантийного письма.

**FR-2.** Номер гарантийного письма передаётся ровно в том виде, в каком его прислала страховая:
без обрезки, смены регистра, добавления или удаления пробелов и разделителей.

**FR-3.** Если на момент неявки гарантийного письма у записи по ДМС нет, сообщение о записи
страховой уходит без номера письма; такие неявки специалист отдела разбирает по акту сверки.

### 4.2. Критерии приёмки
- **[FR-1]** Дано: пациент записан по ДМС, у записи есть гарантийное письмо страховой; когда пациент
  не пришёл и запись получила статус «неявка», тогда страховая получает сообщение о записи, в
  основании которого стоит номер этого гарантийного письма.
- **[FR-1]** Дано: у пациента по ДМС два визита в один день к разным врачам, у каждого своё
  гарантийное письмо, и на оба он не пришёл; тогда страховая получает два сообщения, и в каждом —
  номер письма своего визита.
- **[FR-2]** Дано: страховая прислала гарантийное письмо с номером `ГП-2026/004817-а`; когда запись
  получила статус «неявка», тогда в сообщении о записи стоит ровно `ГП-2026/004817-а`.
- **[FR-3]** Дано: пациент записан по ДМС, гарантийного письма у записи нет; когда пациент не пришёл
  и запись получила статус «неявка», тогда страховая получает сообщение о записи без номера
  гарантийного письма.

### 4.3. Бизнес-данные

| № | Объект | Что это | Что меняется |
|---|--------|---------|--------------|
| 1 | Запись на приём | запись пациента к врачу; у записи по ДМС хранится номер гарантийного письма | без изменений |
| 2 | Гарантийное письмо | обязательство страховой оплатить визит; номер присылает страховая | без изменений |
| 3 | Сообщение о записи | сообщение, которое страховая получает при изменении записи | при неявке по ДМС основание — номер гарантийного письма |

### 4.5. Разбиение на части
не применимо: требования относятся к одному сообщению и выпускаются вместе.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
High — расхождения в сверке со страховыми каждый месяц, жалобы пациентов на заблокированный лимит.

### 5.2. Сроки
Ближайший релиз декабря: страховые закрывают год по актам сверки за декабрь.

### 5.3. Ролевая модель

| Роль | Права / доступные действия |
|------|----------------------------|
| — | роли и права не меняются: сообщение получает страховая, пользователи системы его не видят |

## 6. Приложения (опционально)

Строка акта сверки страховой за октябрь, как её присылают сейчас (данные пациента обезличены):

| Дата визита | Пациент | Врач | Статус у клиники | Статус у страховой | Расхождение |
|---|---|---|---|---|---|
| 14.10.2026 | П-ва А. С. | терапевт | неявка | письмо открыто | письмо не закрыто по неявке |

мы уже получаем; отдельный канал для неявок не нужен».
