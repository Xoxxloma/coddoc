## 1. Обзор изменения
### 1.1. Что делаем и тип изменения
**Суть:** В существующей шапке административной панели «Арсенал» появляется счётчик текущего числа активных пользователей; значение обновляется раз в минуту без перезагрузки страницы. Если источник данных недоступен — показывается прочерк «—» (не ноль, не устаревшее значение); если активных пользователей нет — показывается «0» как обычное значение. Счётчик виден только администраторам, оператор его не видит.
**Тип:** доработка
**Стороны:** Fullstack — FE «Арсенал» отображает счётчик в шапке и опрашивает источник раз в минуту; какой именно бэкенд отдаёт число — ❓ TBD (Открытый вопрос №1).

| источник счётчика (`auth` либо новый механизм в BE «Арсенала») | BE: отдаёт число активных пользователей | TBD | ❓ TBD (отложено аналитиком) |

## 4. Frontend — ответственность
### 4.1. Где и что меняется в UI
Шапка `/admin` (существующий элемент) — доработка счётчика активных пользователей. Визуально неярко, не отвлекает администратора (пожелание БТ §6). Вызывает INT-1.

### 4.2. Пользовательские сценарии
- Администратор открывает `/admin` → видит счётчик (значение / честный ноль / «—» при недоступности, см. §4.3) → счётчик обновляется раз в минуту без перезагрузки (FR-1).
- Оператор открывает `/admin` → счётчик (и панель активности целиком) не отображается вовсе (FR-7, подтверждено аналитиком).

### 4.3. Состояния (именованные — обязательно, если есть FE)
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `loading` | первый запрос после открытия `/admin` | лёгкий неяркий индикатор |
| `value` | ответ получен, число активных пользователей > 0 | число |
| `zero` | ответ получен, число = 0 (валидный ноль) | «0» |
| `error_source` | источник недоступен (точный признак — TBD, см. Открытый вопрос №1) / таймаут / сетевая ошибка | «—» |
| ~~`empty`~~ | ~~—~~ | ~~Не применимо: БТ не вводит состояния «нет данных», отличного от `zero`/`error_source`~~ |
| ~~`error_forbidden`~~ | ~~—~~ | ~~Не применимо: оператор не получает элемент вовсе (скрыт на фронте, §4.4), а не ответ 403~~ |

### 4.3.1. Loading и таймауты (обязательно, если есть FE)
- Cold-path (первый запрос после открытия панели) — таймаут 8 с (конвенция `context/conventions.md`).
- Warm-path (последующие опросы) — таймаут 3 с (конвенция).
- Polling: интервал 60 секунд (подтверждено аналитиком), без джиттера — единственный читатель, нагрузка низкая (десятки администраторов, подтверждено аналитиком).
- При таймауте / 5xx / сетевой ошибке — состояние `error_source` («—»); прежнее значение не выдаётся как актуальное.

### 4.4. Доступ по ролям в UI
Счётчик рендерится только при role=admin (существующий ролевой механизм фронта, по карточке `arsenal-web`); при role=operator элемент не рендерится вовсе — подтверждено аналитиком (🔵, со слов).

## 5. Нефункциональные требования
### 5.1. Синхронность, кэш, производительность
- Синхронность: синхронный HTTP-опрос (polling), не событийный.
- Кэш: не требуется — нагрузка низкая (десятки администраторов, подтверждено аналитиком), прямой запрос на каждый цикл опроса.
- Частота опроса: раз в 60 секунд (подтверждено аналитиком).
- Таймауты: 8 с cold / 3 с warm (конвенция).
- Ожидаемая нагрузка: десятки одновременных администраторов (подтверждено аналитиком).

### 5.2. Надёжность/деградация
Операция только читает (GET), ничего не пишет у нас — вопрос «что остаётся записанным при сбое вызова» не возникает. При недоступности источника — состояние `error_source`, «—» (FR-5); прежнее значение не выдаётся как актуальное.

### 5.3. Безопасность/доступ (сводно)
| Граница | Кто может | Негативный случай |
|---------|-----------|--------------------|
| Рендер счётчика на FE | role=admin | role=operator → элемент не рендерится |
| BE-эндпоинт (источник TBD) | role=admin (ожидаемо) | TBD — зависит от варианта, см. Открытый вопрос №1 |
