Учёт ГСМ: списание топлива по путевым листам. Ведёт команда «Учётные системы».
Акт списания после выгрузки в 1С правится только в 1С; здесь — отмена и новый акт.

## Назначение

Сервис ведёт учёт топлива служебного автопарка для бухгалтерии: без него топливо, заправленное
по картам и за наличные, не списывается на затраты, а остатки в баках на конец месяца приходится
считать вручную. Поддерживает приём заправок по топливным картам, списание топлива по каждому
закрытому путевому листу, исправление списания бухгалтером, формирование и утверждение акта
списания за месяц по подразделению, закрытие учётного периода и ночную выгрузку утверждённых
актов в учётную систему бухгалтерии. Главные объекты — списания по путевым листам, акты
списания, заправки по картам, пробег машин по рейсам и учётные периоды.

## Бизнес-правила

### `ExportBatch` — выгрузка актов в учётную систему
- ждёт (`pending`) — заведена ночной задачей или бухгалтером вручную
- отправлена (`sent`) — учётная система подтвердила приём; акты выгрузки становятся `exported`
- не прошла (`failed`) — учётная система отказала или не ответила; повтор — задачей, не больше трёх попыток

### `PeriodLock` — учётный месяц
- открыт (`open`) — по умолчанию у каждого месяца
- закрыт (`closed`) — главный бухгалтер; списания и акты месяца не меняются, новые списания по листам месяца пишутся в первый открытый месяц
- не определено: перехода в коде нет (`archived`)

### `WaybillWriteOff` — списание топлива по путевому листу
- записано (`recorded`) — по сообщению о закрытии путевого листа; литры — как пришли
- исправлено (`corrected`) — бухгалтер поменял литры с указанием причины; прежнее значение хранится
- в акте (`included`) — вошло в утверждённый акт; больше не правится
- снято (`voided`) — путевой лист аннулирован; в акт не идёт

### `WriteOffAct` — акт списания за месяц по подразделению
- черновик (`draft`) — сформирован бухгалтером; пересчитывается при каждом формировании заново
- утверждён (`approved`) — главный бухгалтер; списания акта становятся `included`
- выгружен (`exported`) — после успешной выгрузки; отменить нельзя
- отменён (`cancelled`) — главный бухгалтер, только из `draft` и `approved`; списания возвращаются в `recorded` или `corrected`

### ограничение «месяц закрыт»
- условием управляет роль `CHIEF_ACCOUNTANT`; пока оно действует, списания и акты месяца не меняются, бухгалтер видит отказ «период закрыт»

### сообщение «акт списания утверждён»
- повод — главный бухгалтер утвердил акт; адресовано шлюзу учётной системы, чтобы заранее зарезервировать номер документа; токен `fuel-accounting.act.approved`

### сообщение «выгрузка не прошла»
- письмо бухгалтерам по ГСМ после третьей неудачной попытки выгрузки, с причиной из ответа учётной системы; токен `export-failed`

### сообщение «пора закрыть месяц»
- письмо главному бухгалтеру третьего числа, если прошлый месяц не закрыт; токен `period-close-reminder`

## Публичный контракт

### GET /actuator/health
Проверка живости для балансировщика.
сущности: → не сущность, служебный ответ
(фактов нет — служебный)

### GET /api/v1/acts
Акты списания.
сущности: → `WriteOffAct` (список), без строк акта
- фильтры `month` (`YYYY-MM`) и `departmentCode`; отменённые — только с `includeCancelled=true`
- сортировка по `month` по убыванию, потом по `departmentCode`

### GET /api/v1/acts/{actId}
Акт списания со строками.
сущности: → `WriteOffAct` и `WaybillWriteOff` акта (список)
- `404` — акта нет
- строки отсортированы по номеру путевого листа

### GET /api/v1/acts/{actId}/xlsx
Акт списания файлом.
сущности: → не сущность, файл Excel
- шапка — месяц, подразделение, кто утвердил; у черновика вместо утвердившего — «черновик»
- `404` — акта нет

### GET /api/v1/balances
Остатки топлива в баках машин на дату.
сущности: → не сущность, агрегат по `FuelReceipt` и `WaybillWriteOff`
- параметр `date` обязателен; остаток — приход минус списание по закрытым листам на конец дня по Москве
- машина без единого листа в выдаче не появляется
- строка: `vehicleId: uuid`, `plate: string`, `liters: decimal` — может быть отрицательным, если списание пришло раньше заправки

### GET /api/v1/exports
История выгрузок в учётную систему.
сущности: → `ExportBatch` (список), постранично
- `errorText: string|null` — текст отказа учётной системы как пришёл; `null` у успешных

### GET /api/v1/periods
Учётные месяцы и их состояние.
сущности: → `PeriodLock` (список)
- месяц без записи считается открытым и в выдачу не попадает

### GET /api/v1/vehicles/{vehicleId}/mileage
Пробег машины за месяц по закрытым рейсам.
сущности: → не сущность, агрегат по `TripMileage`
- параметр `month` (`YYYY-MM`) обязателен
- `tripsCount: int`, `distanceKm: int`
- машина без рейсов — `200` с нулями, не `404`

### GET /api/v1/write-offs
Списания по путевым листам.
сущности: → `WaybillWriteOff` (список), постранично
- фильтры `month`, `departmentCode`, `status`
- месяц — по учётному месяцу списания, а не по дате листа: после закрытия месяца они расходятся

### POST /api/v1/acts
Сформировать акт за месяц по подразделению.
сущности: ← `month`, `departmentCode` · → `WriteOffAct`
- `409` — по подразделению за месяц уже есть утверждённый или выгруженный акт
- `422` — за месяц остались незакрытые путевые листы подразделения; их номера — в `openWaybills`
- `423` — месяц закрыт
- черновик за тот же месяц и подразделение не дублируется, а пересчитывается

### POST /api/v1/acts/{actId}/approve
Утвердить акт.
сущности: → `WriteOffAct`
- `409` — акт не в статусе `draft`
- `403` — роль не `CHIEF_ACCOUNTANT`
- публикует `fuel-accounting.act.approved`

### POST /api/v1/acts/{actId}/cancel
Отменить акт.
сущности: ← `reason: string` · → `WriteOffAct`
- `409` — акт уже выгружен или отменён
- `403` — роль не `CHIEF_ACCOUNTANT`

### POST /api/v1/exports
Выгрузить утверждённые акты сейчас.
сущности: → `ExportBatch`
- берёт все `approved` акты, ещё не выгруженные; нет таких — `204` без тела
- `409` — выгрузка уже идёт

### POST /api/v1/periods/{month}/close
Закрыть учётный месяц.
сущности: → `PeriodLock`
- `409` — месяц уже закрыт
- `422` — в месяце есть черновики актов
- `403` — роль не `CHIEF_ACCOUNTANT`

### POST /api/v1/periods/{month}/reopen
Открыть закрытый месяц.
сущности: ← `reason: string` · → `PeriodLock`
- `409` — в месяце есть выгруженные акты
- `403` — роль не `CHIEF_ACCOUNTANT`

### PUT /api/v1/write-offs/{writeOffId}
Исправить списание по путевому листу.
сущности: ← `liters: decimal`, `reason: string` · → `WaybillWriteOff`
- `409` — списание уже в утверждённом акте или снято
- `423` — месяц закрыт
- прежние литры сохраняются в `originalLiters`, повторное исправление их не перетирает

## События

### потребляет `fleet.trip.closed`
Рейс закрыт — пробег машины за рейс.
- группа `fuel-accounting`, offset коммитится после записи в БД
- читаются `tripId`, `vehicleId`, `plate`, `distanceKm`, `closedAt`; `fuelUsedL` и `closedBy` игнорируются — расход берётся из закрытия путевого листа
- повтор безопасен по `tripId`
- пишет `TripMileage`; на списание и акты не влияет

### потребляет `fleet.waybill.closed`
Путевой лист закрыт — основание списания.
- группа `fuel-accounting`, offset коммитится после записи в БД
- читаются `waybillNumber`, `vehicleId`, `departmentCode`, `fuelUsedL`, `closedAt`; `tripIds` игнорируются
- заводит `WaybillWriteOff` в учётный месяц по `closedAt`; месяц закрыт — в первый открытый
- повтор безопасен по `waybillNumber`

### потребляет `fleet.waybill.voided`
Путевой лист аннулирован.
- группа `fuel-accounting`, offset коммитится после записи в БД
- читается `waybillNumber`; списание по нему, если было, переводится в `voided`
- списание уже в утверждённом акте — сообщение уходит в `fleet.waybill.voided.dlq` для ручного разбора

### потребляет `fuel-cards.transaction.posted`
Заправка по топливной карте.
- группа `fuel-accounting`, offset коммитится после записи в БД
- читаются `transactionId`, `vehicleId`, `liters`, `amountRub`, `postedAt`
- пишет `FuelReceipt`; повтор безопасен по `transactionId`

### публикует `fuel-accounting.act.approved`
Акт списания утверждён.
- `actId: uuid`, `month: string`, `departmentCode: string`, `totalLiters: decimal`, `approvedAt: iso8601`
- ключ партиции — `departmentCode`
- шлётся после коммита; при ретрае возможен дубль
- на отмене утверждённого акта отдельного события нет

## Фоновые задачи

### exportApprovedActs
Ночная выгрузка утверждённых актов в учётную систему.
- расписание `0 1 * * *` по Москве
- берёт все `approved` акты, ещё не выгруженные, одной выгрузкой
- неудача — до трёх попыток с интервалом 20 минут, после третьей — письмо бухгалтерам
- наложение с ручной выгрузкой исключено блокировкой в БД
- событий не публикует

### remindPeriodClose
Напоминание главному бухгалтеру о незакрытом месяце.
- расписание `0 9 3 * *` по Москве
- прошлый месяц закрыт — письма нет
- пропущенный прогон не догоняется

## Владеет данными

### `ExportBatch`
Выгрузка актов в учётную систему.
- `id`: `uuid`
- `actIds`: `uuid[]`
- `status`: `pending` \| `sent` \| `failed`
- `attempts`: `int`
- `errorText`: `string?` — текст отказа учётной системы
- `createdAt`: `timestamp`
- `sentAt`: `timestamp?`

### `FuelReceipt`
Заправка по топливной карте.
- `transactionId`: `string` — ключ
- `vehicleId`: `uuid`
- `liters`: `decimal`
- `amountRub`: `decimal`
- `postedAt`: `timestamp`
— заправки за наличные сюда не попадают: они видны только в литрах путевого листа

### `PeriodLock`
Учётный месяц.
- `month`: `string` — `YYYY-MM`, ключ
- `status`: `open` \| `closed` \| `archived`
- `closedBy`: `string?`
- `closedAt`: `timestamp?`
- `reopenReason`: `string?` — причина последнего открытия заново

### `TripMileage`
Пробег машины по закрытому рейсу.
- `tripId`: `uuid` — ключ
- `vehicleId`: `uuid`
- `plate`: `string`
- `distanceKm`: `int`
- `closedAt`: `timestamp`
— только для справки о пробеге; в списании и актах не участвует

### `WaybillWriteOff`
Списание топлива по путевому листу.
- `id`: `uuid`
- `waybillNumber`: `string` — уникален
- `vehicleId`: `uuid`
- `departmentCode`: `string`
- `accountingMonth`: `string` — `YYYY-MM`; может быть позже месяца листа, если месяц листа закрыт
- `liters`: `decimal`
- `originalLiters`: `decimal?` — как пришло, если списание исправляли
- `correctionReason`: `string?`
- `status`: `recorded` \| `corrected` \| `included` \| `voided`
- `actId`: `uuid?`

### `WriteOffAct`
Акт списания за месяц по подразделению.
- `id`: `uuid`
- `month`: `string`
- `departmentCode`: `string`
- `status`: `draft` \| `approved` \| `exported` \| `cancelled`
- `totalLiters`: `decimal`
- `approvedBy`: `string?`
- `approvedAt`: `timestamp?`
- `cancelReason`: `string?`
— на месяц и подразделение не больше одного акта не в статусе `cancelled`
