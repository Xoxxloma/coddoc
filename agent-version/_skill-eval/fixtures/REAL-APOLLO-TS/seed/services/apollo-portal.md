# apollo-portal — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Назначение

Сервис даёт командам управлять конфигурацией своих приложений в разных окружениях без передеплоя:
создавать приложения, пространства конфигурации (namespace) и кластеры, редактировать настройки и
выпускать их в прод, откатывать неудачный выпуск — всё из одного UI и из открытого HTTP API для
внешних интеграций. Поддерживаются вход пользователей и выдача токенов внешним клиентам, создание и
удаление приложений/namespace/кластеров, построчное и текстовое редактирование конфигурации,
экспорт и импорт конфигурации файлом, выпуск обычных, серых (gray) и экстренных релизов, откат на
предыдущий релиз, назначение и отзыв прав доступа, сравнение релизов и просмотр истории изменений,
уведомление о публикации по почте и во внутреннюю систему мониторинга изменений. Главные объекты —
приложения, их кластеры и пространства конфигурации с элементами настроек; релизы и история
публикаций; пользователи, роли и права на namespace; консьюмеры открытого API и избранные
приложения пользователя.

| Откатить релиз на предыдущий | Пользователь с правом релиза namespace |
| Сравнить два релиза, посмотреть историю публикаций и изменений (commits) | Пользователь |
| Посмотреть работающие инстансы приложения по namespace или по релизу | Пользователь |
| Назначить и снять роль на redактирование/релиз namespace другому пользователю | Администратор приложения |
| Назначить и снять роль владельца (Master) приложения | Суперадминистратор |
| Проверить, есть ли у меня то или иное право | Пользователь |
| Добавить/убрать приложение из избранного, поднять избранное в начало списка | Пользователь |
| Зарегистрировать внешнее приложение-консьюмера и выдать ему токен открытого API, назначить консьюмеру права на namespace или на всё приложение | Суперадминистратор |

| Посмотреть список организаций и общие настройки страницы (адрес wiki и т.п.) | Пользователь |

## Бизнес-правила

### сообщение «уведомление о публикации конфигурации»
- при обычной, серой или экстренной публикации, при откате релиза и при объединении серой ветки с основным кластером
- получатель — почта тех, кого должны уведомить об изменении; шаблоны конкретных писем для разных видов публикации лежат вне этого репозитория
- уходит только для окружений из отдельного списка разрешённых почтовых окружений
- в профиле без подключённого почтового сервиса сообщение не отправляется вовсе

### сообщение «публикация в NOC»
- при тех же событиях, что и почтовое уведомление — обычная/серая/экстренная публикация, откат, объединение серой ветки
- получатель — внутренняя система мониторинга изменений (NOC), не входящая в состав этого стенда
- вид — топик `ops.noc.record.created`
- отправляется только в одном из профилей развёртывания; в остальных профилях не уходит вовсе, и повторной отправки при сбое нет

## Публичный контракт

### DELETE /apps/{appId}
Удаление приложения.
сущности: → не сущность, класс App (вне сервиса)
- доступ только суперадминистратору
- после удаления рассылается запрос на удаление во все активные окружения

### DELETE /apps/{appId}/appnamespaces/{namespaceName}
Удаление пространства конфигурации приложения.
сущности: ← AppNamespace (вне сервиса) · → не сущность (void)
- доступ только суперадминистратору
- после удаления рассылается запрос на удаление во все активные окружения

### DELETE /apps/{appId}/envs/{env}/clusters/{clusterName}
Удаление кластера в окружении.
сущности: → не сущность, ответ соседнего сервиса
- доступ только суперадминистратору

### DELETE /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}
Удаление namespace в окружении.
сущности: → не сущность (void)
- доступ — суперадминистратор либо право назначения ролей на это приложение

### DELETE /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}
Удаление серой (gray) ветки namespace.
сущности: → не сущность (void)
- удалить можно при праве на релиз, либо при праве на изменение и условии, что ветка ещё не выпускалась; иначе отказ с объяснением причины

### DELETE /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/items/{itemId}
Удаление элемента конфигурации по идентификатору.
сущности: → не сущность, класс ItemDTO (вне сервиса)
- доступ — право редактирования этого namespace в этом окружении
- ошибка, если элемент принадлежит другому namespace, чем указан в пути

### DELETE /apps/{appId}/envs/{env}/namespaces/{namespaceName}/roles/{roleType}
Снятие роли уровня «namespace в окружении» с пользователя.
сущности: → не сущность (void)
- доступ — право назначения ролей на это приложение
- тип роли проверяется на допустимость значения

### DELETE /apps/{appId}/namespaces/{namespaceName}/roles/{roleType}
Снятие роли уровня «namespace» (без привязки к окружению) с пользователя.
сущности: → не сущность (void)
- доступ — право назначения ролей на это приложение

### DELETE /apps/{appId}/roles/{roleType}
Снятие роли владельца (Master) приложения с пользователя.
сущности: → не сущность (void)
- доступ — право управления владельцами приложения

### DELETE /apps/{appId}/system/master/{userId}
Запрет управления владельцами приложения для пользователя.
сущности: → не сущность (void)
- доступ только суперадминистратору

### DELETE /favorites/{favoriteId}
Удаление приложения из избранного.
сущности: → не сущность (void)

### DELETE /system/role/createApplication/{userId}
Снятие системного права создания приложений у пользователя.
сущности: → не сущность (void)
- доступ только суперадминистратору

### DELETE /openapi/v1/envs/{env}/apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items/{key}
Открытый API: удаление элемента конфигурации по ключу.
сущности: → не сущность (void)
- доступ — право редактирования namespace у консьюмера
- оператор и ключ должны существовать, иначе отказ

### GET /apps
Список приложений.
сущности: → не сущность, список класса App (вне сервиса)
- без параметра — все приложения; с параметром — только перечисленные через запятую

### GET /apps/{appId}
Приложение по идентификатору.
сущности: → не сущность, класс App (вне сервиса)

### GET /apps/{appId}/appnamespaces/{namespaceName}
Пространство конфигурации приложения по имени.
сущности: → не сущность, класс AppNamespace (вне сервиса)
- ошибка, если такое пространство не существует

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}
Кластер в окружении.
сущности: → не сущность, ответ соседнего сервиса

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/missing-namespaces
Список «пропавших» пространств конфигурации.
сущности: → не сущность, список имён
- «пропавшее» значит: пространство есть в портале, но не создано в окружении, либо приватное пространство без соответствующих данных в окружении

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces
Список пространств конфигурации кластера с их содержимым.
сущности: → не сущность, список агрегатов (базовые данные пространства + его элементы + признак «публичное»)
- если у пользователя нет доступа и окружение закрыто для не-участников — элементы и их число скрываются, выставляется признак «конфигурация скрыта»

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}
Пространство конфигурации с его содержимым.
сущности: → не сущность, тот же агрегат, что выше
- то же скрытие содержимого при отсутствии доступа и закрытом окружении

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/branches
Серая (gray) ветка namespace с её содержимым.
сущности: → не сущность, тот же агрегат, что выше
- то же скрытие содержимого при отсутствии доступа и закрытом окружении

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}/items
Элементы конфигурации серой ветки.
сущности: → не сущность, класс ItemDTO (вне сервиса)
- те же элементы, что у обычного namespace, но для ветки; сортировка по времени последнего изменения

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}/rules
Правила серого выпуска ветки.
сущности: → не сущность, класс правил выпуска (вне сервиса)

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/commits
История изменений namespace.
сущности: → не сущность, список записей изменений (вне сервиса)
- при отсутствии доступа и закрытом окружении — пустой список вместо истории
- номер страницы и размер страницы должны быть неотрицательными/положительными, иначе отказ

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/items
Элементы конфигурации namespace.
сущности: → не сущность, класс ItemDTO (вне сервиса)
- при отсутствии доступа и закрытом окружении — пустой список вместо элементов
- можно отсортировать по времени последнего изменения (по убыванию); по умолчанию — порядок добавления

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/items/export
Экспорт конфигурации namespace файлом.
сущности: → не сущность, агрегат по содержимому namespace
- содержимое целого файла (если такой элемент есть) отдаётся как есть, остальные пары — построчно «ключ = значение»
- имя файла — имя namespace; если в нём нет расширения, добавляется расширение формата properties
- ошибка при сбое записи файла в ответ

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/lock
Информация о блокировке namespace (устаревшая ручка).
сущности: → не сущность, класс блокировки (вне сервиса)
- ручка помечена как устаревшая в коде, заменена на `/lock-info`

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/lock-info
Информация о блокировке namespace и о разрешённости экстренной публикации.
сущности: → не сущность, агрегат «владелец блокировки + разрешена ли экстренная публикация»
- владелец блокировки — пустая строка (не null), если блокировки нет

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/releases/active
Текущий активный релиз и история активных релизов namespace.
сущности: → не сущность, класс ReleaseDTO (вне сервиса)
- при отсутствии доступа и закрытом окружении — пустой список
- номер и размер страницы должны быть неотрицательными/положительными, иначе отказ

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/releases/all
Все релизы namespace, включая неактивные.
сущности: → не сущность, агрегат по данным релиза (без маркера хранения)
- при отсутствии доступа и закрытом окружении — пустой список
- номер и размер страницы должны быть неотрицательными/положительными, иначе отказ

### GET /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/releases/histories
История публикаций namespace.
сущности: → не сущность, агрегат по истории публикаций (без маркера хранения)
- при отсутствии доступа и закрытом окружении — пустой список

### GET /apps/{appId}/envs/{env}/namespaces/{namespaceName}/permissions/{permissionType}
Проверка права пользователя на namespace в конкретном окружении.
сущности: → не сущность, признак «есть право» (булево)

### GET /apps/{appId}/envs/{env}/namespaces/{namespaceName}/role_users
Пользователи с ролями на namespace в конкретном окружении.
сущности: → не сущность, агрегат по Role (пользователи с ролью редактирования и с ролью релиза)
- ошибка при нераспознанном имени окружения

### GET /apps/{appId}/miss_envs
Окружения, в которых приложение не найдено.
сущности: → не сущность, список окружений
- окружение считается «пропавшим» для приложения только если соседний сервис ответил «не найдено»; любая другая ошибка возвращается как ошибка сервера, а не как «пропавшее окружение»

### GET /apps/{appId}/namespaces/publish_info
Есть ли неопубликованные изменения, по каждому окружению и кластеру.
сущности: → не сущность, карта «окружение → кластер → есть изменения»
- признак означает, что в кластере есть хотя бы один namespace без опубликованного релиза

### GET /apps/{appId}/namespaces/{namespaceName}/permissions/{permissionType}
Проверка права пользователя на namespace (без привязки к окружению).
сущности: → не сущность, признак «есть право» (булево)

### GET /apps/{appId}/namespaces/{namespaceName}/role_users
Пользователи с ролями на namespace (без привязки к окружению).
сущности: → не сущность, агрегат по Role

### GET /apps/{appId}/navtree
Сводная карта приложения по всем активным окружениям и кластерам — для навигации.
сущности: → не сущность, агрегат по активным окружениям
- каждое окружение опрашивается отдельно; ошибка одного окружения не блокирует остальные — проблемное окружение возвращается с сообщением об ошибке вместо данных

### GET /apps/{appId}/permissions/{permissionType}
Проверка права пользователя на уровне приложения.
сущности: → не сущность, признак «есть право» (булево)

### GET /apps/{appId}/role_users
Пользователи с ролью владельца (Master) приложения.
сущности: → не сущность, агрегат по Role

### GET /apps/by-owner
Приложения, принадлежащие указанному пользователю.
сущности: → не сущность, список App
- принадлежность определяется не отдельным полем владельца, а наличием у пользователя любой роли на это приложение

### GET /apps/search/by-appid-or-name
Поиск приложений по идентификатору или имени, с пагинацией.
сущности: → не сущность, страница App
- без поискового запроса — постраничный список всех приложений

### GET /appnamespaces/public
Список публичных пространств конфигурации всех приложений.
сущности: → не сущность, список AppNamespace (вне сервиса)

### GET /consumers/by-appId
Токен консьюмера по идентификатору приложения-консьюмера.
сущности: → ConsumerToken

### GET /envs
Список окружений.
сущности: → не сущность, список окружений
- возвращает только активные (не упавшие по проверке доступности) окружения

### GET /envs/{env}/apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/associated-public-namespace
Публичное пространство конфигурации, связанное с данным (для приватного пространства, унаследовавшего публичное).

- ключ элемента обязателен

### PUT /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/items
Изменение элементов namespace сплошным текстом.
сущности: ← модель текста namespace · → не сущность
- доступ по праву редактирования namespace в этом окружении
- заменяет содержимое namespace целиком предложенным текстом

### PUT /apps/{appId}/envs/{env}/clusters/{clusterName}/namespaces/{namespaceName}/syntax-check
Проверка синтаксиса предложенного текста конфигурации.
сущности: ← модель текста namespace · → не сущность
- доступ по праву редактирования namespace в этом окружении
- проверка реально выполняется только для форматов YAML/YML; для прочих форматов и для пустого текста ответ успешный, но без факта проверки

### PUT /apps/{appId}/namespaces/{namespaceName}/items
Синхронизация конфигурации namespace сразу по нескольким окружениям.
сущности: ← модель синхронизации · → не сущность
- отказ при недопустимой модели запроса
- нужно право редактирования хотя бы одним способом, либо право на КАЖДОЕ окружение из списка синхронизации — иначе отказ с указанием, в каком окружении не хватает прав

### PUT /envs/{env}/releases/{releaseId}/rollback
Откат релиза на предыдущий.
сущности: → не сущность
- отказ, если релиз с таким идентификатором не найден
- доступ по праву релиза namespace этого релиза в этом окружении, иначе отказ в доступе
- после отката публикуется уведомление о публикации (почта и NOC)

### PUT /favorites/{favoriteId}
Перемещение избранного приложения в начало списка пользователя.
сущности: → не сущность (void)
- точный алгоритм пересортировки остальных записей — не определено: лежит в сервисном слое, не исследован

### PUT /openapi/v1/envs/{env}/apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items/{key}
Открытый API: изменение элемента конфигурации.
сущности: ← проекция элемента · → не сущность (void)
- доступ по праву редактирования namespace у консьюмера
- ключ в пути и в теле должны совпадать
- изменить можно только значение, комментарий и автора последнего изменения — остальные поля существующего элемента не трогаются
- если включён параметр «создать при отсутствии» и ключ не найден — элемент создаётся этим же вызовом

### PUT /openapi/v1/envs/{env}/releases/{releaseId}/rollback
Открытый API: откат релиза.
сущности: → не сущность (void)
- оператор обязателен и должен существовать как пользователь
- отказ, если релиз не найден
- право на откат проверяется отдельно от общего механизма прав консьюмера: без права на релиз этого namespace — отказ в доступе

## Фоновые задачи

### EnvHealthChecker
Проверка доступности admin-сервиса каждого окружения.
- расписание — раз в 10 секунд, первый запуск через 1 секунду после старта
- окружение помечается недоступным после 2 подряд неудачных проверок; «оживает» сразу при первой успешной проверке
- результат определяет, какие окружения показываются пользователю как активные

### RefreshAdminServerAddressTask
Обновление адресов инстансов admin-сервиса по каждому окружению.
- сама себя перепланирует: при полном успехе по всем окружениям — следующий запуск через 5 минут, при неудаче хотя бы одного окружения — через 10 секунд
- на окружение — до 3 попыток получить адреса за один запуск
- при неудаче адреса этого окружения в кэше не обновляются, остаётся прежнее значение

### ConsumerAuditUtil
Запись журнала обращений к открытому API.
- работает непрерывно фоновым потоком с момента старта сервиса
- учитывает только не-чтение (не-GET) запросы открытого API
- сбрасывает накопленное в БД пачками по 100 записей либо раз в 5 секунд — что раньше наступит
- внутренняя очередь ограничена 10000 записей; при переполнении новые записи аудита отбрасываются, не блокируя запрос
- при перезапуске процесса несброшенные записи из очереди теряются

## Владеет данными

### Consumer
Внешнее приложение-консьюмер открытого API.
- `id`: `long`
- `name`: `string`
- `appId`: `string`
- `orgId`: `string`
- `orgName`: `string`
- `ownerName`: `string`
- `ownerEmail`: `string` — заполняется автоматически из данных владельца при создании, в запросе не передаётся
— уникальность `appId` обеспечивается проверкой в коде перед созданием; отдельный уникальный индекс в БД этого репозитория не определён

### ConsumerAudit
Журнал обращений консьюмеров к открытому API.
- `id`: `long`
- `consumerId`: `long`
- `uri`: `string`
- `method`: `string`
- `dataChangeCreatedTime`: `timestamp`
- `dataChangeLastModifiedTime`: `timestamp`
— пишется только для не-GET запросов; накопление и запись идут фоновой задачей, записи из памяти могут быть потеряны при переполнении очереди или перезапуске

### ConsumerRole
Связка «консьюмер — роль».
- `id`: `long`
- `consumerId`: `long`
- `roleId`: `long`
— повторное назначение той же пары консьюмер+роль идемпотентно, дубль не создаётся

### ConsumerToken
Токен доступа консьюмера к открытому API.
- `id`: `long`
- `consumerId`: `long`
- `token`: `string`
- `expires`: `timestamp`
— при создании без явного срока действия подставляется далёкая фиксированная дата (фактически «бессрочный»)

### Favorite
Избранное приложение пользователя.
- `id`: `long`
- `appId`: `string`
- `userId`: `string`
- `position`: `long` — порядок в списке избранного пользователя
— при перемещении записи «в начало» порядок остальных записей пользователя пересчитывается; точный алгоритм — не определено

### Permission
Право на целевой объект.
- `id`: `long`
- `permissionType`: `string`
- `targetId`: `string`
— пара `permissionType`+`targetId` задумана уникальной по бизнес-правилу; отдельный уникальный индекс в БД этого репозитория не определён

### Role
Роль (право, которое можно назначить пользователю, консьюмеру или группе).
- `id`: `long`
- `roleName`: `string` — составной идентификатор: тип роли плюс идентификатор приложения, а при необходимости — ещё namespace и/или окружение; не вводится человеком напрямую
— уникальность `roleName` задумана по бизнес-правилу

### RolePermission
Связка «роль — право».
- `id`: `long`
- `roleId`: `long`
- `permissionId`: `long`

### ServerConfig
Собственная конфигурация портала, хранимая в БД (а не в файле).
- `id`: `long`
- `key`: `string` — уникален по бизнес-правилу
- `value`: `string`
- `comment`: `string`
— создание и обновление идут одной и той же ручкой: если запись с таким `key` уже есть, обновляется она, иначе создаётся новая

### UserPO
Локальный пользователь (таблица `Users`).
- `id`: `long`
- `username`: `string`
- `password`: `string`
- `email`: `string`
- `enabled`: `int` (0/1)
— используется только в профиле со своей таблицей пользователей; в остальных профилях (LDAP, единый вход) пользователи хранятся не здесь

### UserRole
Связка «пользователь — роль».
- `id`: `long`
- `userId`: `string`
- `roleId`: `long`

## Роли и доступ
| Роль | Что может |
|---|---|
| superAdmin | полный доступ: управление пользователями, консьюмерами открытого API, серверной конфигурацией, системной информацией; удаление приложений, кластеров и namespace; назначение и снятие системных ролей |
| Master (владелец приложения) | изменение данных приложения, назначение ролей на namespace в своём приложении |
| ModifyNamespace | редактирование элементов конфигурации namespace (на приложение целиком или на конкретное окружение) |
| ReleaseNamespace | публикация, откат и экстренная публикация релиза namespace (на приложение целиком или на конкретное окружение) |
| CreateNamespace | создание нового namespace в приложении |
| CreateCluster | создание кластера в приложении |
| AssignRole | назначение и снятие ролей ModifyNamespace/ReleaseNamespace другим пользователям; фактически делает пользователя администратором приложения |
| CreateApplication | создание нового приложения — право закрыто только если включён отдельный переключатель, иначе есть у всех |
| ManageAppMaster | назначение и снятие роли владельца (Master) приложения — право закрыто только если включён отдельный переключатель, иначе есть у всех |
| консьюмер открытого API | те же права (CreateNamespace/CreateCluster/ModifyNamespace/ReleaseNamespace), но отдельно для внешнего приложения-консьюмера по токену, не для пользователя; роли суперадминистратора у консьюмера нет |
| без входа | статические ресурсы, страница входа, открытый API под собственным токеном и диагностический путь настройки — обходят обычную веб-аутентификацию портала |
| без входа (весь портал) | при отсутствии подключённого профиля аутентификации веб-защиты вообще нет — любой запрос проходит без входа |
