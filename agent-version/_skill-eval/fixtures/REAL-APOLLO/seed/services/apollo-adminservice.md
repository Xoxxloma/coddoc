# apollo-adminservice — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Назначение

Сервис ведёт иерархическую структуру конфигурации — приложение, кластер, пространство имён
(namespace) и пункты конфигурации внутри него (ключ-значение) — и управляет её выпуском в прод без
передеплоя потребляющих приложений. Поддерживает создание и удаление app, кластеров и namespace
(приватных и публичных, то есть общих для нескольких app); редактирование пунктов конфигурации с
захватом блокировки namespace на время правок, чтобы правки одного человека не затирались другим;
публикацию (релиз) конфигурации, включая экстренную публикацию и откат к предыдущему релизу; серое
(gray) тестирование новой конфигурации на части клиентов через ветки (branch) с собственными
правилами выдачи по идентификатору приложения и IP, и последующее слияние ветки обратно в основную конфигурацию.
Главные объекты — приложения, кластеры, пространства имён и их пункты конфигурации, релизы и их
история, а также запущенные экземпляры клиентов и то, какую конфигурацию они фактически получили.

## Бизнес-правила

### сообщение «конфигурация namespace изменилась»
- не письмо и не push: строка-ключ namespace кладётся в общую таблицу БД (канал `apollo-release`),
  которую опросом читает `apollo-configservice`, чтобы обновить свой кэш; получатель —
  `apollo-configservice`, сам сервис эту таблицу не читает
- шлётся при публикации (обычной, экстренной, gray-del, слиянием ветки), при откате релиза, при
  изменении или удалении правил gray-ветки и при удалении namespace
- не шлётся при создании или правке отдельных пунктов конфигурации до публикации — только по факту
  публикации или отмены

## Публичный контракт

### GET /
Корневой ответ сервиса.
сущности: → не сущность, ответ строкой
(фактов нет — служебный)

### GET /appnamespaces/{publicNamespaceName}/associated-namespaces/count
Число namespace других приложений, подключённых к этому публичному namespace.
сущности: → не сущность, агрегат: количество
- `400` — публичного namespace с таким именем нет
- в счёт не входит namespace самого приложения-владельца публичного namespace

### GET /appnamespaces/{publicNamespaceName}/namespaces
Список namespace других приложений, подключённых к этому публичному namespace.
сущности: → не сущность, ответ `NamespaceDTO` (список)
- `400` — публичного namespace с таким именем нет
- из списка исключены gray-ветки: видны только обычные (не дочерние) namespace

### GET /apps
Список приложений, постранично или по точному совпадению имени.
сущности: → не сущность, ответ `AppDTO` (список)
- без параметра `name` — постраничная выдача всех приложений
- с параметром `name` — поиск по точному совпадению имени, без пагинации

### GET /apps/{appId}
Карточка одного приложения.
сущности: → не сущность, ответ `AppDTO`
- `404` — приложение с таким `appId` не найдено

### GET /apps/{appId}/appnamespaces
Namespace-шаблоны (публичные и приватные), заведённые этим приложением.
сущности: → не сущность, ответ `AppNamespaceDTO` (список)

### GET /apps/{appId}/cluster/{clusterName}/unique
Свободно ли имя кластера в этом приложении.
сущности: → не сущность, агрегат: булево
- путь использует единственное число «cluster», а не «clusters», как во всех остальных вызовах про кластеры

### GET /apps/{appId}/clusters
Список кластеров приложения.
сущности: → не сущность, ответ `ClusterDTO` (список)
- возвращает только обычные кластеры: gray-ветки в список не попадают

### GET /apps/{appId}/clusters/{clusterName}
Карточка одного кластера.
сущности: → не сущность, ответ `ClusterDTO`
- `404` — кластер с таким именем не найден

### GET /apps/{appId}/clusters/{clusterName}/namespaces
Список namespace кластера.
сущности: → не сущность, ответ `NamespaceDTO` (список)

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}
Карточка одной namespace.
сущности: → не сущность, ответ `NamespaceDTO`
- `404` — namespace не найдена

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/associated-public-namespace
Какая именно namespace (своего или дефолтного кластера) отдаёт конфигурацию клиентам этого
публичного namespace в этом кластере.
сущности: → не сущность, ответ `NamespaceDTO`
- для дефолтного кластера возвращается собственная namespace
- для прочих кластеров: если у собственной namespace кластера есть активный релиз — отдаётся она;
  если нет, а у дефолтной есть — отдаётся дефолтная; если у обеих релиза нет — отдаётся собственная
- `404` — если выбор не дал результата (ни публичного namespace с таким именем нет)

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/branches
Текущая gray-ветка namespace, если она есть.
сущности: → не сущность, ответ `NamespaceDTO`
- `400` — родительская namespace не найдена
- если ветки нет — тело ответа `null` при HTTP `200`, а не `404`

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}/rules
Правила выдачи gray-ветки: каким клиентам (по appId и списку IP) показывать её конфигурацию.
сущности: → не сущность, ответ `GrayReleaseRuleDTO`
- `400` — родительская или дочерняя (ветка) namespace не найдена
- если правил ещё нет — тело ответа `null` при HTTP `200`, а не `404`
- список IP может содержать значение «любой IP» — тогда правило действует на всех клиентов этого appId

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/commit
История правок пунктов конфигурации этой namespace, постранично.
сущности: → не сущность, ответ `CommitDTO` (список)

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items
Текущие пункты конфигурации namespace, в порядке строк.
сущности: → не сущность, ответ `ItemDTO` (список)
- порядок — по номеру строки (`lineNum`) по возрастанию

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items/deleted
Удалённые пункты конфигурации этой namespace.
сущности: → не сущность, ответ `ItemDTO` (список)
- список не читается из текущего состояния, а восстанавливается разбором истории правок (записей
  коммитов) всей namespace — если история не хранится или подчищена, восстановить список нельзя

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items/{key}
Один пункт конфигурации по ключу.
сущности: → не сущность, ответ `ItemDTO`
- `404` — ключ не найден в этой namespace

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/lock
Кто сейчас держит блокировку этой namespace, если держит.
сущности: → не сущность, ответ `NamespaceLockDTO`
- `400` — namespace не найдена
- если блокировка в принципе выключена конфигом сервиса ИЛИ просто никто сейчас не держит namespace —
  в обоих случаях тело ответа одинаковое: `null` при HTTP `200`; различить эти два случая по ответу
  нельзя

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/releases/active
Активные (не отменённые) релизы namespace, постранично.
сущности: → не сущность, ответ `ReleaseDTO` (список)

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/releases/all
Все релизы namespace, включая отменённые откатом, постранично.
сущности: → не сущность, ответ `ReleaseDTO` (список)

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/releases/histories
История релизов namespace (публикации, откаты, слияния gray-веток), постранично.
сущности: → не сущность, ответ `PageDTO<ReleaseHistoryDTO>`
- если страница пуста — тело ответа `null` целиком, а не пустая страница с нулевым счётчиком
- контекст операции (`operationContext`) хранится как JSON-строка и разбирается в карту на лету при
  каждом ответе

### GET /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/releases/latest
Последний активный релиз namespace.
сущности: → не сущность, ответ `ReleaseDTO`
- если активного релиза нет — тело ответа `null` при HTTP `200`, а не `404`

### GET /apps/{appId}/namespaces/publish_info
По каждому кластеру приложения — есть ли в нём namespace с неопубликованными изменениями.
сущности: → не сущность, агрегат: карта «кластер → есть неопубликованные изменения»
- `400` — у приложения нет ни одного кластера
- «неопубликовано» — это не просто наличие несохранённых пунктов: значение пункта должно отличаться
  от уже выпущенного в последнем релизе, иначе правка не считается неопубликованной

### GET /apps/{appId}/unique
Свободен ли этот `appId`.
сущности: → не сущность, агрегат: булево

### GET /instances/by-namespace
Экземпляры клиентов, получившие конфигурацию этой namespace, постранично.
сущности: → не сущность, ответ `PageDTO<InstanceDTO>`
- учитываются только конфигурации экземпляров, обновлённые не более ~25 часов назад (сутки плюс час
  запаса на разницу часов) — более старые считаются неактуальными и в выдачу не попадают
- необязательный параметр `instanceAppId` сужает выборку до экземпляров конкретного приложения

### GET /instances/by-namespace-and-releases-not-in
Экземпляры этой namespace, которые применили конфигурацию НЕ из перечисленного списка релизов.
сущности: → не сущность, ответ `InstanceDTO` (список); вложенный `configs[].release` заполнен `ReleaseDTO`
- используется, чтобы найти экземпляры, пропустившие один из указанных релизов
- у вложенного `release` обнулено поле `configurations` «для экономии места» — сам факт применения
  видно, содержимое конфигурации — нет

### GET /instances/by-namespace/count
Число экземпляров этой namespace (без деталей, только счётчик).
сущности: → не сущность, агрегат: число
- тот же фильтр «не более ~25 часов», что у `GET /instances/by-namespace`

### GET /instances/by-release
Экземпляры, применившие конкретный релиз.
сущности: → не сущность, ответ `PageDTO<InstanceDTO>`; вложенный `configs[].release` — всегда `null`
- `404` — указанный `releaseId` не найден
- в отличие от `GET /instances/by-namespace-and-releases-not-in`, здесь поле `release` внутри
  `configs[]` обнулено всегда, даже когда релиз существует — «для экономии места»

### GET /items/{itemId}
Один пункт конфигурации по внутреннему id.
сущности: → не сущность, ответ `ItemDTO`
- `404` — id не найден

### GET /namespaces/{namespaceId}
Карточка namespace по внутреннему id.
сущности: → не сущность, ответ `NamespaceDTO`

### GET /releases
Несколько релизов по списку id.
сущности: → не сущность, ответ `ReleaseDTO` (список)
- `releaseIds` передаётся через запятую; id, которых не существует, просто отсутствуют в ответе —
  без ошибки

### GET /releases/{releaseId}
Один релиз по id.
сущности: → не сущность, ответ `ReleaseDTO`

### GET /releases/histories/by_previous_release_id_and_operation
История релизов, у которых указанный релиз был предыдущим, с фильтром по виду операции.
сущности: → не сущность, ответ `PageDTO<ReleaseHistoryDTO>`

### GET /releases/histories/by_release_id_and_operation
История релизов по id релиза, с фильтром по виду операции.
сущности: → не сущность, ответ `PageDTO<ReleaseHistoryDTO>`
- те же два факта, что у `GET /releases/histories/by_previous_release_id_and_operation`

### POST /apps
Завести приложение.
сущности: ← `AppDTO` · → не сущность, ответ `AppDTO`
- `400` — `appId` уже занят
- `appId` ограничен набором символов (цифры, буквы, `-_.`), иначе `400` с сообщением о неверном
  формате
- создание атомарно заводит дефолтный namespace `application`, дефолтный кластер `default` и по
  одной namespace в этом кластере на каждый уже существующий у приложения namespace-шаблон

### POST /apps/{appId}/appnamespaces
Завести namespace-шаблон (приватный или публичный) для приложения.
сущности: ← `AppNamespaceDTO` · → не сущность, ответ `AppNamespaceDTO`
- `400` — имя уже занято и не передан флаг «тихого» подключения
- при занятом имени и выставленном флаге «тихого» подключения — не ошибка: приложение молча
  доращивает у себя namespace этого имени во всех своих кластерах и получает в ответ уже
  существующий namespace-шаблон
- если формат не передан — подставляется формат `Properties`

### POST /apps/{appId}/clusters
Завести кластер приложения.
сущности: ← `ClusterDTO` · → не сущность, ответ `ClusterDTO`
- `400` — имя кластера в этом приложении уже занято
- имя кластера и `appId` обязательны, имя ограничено тем же набором символов, что у приложения и namespace
- флаг «создавать приватные namespace автоматически» (по умолчанию включён) — при включении новый
  кластер сразу получает по одной namespace на каждый namespace-шаблон приложения; при выключении
  кластер создаётся пустым

### POST /apps/{appId}/clusters/{clusterName}/namespaces
Завести namespace в кластере.
сущности: ← `NamespaceDTO` · → не сущность, ответ `NamespaceDTO`
- `400` — такая namespace уже есть
- имя namespace ограничено тем же набором символов, что у приложения и кластера

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/branches
Завести gray-ветку namespace для серого тестирования конфигурации.
сущности: → не сущность, ответ `NamespaceDTO`
- `400` — родительская namespace не найдена
- `400` — у namespace уже есть gray-ветка
- `400` — родительский кластер сам является gray-веткой: создать ветку от ветки нельзя
- для ветки заводится отдельный технический кластер с сгенерированным именем, в котором и хранится
  её конфигурация

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/gray-del-releases
Опубликовать gray-ветку, дополнительно исключив из выдачи отдельные ключи.
сущности: → не сущность, ответ `ReleaseDTO`
- вызов имеет смысл только для gray-ветки: если у переданной namespace нет родителя — `404`
  «родительская namespace не найдена»
- `400` «публикация самим же держателем блокировки запрещена», если блокировку держит тот же
  `operator`, а режим экстренной публикации не включён
- исключаемые ключи (`grayDelKeys`) убираются из объединённой конфигурации родителя и ветки уже
  после слияния — то есть «гасят» и собственные ключи ветки, и унаследованные от родителя
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items
Добавить пункт конфигурации.
сущности: ← `ItemDTO` · → не сущность, ответ `ItemDTO`
- `400` — такой ключ в namespace уже есть
- ключ длиннее настраиваемого предела (по умолчанию 128 символов) — `400` с указанием предела
- значение длиннее настраиваемого предела (по умолчанию 20000 символов; предел может быть
  переопределён отдельно для конкретной namespace) — `400` с указанием предела
- требует предварительного захвата блокировки namespace (см. «Бизнес-правила» выше в карточке — факт
  о переключателе-конфиге вынесен туда же, в «Публичный контракт» не дублируется)
- каждое добавление пишет отдельную запись истории правок (коммит)

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/itemset
Пакетно добавить, изменить и удалить пункты конфигурации одним вызовом.
сущности: ← не сущность, список создаваемых/обновляемых/удаляемых `ItemDTO` · → не сущность, пустой ответ
- у обновляемых пунктов меняются только значение, комментарий и номер строки — остальное защищено
- захватывает блокировку namespace на весь вызов
- пишет одну запись истории правок на весь пакет, если в нём были реальные изменения

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/releases
Опубликовать (выпустить) текущую конфигурацию namespace.
сущности: → не сущность, ответ `ReleaseDTO`
- `404` — namespace не найдена
- `400` «публикация самим же держателем блокировки запрещена», если блокировку держит тот же
  `operator`, а режим экстренной публикации не включён
- если у namespace есть gray-ветка — после публикации основной конфигурации её gray-релиз
  автоматически пересчитывается и переиздаётся тоже, одним вызовом
- успешная публикация снимает блокировку namespace
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### POST /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/updateAndPublish
Влить правки gray-ветки в основную конфигурацию и сразу опубликовать её.
сущности: ← набор правок (`ItemDTO` на создание/изменение/удаление) · → не сущность, ответ `ReleaseDTO`
- `404` — namespace не найдена
- флаг «удалить ветку после слияния» включён по умолчанию
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### PUT /apps/{appId}
Изменить данные приложения.
сущности: ← не сущность, тело запроса — класс без маркера хранения в этом сервисе · → не сущность, пустой ответ
- `400` — `appId` из пути и из тела запроса не совпадают
- меняются только название, организация и владелец; сам `appId` существующей записи через этот
  вызов не меняется

### PUT /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}/rules
Задать правила выдачи gray-ветки.
сущности: ← `GrayReleaseRuleDTO` · → не сущность, пустой ответ
- `400` — родительская или дочерняя (ветка) namespace не найдена
- старые правила этой ветки не обновляются по месту, а удаляются и заменяются новыми целиком
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### PUT /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/items/{itemId}
Изменить пункт конфигурации.
сущности: ← `ItemDTO` · → не сущность, ответ `ItemDTO`
- `400` — id не найден
- защищено: через этот вызов можно поменять только значение и комментарий; ключ пункта и
  принадлежность namespace изменить нельзя
- значение длиннее настраиваемого предела (по умолчанию 20000 символов, может быть переопределён для
  конкретной namespace) — `400` с указанием предела
- требует предварительного захвата блокировки namespace
- запись истории правок пишется только если изменение что-то реально поменяло

### PUT /releases/{releaseId}/rollback
Откатить namespace к предыдущему активному релизу.
сущности: → не сущность, пустой ответ
- `404` — releaseId не найден
- `400` — релиз уже отменён ранее
- `400` «нельзя откатить — активен только один релиз», если активных релизов меньше двух
- откатывает к предпоследнему активному релизу; если у namespace есть gray-ветка, её конфигурация
  при необходимости тоже пересчитывается и переиздаётся
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### DELETE /apps/{appId}
Удалить приложение.
сущности: → не сущность, пустой ответ
- `404` — приложение не найдено
- каскадно удаляет все кластеры приложения (а через них — их namespace) и все namespace-шаблоны
  приложения

### DELETE /apps/{appId}/appnamespaces/{namespaceName}
Удалить namespace-шаблон приложения.
сущности: → не сущность, пустой ответ
- `400` — namespace-шаблон не найден
- удаляет сам шаблон и все namespace этого имени во всех кластерах приложения, с тем же каскадом,
  что у удаления отдельной namespace (см. ниже)

### DELETE /apps/{appId}/clusters/{clusterName}
Удалить кластер.
сущности: → не сущность, пустой ответ
- `404` — кластер не найден
- `400` — это дефолтный кластер; дефолтный кластер удалить нельзя
- удаляет все namespace этого кластера, с тем же каскадом, что у удаления отдельной namespace

### DELETE /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}
Удалить namespace.
сущности: → не сущность, пустой ответ
- `404` — namespace не найдена
- каскад: удаляются пункты конфигурации, история правок и, если это не gray-ветка, релизы этой
  namespace; удаляется её запись в истории релизов и данные о применивших её экземплярах; снимается
  блокировка; сама namespace помечается удалённой (мягкое удаление, не физическое)
- если у удаляемой namespace есть gray-ветка — ветка (её технический кластер и правила) удаляется
  вместе с ней, но релизы самой ветки при этом НЕ удаляются
- релизы gray-ветки переживают удаление родительской namespace
- удаление шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### DELETE /apps/{appId}/clusters/{clusterName}/namespaces/{namespaceName}/branches/{branchName}
Удалить gray-ветку.
сущности: → не сущность, пустой ответ
- `400` — родительская или дочерняя (ветка) namespace не найдена
- при успехе шлёт сообщение «конфигурация namespace изменилась» (см. «Бизнес-правила»)

### DELETE /items/{itemId}
Удалить пункт конфигурации.
сущности: → не сущность, пустой ответ
- `404` — id не найден
- удаление мягкое: запись помечается удалённой, а не стирается физически — поэтому она и
  восстановима через `GET …/items/deleted`
- требует предварительного захвата блокировки namespace
- пишет отдельную запись истории правок с описанием удаления
