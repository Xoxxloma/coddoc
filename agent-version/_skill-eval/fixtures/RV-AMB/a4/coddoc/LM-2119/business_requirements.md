## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего механизма входа через OIDC (единый вход, SSO) в listmonk: в его настройках появляется опция автоматического создания пользователя.

### 1.1. Описание проблемы
Состав пользователей в SSO большой и часто меняется, а войти в listmonk может только тот, кого отдельно завели в системе руками: ручное заведение не успевает за изменениями состава в SSO.

### 1.2. Конечные потребители
Администратор listmonk (настраивает опцию) и сотрудники, входящие через SSO (получают доступ без ручного заведения учётной записи).

### 1.4. Как сейчас

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор listmonk должен иметь возможность настроить автоматическое создание пользователей из SSO с ролью по умолчанию, чтобы сотрудники, появившиеся в SSO, получали доступ к listmonk сразу при первом входе — без ручного заведения учётной записи.

### 2.2. Ценность для бизнеса
Экономия времени администратора на ручном заведении пользователей и отсутствие ситуаций, когда нужному человеку нет доступа только потому, что его не успели завести вручную.

## 3. Объём проекта

### 3.1. Входит в проект
- Опция в настройках OIDC «создавать пользователя автоматически, если его ещё нет» (по умолчанию выключена).
- Выбор роли по умолчанию (из уже существующих в системе ролей) для пользователей, создаваемых автоматически.
- При включённой опции — автоматическое создание пользователя при первом входе через SSO, если такого пользователя в listmonk ещё нет: с выбранной ролью по умолчанию, обычного типа, включённого.
- Роль присваивается автоматически созданному пользователю один раз, в момент создания; при последующих входах того же пользователя не пересматривается.

### 3.2. Не входит в проект
- При выключенной опции поведение не меняется: пользователь без учётной записи в listmonk войти не может.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса
- **FR-1.** В настройках OIDC администратор может включить опцию «создавать пользователя автоматически, если его ещё нет» (по умолчанию опция выключена).
- **FR-2.** В тех же настройках администратор выбирает роль по умолчанию для пользователей, которые будут созданы автоматически, — из уже существующих в системе ролей.
- **FR-3.** При первом входе через SSO пользователя, которого нет в listmonk: если опция выключена — вход отклоняется, как сейчас, без изменений; если включена — listmonk создаёт пользователя (обычного типа, включённого) с выбранной ролью по умолчанию и пускает его.
- **FR-4.** Роль, присвоенная при автоматическом создании, при последующих входах того же пользователя не пересматривается и не обновляется, даже если роль по умолчанию в настройках впоследствии изменена.

### 4.2. Критерии приёмки
- **FR-1.** Дано: опция в настройках OIDC. Когда администратор открывает настройки после обновления — тогда опция «создавать пользователя автоматически» выключена. Когда администратор включает опцию и сохраняет настройки — тогда опция остаётся включённой.
- **FR-2.** Дано: опция включена. Когда администратор открывает выбор роли по умолчанию — тогда может выбрать любую из существующих в системе ролей.
- **FR-3.** Дано: опция выключена. Когда пользователь без учётной записи в listmonk входит через SSO — тогда вход отклоняется.
  Дано: опция включена. Когда такой пользователь входит через SSO первый раз — тогда создаётся пользователь с выбранной ролью по умолчанию, и вход происходит успешно.
- **FR-4.** Дано: пользователь уже создан автоматически, и роль по умолчанию в настройках впоследствии изменена. Когда этот же пользователь входит через SSO повторно — тогда его роль остаётся прежней, не обновляется.

### 4.5. Разбиение на части
Не применимо: все четыре FR — звенья одного механизма (настройка опции и роли по умолчанию + её применение при входе через SSO). Ни один FR не даёт бизнесу ценности по отдельности: настройка без логики создания ничего не меняет, а логика создания не работает без настроек.
