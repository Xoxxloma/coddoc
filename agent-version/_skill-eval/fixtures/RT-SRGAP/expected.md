# RT-SRGAP — настоящая проверка спеки в треде оркестратора

Готовый БТ PSS-2210 (заявка на разовый пропуск; §4.5 «не применимо») → `technical-spec-doc` (заглушка
копирует спеку фикстуры `SR-GAP` и, как живой автор, выводит её в чат целиком) → приёмка (заглушка) →
узел «Что дальше?» → реплика «Проверить спеку.» → **живой** `rehearse … проверка` (снимок из репозитория
поверх заглушек, `REAL_SUBS=rehearse`; до 5.89 — `spec-readiness`).

Зачем. До 2.0.0 проверку запускал аналитик сам, в чистом контексте. Теперь её зовёт оркестратор — в
треде, где спека только что напечатана целиком. Правило проверки «спеку ты не открываешь, читают
роли» держится тем, что ведущий текста спеки не видел; здесь он его видел.

| Что | Верно |
|---|---|
| вызов | `rehearse <путь спеки> проверка` |
| роли | ведущий поднял трёх субагентов-ролей и сводящего — `Agent` в его потоке ≥ 4 |
| спека | ведущий целиком её не читает: `Read` спеки только строкой опоры, `limit` ≤ 10 |
| запись | ноль `Write`/`Edit` в ходе проверки |
| промпты ролей | промпт `check.md` без добавлений: `services/` в нём нет, карточки роли ищут сами |
| после списка | список «Проверка: … Критичных вопросов: N» и тем же ходом узел «Что дальше?» снова |

Считать по ведущему: события субагентов приходят в тот же поток с `parent_tool_use_id` — их
отбрасывать. Сравнение улова с отдельным запуском `chk-gap` — справкой (ключ дыр — `SR-GAP/README.md`).

Грейд: `grade-rt-srgap.mjs`.
