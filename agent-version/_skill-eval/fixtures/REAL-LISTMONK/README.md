# REAL-LISTMONK — настоящая задача: БТ и спека с эталоном из влитого PR

Задача: [knadh/listmonk#2119](https://github.com/knadh/listmonk/issues/2119), автосоздание пользователей при входе через
OIDC. Эталон: PR #2578, squash `c9c678c`. listmonk — AGPL-3.0.

Цепочка `run-chain.sh real-listmonk`: стадия 1 пишет БТ, стадия 2 — спеку по этому БТ, без правки между ними.

- `seed/services/` — карточка `service-map` (скилл из main) с коммита `66d7413`, сразу перед PR. Клон в
  `product/real/listmonk-pre2578`. Карточки с текущего кода не годятся: в них уже есть автосоздание.
- `stage-1-twin-card.md`, `stage-2-twin-card.md` — двойник отвечает словами из 14 комментариев задачи и описания PR в
  переводе. Из кода PR взяты: роль на списки, поля нового пользователя, страница входа при отказе.
- `expected.md` — анкеры, написаны до первого прогона.

Зачем вторая задача: проверить, повторяются ли механизмы потерь, найденные на Apollo. Модель стенда этой фичи не помнит
(проверено вопросом 2026-11-09), Apollo — помнит: HMAC-SHA1, заголовки, таблица.

Клиентской библиотеки в задаче нет, поэтому механизм «клиент не сторона изменения» здесь проверяется только через
фронт, который лежит в той же репе.
