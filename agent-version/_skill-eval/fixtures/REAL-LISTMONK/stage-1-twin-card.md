## Когда спрашивают о зачем, проблеме, цели, чего хотим добиться, кому это больно

Отвечаешь: Сейчас администратор должен заранее завести каждого пользователя в listmonk, иначе тот через SSO не войдёт. Пользователей в SSO много, и состав меняется. Пример из обсуждения: команда около десяти человек, где люди часто приходят и уходят. Заводить каждого руками — мучение.

## Когда спрашивают, как сейчас устроен вход через SSO, как находят пользователя, по какому признаку сопоставляют

Отвечаешь: Сейчас вход через SSO ищет пользователя listmonk по e-mail, который пришёл из SSO: нашёлся — входит, нет — не пускаем. После изменения сопоставление то же, по e-mail; создаём только того, кого по этому e-mail не нашли.

## Когда спрашивают об участниках, ролях, кто что делает, кто включает

Отвечаешь: Опцию включает и роль по умолчанию выбирает администратор listmonk: Настройки → Безопасность → OIDC. Сотрудник просто входит через SSO.

## Когда спрашивают, какую роль или права получает новый пользователь, про роль по умолчанию

Отвечаешь: Роль пользователя по умолчанию выбирают в настройках, без неё опцию не включить. Там же можно выбрать роль на списки по умолчанию — по желанию, можно оставить пустой.

## Когда спрашивают, берём ли роли, группы или права из SSO-провайдера, про scopes

Отвечаешь: Не в этой задаче: роли из SSO и настраиваемые scopes сейчас не делаем.

## Когда спрашивают о свойствах нового пользователя: имя, логин, пароль, статус, тип

Отвечаешь: Обычный пользователь, сразу активный, логин — его e-mail. Пароля у него нет, входит только через SSO. Имя берём из SSO: полное имя, если его нет — имя пользователя в SSO, если и его нет — часть e-mail до @.

## Когда спрашивают про уже заведённых пользователей, их повторный вход и роль, совместимость, обновление, включено ли по умолчанию

Отвечаешь: По умолчанию опция выключена, после обновления всё работает как раньше. Уже заведённые пользователи входят как входили.
