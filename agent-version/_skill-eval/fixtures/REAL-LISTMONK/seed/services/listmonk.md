# listmonk — backend

> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Назначение

Сервис позволяет организации вести собственную рассылку писем на своей инфраструктуре, без стороннего провайдера почтовых рассылок — самостоятельный, самостоятельно размещаемый менеджер списков адресатов и рассылок с базой на PostgreSQL. Он поддерживает сбор и сегментацию адресатов по спискам с одно- и двухшаговым подтверждением подписки (opt-in), подготовку и отправку кампаний по шаблонам с вложениями, обработку технических отказов доставки из почтового ящика и от вебхуков почтовых провайдеров, массовый импорт адресатов из файла, отправку отдельных транзакционных писем по запросу и публичный архив прошлых рассылок. Главные объекты — адресаты, списки рассылки, кампании, шаблоны писем и отказы доставки.

## Бизнес-правила

### `Bounce` — отказ доставки письма
- `hard` (постоянный отказ), `soft` (временный), `complaint` (жалоба на спам) — каждый вид считается у адресата отдельно от других видов; при достижении настроенного порога срабатывает настроенное действие: блокировка адресата, отписка от всех списков или удаление профиля целиком
- отказ не фиксируется вовсе, если адресат уже заблокирован

### `Campaign` — кампания рассылки
- `draft` (черновик) — начальное состояние любой новой кампании, даже если при создании передан другой статус
- `scheduled` (запланирована) — доступен переход только из `draft` или `paused`, и только если задана дата отправки
- `running` (идёт) — доступен переход только из `draft` или `paused`
- `paused` (на паузе) — вручную доступен только из `running`; автоматически — после серии подряд идущих ошибок отправки сверх настроенного предела, с уведомлением администраторам
- `finished` (завершена) — ставится автоматически, когда у запущенной или запланированной кампании заканчиваются получатели
- `cancelled` (отменена) — вручную доступен только из `running` или `paused`, обратного перехода нет
- редактировать содержимое кампании можно только в статусах `draft`, `paused` или `scheduled`
- `regular` (обычная) — для двухшаговых списков уходит только подтвердившим подписку, для одношаговых — всем, кто не отписался явно
- `optin` (приглашение подтвердить) — тело письма генерируется автоматически и адресуется только тем, кто ещё не подтвердил подписку на двухшаговый список
- `visual` (визуальный формат) — при предпросмотре игнорирует сохранённый в шаблоне текст и выбранный шаблон
- `plain` (текстовый формат) — при предпросмотре отдаётся как обычный текст, остальные форматы — как HTML

### `List` — список рассылки
- `private` (приватный) — не отдаётся в публичном перечне и недоступен для подписки через публичную форму; его название при выгрузке личных данных подписчика в ответ не попадает
- `public` (публичный) — виден в публичном перечне и открыт для подписки
- `single` (одношаговый) — подписчик, не отписавшийся явно, считается получателем кампаний
- `double` (двухшаговый) — подписчику сначала уходит письмо-подтверждение; получателем обычной кампании он становится только после подтверждения

### `Media` — загруженный файл
- `filesystem`, `s3` — определяет, откуда позже читаются байты и ссылка файла; значение фиксируется в момент загрузки и для уже загруженного файла не пересчитывается заново при смене настройки

### `Role` — именованный набор прав
- роль для пользователей — несёт произвольный набор прав из общего каталога
- роль для списков — несёт только права на чтение/управление конкретными списками; у одного пользователя не может быть больше одной такой роли одновременно
- встроенная роль с зарезервированным идентификатором (Super Admin) обходит все проверки прав, включая проверки по спискам, и не может быть изменена или удалена через API

### `Subscriber` — адресат рассылки
- `enabled` (активен) — обычный получатель
- `blocklisted` (заблокирован) — не получает кампаний; ставится вручную или автоматически по накопленным отказам доставки; при установке снимает сразу все подписки адресата на все списки
- не определено: переход в значение `disabled` объявлен в коде, но самого перехода в него не нашлось

### `Subscription` — подписка адресата на список
- `unconfirmed` (не подтверждена) — подписка оформлена, подтверждения не было
- `confirmed` (подтверждена) — подтверждена явно по ссылке либо проставлена сразу при соответствующем флаге на операции подписки или импорта
- `unsubscribed` (отписан) — адресат отписался сам либо отписан массовой операцией или блокировкой

### `Template` — шаблон письма
- для шаблона транзакционных писем тема обязательна; у шаблона кампании и визуального шаблона тема всегда стирается при сохранении, потому что берётся с самой кампании
- отметку «шаблон по умолчанию» одновременно может нести только один шаблон во всей таблице

### `User` — пользователь
- `user` (обычный) — вход по логину и паролю либо через OIDC
- `api` (API-клиент) — вход только токеном, пароль генерируется автоматически и не раскрывается, кроме момента создания/обновления
- `enabled`/`disabled` — вход по паролю и действие API-токена возможны только у включённого пользователя

### сообщение «подтверждение подписки»
- уходит адресату двухшагового списка при оформлении подписки (если автоподтверждение не включено) и повторно — по отдельному запросу

### сообщение «смена статуса кампании»
- уходит администраторам при автоматической постановке кампании на паузу из-за ошибок отправки и при её естественном завершении

### сообщение «статус импорта»
- уходит администраторам по завершении, остановке или сбое импорта адресатов

### сообщение «выгрузка личных данных»
- уходит самому адресату вложением при его самостоятельном запросе на выгрузку данных

### сообщение «проверка почтового сервера»
- уходит на адрес, который администратор указал при тестировании настроек SMTP

### ограничение «массовые операции по произвольному условию над адресатами отключены»
- условием управляет отдельно выдаваемое право `subscribers:sql_query`; без него попытка задать условие выборки отклоняется
- переключатель: `пользовательская роль (назначается через каталог гранулярных прав)`

## Стек
| Слой | Чем |
|---|---|
| Язык и фреймворк | Go, Echo |
| Хранилище | PostgreSQL |
| Почта | встроенный SMTP messenger; опционально внешние вебхуки отказов (Amazon SES, SendGrid, Postmark, ForwardEmail) и POP-ящик для отказов |
| Файлы | локальная файловая система либо S3 (настраивается) |
| Сессии входа | cookie-сессии, хранятся в PostgreSQL |
| Вход | логин и пароль, API-токен, OIDC |
| Антиспам | hCaptcha (для публичной формы подписки) |

## Публичный контракт

### `GET /`
Публичная заглушка-лендинг.
(фактов нет — служебный)

### `GET /admin`
Отдаёт собранный фронтенд администратора (SPA).
(фактов нет — служебный)

### `GET /admin/*`
Catch-all для роутинга SPA администратора на клиенте.
(фактов нет — служебный)

### `GET /admin/custom.css`
Отдаёт кастомный CSS администратора из настроек внешнего вида.
(фактов нет — служебный)

### `GET /admin/custom.js`
Отдаёт кастомный JS администратора из настроек внешнего вида.
(фактов нет — служебный)

### `GET /admin/login`
Страница входа; если ни одного пользователя ещё не создано, вместо неё отдаётся страница первичной настройки.
сущности: → не сущность, HTML-страница
- если пользователей в системе нет — показывается форма создания первого администратора вместо формы входа

### `POST /admin/login`
Обработка формы входа или формы первичной настройки, в зависимости от того, создан ли уже хоть один пользователь.
сущности: ← `username`,`password` (или данные первичной настройки) · → редирект либо HTML с ошибкой
- при первичной настройке создаётся встроенная роль Super Admin со всеми правами из каталога и первый пользователь с ней
- обычный вход сверяет пароль в самом SQL-запросе; совпадение заводит cookie-сессию

### `GET /admin/static/*`
Статические файлы фронтенда администратора.
(фактов нет — служебный)

### `GET /api/about`
Версия, сборка и текущее потребление памяти процесса.
сущности: → не сущность, диагностический снимок
- данные читаются из рантайма процесса в момент запроса, не из БД

### `POST /api/admin/reload`
Запрашивает полный перезапуск приложения.
сущности: → true
- сигнал перезапуска отправляется самому себе с задержкой в пол секунды

### `DELETE /api/bounces`
Удаление отказов доставки — списком идентификаторов либо всех сразу.
сущности: ← `id`(множественный) | `all`

### `GET /api/bounces`
Список зафиксированных отказов доставки с фильтрами и пагинацией.
сущности: → не сущность, агрегат по `Bounce`

### `DELETE /api/bounces/:id`
Удаление одного отказа доставки.
сущности: ← id

### `GET /api/bounces/:id`
Один отказ доставки по идентификатору.
сущности: → `Bounce`
- ошибки: не найден — отдельная ошибка, а не пустой список

### `GET /api/campaigns`
Список кампаний с фильтрами, тегами и пагинацией.
сущности: → не сущность, агрегат по `Campaign`
- флаг отключения тела письма в ответе убирает из каждой записи поля тела и исходника визуального редактора

### `POST /api/campaigns`
Создание кампании.
сущности: ← `Campaign` + список идентификаторов списков и медиа · → `Campaign`
- новая кампания всегда создаётся в состоянии «черновик», какой бы статус ни был передан
- для кампании-приглашения («optin») без выбранных двухшаговых списков — отказ; тело письма для такой кампании собирается автоматически
- отправитель по умолчанию берётся из общих настроек, если не указан, иначе должен пройти проверку адреса
- неизвестный формат содержимого тихо заменяется на формат «форматированный текст»
- дата отложенной отправки в прошлом — отказ
- выбранный messenger должен быть реально подключён, иначе отказ
- произвольный слаг для публичной архивной страницы нормализуется в буквенно-цифровой с дефисами и должен быть уникален среди всех кампаний; при совпадении слага возвращается обычная внутренняя ошибка, а не отдельный код конфликта

### `DELETE /api/campaigns/:id`
Удаление кампании.
сущности: ← id
- комментарий в коде обещает ограничение «удалить можно только ещё не стартовавшую запланированную кампанию», но в самом запросе удаления и в бизнес-логике такого ограничения нет — удаляется кампания в любом статусе

### `GET /api/campaigns/:id`
Одна кампания по идентификатору.
сущности: → `Campaign`

### `PUT /api/campaigns/:id`
Изменение кампании.
сущности: ← `Campaign` + список идентификаторов списков и медиа · → `Campaign`
- редактировать можно только кампанию в статусе «черновик», «на паузе» или «запланирована», иначе отказ
- те же проверки полей, что при создании

### `PUT /api/campaigns/:id/archive`
Изменение настроек публичной архивной страницы кампании.
сущности: ← `archive`,`archive_template_id`,`archive_meta`,`archive_slug` · → то же тело

### `POST /api/campaigns/:id/content`
Конвертация содержимого кампании между форматами.
сущности: ← `Campaign`(body) + исходный и целевой формат · → строка
- конвертирует контент между форматами (например markdown→HTML) без сохранения

### `GET /api/campaigns/:id/preview`
Предпросмотр письма кампании как оно уйдёт адресату.
сущности: → не сущность, HTML или текст письма
- для визуального формата содержимого выбор конкретного шаблона игнорируется
- используется фиктивный идентификатор кампании, чтобы предпросмотр не засчитался как реальный просмотр или клик

### `POST /api/campaigns/:id/preview`
Предпросмотр несохранённых правок письма (тело и формат берутся из запроса, а не из БД).
сущности: → не сущность, HTML или текст письма
- для визуального формата исходник шаблона из БД в предпросмотр не подставляется

### `POST /api/campaigns/:id/preview/archive`
Предпросмотр публичной архивной страницы кампании.
сущности: → не сущность, HTML страницы архива

### `GET /api/campaigns/analytics/:type`
Аналитика по кампаниям: просмотры, клики, отказы — либо отдельно список ссылок с числом кликов, если запрошен вид «ссылки».
сущности: → не сущность, агрегат по `CampaignAnalyticsCount` либо `CampaignAnalyticsLink`
- границы периода обязательны и должны быть датой длиной 10–30 символов, иначе отказ

### `GET /api/campaigns/running/stats`
Текущая скорость и прогресс отправки у всех запущенных кампаний.
сущности: → не сущность, агрегат по `CampaignStats`
- приводится две скорости: средняя за всё время кампании и реальная скользящая скорость за последнюю минуту из воркера отправки

Удаление одного пользователя.
сущности: ← id
- та же защита «хотя бы один активный Super Admin», если удаление не затронуло ни одной строки

### `GET /api/users/:id`
Один пользователь по идентификатору.
сущности: → `User`, без пароля

### `PUT /api/users/:id`
Изменение пользователя.
сущности: ← `User` · → `User`, без пароля
- пустой пароль в запросе не очищает пароль в базе; если вход по паролю включён, а пароля в базе ещё нет — пароль требуется явно
- если изменение не затронуло ни одной строки — та же защита «хотя бы один активный Super Admin»
- после изменения перекэшируются действующие API-токены

### `GET /archive`
Публичная HTML-страница архива кампаний с постраничной навигацией.
сущности: → не сущность, агрегат архивных записей

### `GET /archive.xml`
RSS-лента архива кампаний.
сущности: → не сущность, RSS
- полный текст письма в ленте — отдельный переключатель; по умолчанию в ленте только заголовок и ссылка

### `GET /archive/:id`

- кампании не обычного («regular») типа или не найденные — страница «не найдено»
- доступна только если публичный архив включён

### `GET /archive/latest`
Самая новая заархивированная кампания.
сущности: → не сущность, HTML письма
- если архив пуст — страница «не найдено»
- доступна только если публичный архив включён

Инициирует вход через внешний OIDC-провайдер.
сущности: → редирект на провайдера
- доступен только если вход через OIDC включён администратором
- защищён от подделки запроса сверкой одноразового значения из куки и из формы

### `GET /auth/oidc`
Обратный вызов от OIDC-провайдера после аутентификации пользователя там.
сущности: → редирект на целевую страницу либо страница ошибки
- проверяется то же одноразовое значение, обменивается код на токен, валидируется токен
- если e-mail не пришёл в самих данных токена — дополнительно запрашивается у провайдера
- пользователь с таким e-mail должен уже существовать в системе — OIDC не создаёт новых пользователей сам

### `GET /campaign/:campUUID/:subUUID`
Просмотр письма кампании в браузере по постоянной ссылке — целевая страница ссылки «посмотреть в браузере» внутри письма.
сущности: → не сущность, HTML письма
- кампания и адресат определяются по UUID прямо из пути

### `GET /campaign/:campUUID/:subUUID/px.png`
Регистрация просмотра письма (трекинг-пиксель).
сущности: → изображение-пиксель
- всегда отдаёт один и тот же прозрачный пиксель независимо от того, удалось ли записать просмотр, чтобы письмо не выглядело сломанным

### `GET /link/:linkUUID/:campUUID/:subUUID`

сущности: → редирект на исходный адрес
- если индивидуальный трекинг выключен в настройках приватности — клик записывается без привязки к конкретному адресату

### `GET /public/custom.css`
Кастомный CSS публичных страниц из настроек внешнего вида.
(фактов нет — служебный)

### `GET /public/custom.js`
Кастомный JS публичных страниц из настроек внешнего вида.
(фактов нет — служебный)

### `GET /public/static/*`
Статические файлы публичных страниц.
(фактов нет — служебный)

### `GET <путь из настройки загрузки файлов>/*`
Отдача загруженных файлов напрямую с диска — регистрируется только при хранении файлов на локальной файловой системе и заданном пути отдачи.
(фактов нет — служебный)

### `GET /subscription/:campUUID/:subUUID`
Страница управления подпиской/отпиской адресата — целевая страница ссылки отписки внутри письма конкретной кампании.
сущности: → не сущность, HTML страницы
- заблокированному адресату вместо страницы управления показывается сообщение «отписан навсегда»
- управление полным набором подписок на странице показывается только если это разрешено в настройках приватности; приватные списки в такое управление не попадают

### `POST /subscription/:campUUID/:subUUID`
Обработка формы со страницы управления подпиской.
сущности: ← `name`,список UUID списков,флаг блокировки,флаг управления · → HTML с результатом
- простая отписка (без явного запроса управления или с выбранной блокировкой) не требует включённого управления подписками
- полное управление подписками требует, чтобы это было разрешено в настройках приватности; имя обязано быть в допустимой длине
- списки, не отмеченные в форме (кроме приватных), отписываются

### `POST /subscription/export/:subUUID`
Самостоятельный запрос адресата на выгрузку своих данных.
сущности: → HTML с результатом
- доступен только если самостоятельная выгрузка разрешена в настройках приватности
- данные не отдаются напрямую, а уходят письмом-вложением на e-mail самого адресата

### `GET /subscription/form`
Публичная страница формы подписки.
сущности: → не сущность, HTML формы
- доступна только если публичная подписка включена; без хотя бы одного публичного списка — страница с ошибкой «нет доступных списков»
- ключ капчи передаётся в форму только если капча включена

### `POST /subscription/form`
Обработка публичной формы подписки.
сущности: ← `name`,`email`,список UUID списков · → HTML с результатом
- скрытое поле-приманка, заполненное ботом, отбивает запрос
- при включённой капче — её ответ проверяется
- если среди выбранных списков есть двухшаговый — показывается сообщение «письмо для подтверждения отправлено» вместо «подписка подтверждена»

### `GET /subscription/optin/:subUUID`
Страница подтверждения двухшаговой подписки — целевая страница ссылки «подтвердить подписку» из письма.
сущности: → не сущность, HTML страницы
- если у адресата нет неподтверждённых двухшаговых подписок — показывается сообщение «нет подписок для подтверждения»
- при подтверждении и включённой записи IP в настройках приватности — IP-адрес подтверждения сохраняется вместе с подпиской

### `POST /subscription/optin/:subUUID`
Подтверждение подписки с этой же страницы (форма шлёт сюда).
сущности: ← список UUID списков,флаг подтверждения · → HTML с результатом
- те же правила, что у GET-варианта этой страницы

### `POST /subscription/wipe/:subUUID`
Самостоятельный запрос адресата на удаление своих данных.
сущности: → HTML с результатом
- доступен только если самостоятельное удаление разрешено в настройках приватности
- удаляет профиль адресата целиком; просмотры кампаний и клики по ссылкам в базе остаются, но перестают быть привязаны к адресату

### `POST /webhooks/bounce`
Приём отказа доставки собственным (нативным) форматом — защищённый, требует права на приём отказов.
сущности: ← сырой JSON отказа · → true
- доступен только если приём отказов через вебхуки включён администратором
- вид отказа обязан быть одним из трёх известных, иначе отказ

### `POST /webhooks/service/:service`
Приём отказов доставки от конкретного почтового провайдера (Amazon SES, SendGrid, Postmark, ForwardEmail) — без аутентификации, провайдер определяется частью пути.
сущности: ← payload конкретного провайдера · → true
- каждый провайдер включается собственным переключателем в настройках и доступен только при нём
- Amazon SES: подтверждение подписки на уведомления обрабатывается отдельно от самих уведомлений об отказах
- SendGrid проверяется подписью в заголовках запроса; за один вызов может прийти сразу несколько отказов
- приём отказа (из любого источника) считает отказы того же вида у адресата и, по достижении настроенного порога, выполняет настроенное действие — блокировку, отписку от списков или удаление профиля; если адресат уже заблокирован, новый отказ не сохраняется

## Фоновые задачи

### периодический обход активных кампаний
Забирает кампании в состояниях «идёт»/«запланирована», готовые к отправке, пачками подписывает адресатов и передаёт письма воркерам отправки.
- включается отдельным переключателем (на части инстансов рассылку можно не обрабатывать вовсе)
- размер пачки адресатов и число параллельных воркеров задаются настройками
- при превышении настроенного предела ошибок подряд — кампания автоматически переводится на паузу, администраторам уходит уведомление
- при естественном исчерпании адресатов у идущей или запланированной кампании — она переводится в «завершена», администраторам уходит уведомление
- ручная пауза или отмена останавливает приём новых адресатов немедленно, но уже поставленные в очередь письма доходят до отправки
- опциональное скользящее окно ограничения скорости отправки — при превышении лимита в окне поток засыпает до конца текущего окна

### сканирование почтового ящика отказов
Периодически проверяет настроенный POP-ящик на новые письма о недоставке и заводит из них отказы доставки тем же путём, что и вебхуки.
- включается отдельным переключателем и доступен только для почтового протокола POP
- интервал сканирования задаётся настройками и не может быть короче минуты

### обновление кэша дашборда и статистики по спискам
Пересчитывает материализованные представления, на которых строятся графики, счётчики дашборда и статистика подписчиков по спискам.
- включается отдельным переключателем в настройках; расписание — тоже из настроек (cron-выражение)
- если переключатель выключен — те же представления пересчитываются синхронно при каждом обращении к дашборду или к списку списков, а не по расписанию

### проверка обновлений
Периодически обращается к внешней службе проверки версий и выставляет признак «доступно обновление», который видит интерфейс администратора.
- включается отдельным переключателем в настройках
- первая проверка — спустя 15 минут после старта процесса, далее каждые сутки; интервал зашит в коде, настройкой не меняется

### чистка старых сессий входа
Должна периодически удалять истёкшие записи сессий входа из базы.
- не определено: периодичности в коде нет — чистка запускается один раз сразу при старте процесса и больше не повторяется, хотя сопровождающий комментарий обещает периодическое выполнение

## Владеет данными

### `Bounce`
Зафиксированный технический отказ доставки письма.
- `id`: int
- `type`: `hard` | `soft` | `complaint`
- `source`: string — источник уведомления (имя почтового провайдера, почтовый ящик, либо пусто у ручного приёма)
- `meta`: json — необработанное тело уведомления
- `created_at`: timestamp
- `email` / `subscriber_uuid` / `subscriber_id`: string?/string?/int? — хотя бы одно из первых двух обязано быть задано на входе
- `campaign_uuid`: string? — кампания, во время которой зафиксирован отказ, необязательна
- `campaign`: json? — краткие данные кампании, подставляются при отдаче

### `Campaign`
Кампания рассылки.
- `id`, `uuid`, `created_at`, `updated_at`
- `type`: `regular` | `optin`
- `name`, `subject`, `from_email`
- `body`: string — формат зависит от значения типа содержимого
- `body_source`: string? — исходник визуального редактора; пусто, если тип содержимого не визуальный
- `altbody`: string? — альтернативный текстовый вариант письма
- `send_at`: timestamp? — отложенная отправка
- `status`: `draft`|`scheduled`|`running`|`paused`|`finished`|`cancelled`
- `content_type`: `richtext`|`html`|`plain`|`visual`|`markdown`
- `tags`: string[]
- `headers`: произвольные дополнительные заголовки письма
- `template_id`: int?
- `messenger`: string — имя подключённого отправителя
- `archive`,`archive_slug`,`archive_template_id`,`archive_meta` — настройки публичной архивной страницы; `archive_slug` уникален среди всех кампаний
- `views`,`clicks`,`bounces`,`to_send`,`sent`,`started_at` — счётчики хода отправки
— `lists`,`media` отдаются как исторический снимок {идентификатор,имя} на момент последнего обращения, а не живым соединением с текущими списками/медиа: название списка остаётся видимым в кампании даже после удаления самого списка

### `List`
Список рассылки.
- `id`,`uuid`,`created_at`,`updated_at`
- `name`,`description`,`tags`
- `type`: `private`|`public`
- `optin`: `single`|`double`
- `subscriber_count`: int — сумма по всем статусам подписки
- `subscriber_statuses`: словарь статус→число (не подтверждена/подтверждена/отписан)

### `ListRole`
Именованный набор прав на чтение/управление конкретными списками.
- `id`,`created_at`,`updated_at`,`name`
- `lists`: [{идентификатор,имя,права}] — права назначаются на каждый список отдельно

### `Media`
Загруженный файл (изображение или документ для использования в кампаниях).
- `id`,`uuid`,`created_at`,`filename`,`content_type`
- `thumb`: string — имя файла миниатюры, пусто для файлов без миниатюры
- `provider`: `filesystem`|`s3` — фиксируется в момент загрузки
- `meta`: json — ширина и высота, только для растровых изображений

### `Role`
Именованный набор гранулярных прав из общего каталога.
- `id`,`created_at`,`updated_at`,`name`
- `permissions`: string[]
— один конкретный идентификатор зарезервирован под встроенную роль Super Admin и недоступен для изменения или удаления через API

### `Settings`
Единая конфигурация приложения — одна запись в своей таблице на каждый ключ настройки, но отдаётся и принимается одним объединённым объектом.
- поля сгруппированы по смыслу: общие настройки сайта и отправки; настройки приватности (трекинг, выгрузка и удаление данных, домен-листы); настройки безопасности (капча, OIDC); настройки хранения файлов (локально или в облаке); список блоков SMTP; список почтовых ящиков для отказов; список дополнительных messenger'ов
— пароли и секреты всех видов при отдаче клиенту заменяются символом-маской, настоящее значение наружу не отдаётся никогда

### `Subscriber`
Адресат рассылки.
- `id`,`uuid`,`created_at`,`updated_at`
- `email`: string — уникален без учёта регистра
- `name`
- `attribs`: json — произвольные пользовательские атрибуты
- `status`: `enabled`|`disabled`|`blocklisted`
— `lists` в ответе вычисляется объединением с подписками/списками на чтение, собственного поля-колонки с таким именем нет

### `Subscription`
Подписка одного адресата на один список (составной ключ — пара адресат+список); несёт в себе также все поля самого списка.
- `subscription_status`: `unconfirmed`|`confirmed`|`unsubscribed`
- `subscription_created_at`,`subscription_updated_at`
- `meta`: json — например, IP-адрес подтверждения, если его запись включена

### `Template`
Шаблон письма.
- `id`,`created_at`,`updated_at`,`name`
- `type`: `campaign`|`campaign_visual`|`tx`
- `subject`: string — значим только у транзакционного типа
- `body`,`body_source`
- `is_default`: bool — ровно у одного шаблона во всей таблице может быть истинным одновременно

### `User`
Администратор или API-клиент.
- `id`,`created_at`,`updated_at`,`username`,`name`
- `type`: `user`|`api`
- `status`: `enabled`|`disabled`
- `email`: string? — у API-клиента всегда стирается в ответе
- `password`: string? — хранится как хэш; для API-клиента это открытый токен, видимый в ответе только в момент создания/обновления
- `password_login`: bool
- `avatar`,`loggedin_at`
- `user_role_id`,`list_role_id` — ссылки на роль и на роль по спискам

| пользовательская роль (назначается через каталог гранулярных прав) | то, что разрешено выданным подмножеством прав: доступ к адресатам, спискам, кампаниям, отказам, медиа, шаблонам, пользователям, ролям, настройкам, обслуживанию, отправке транзакционных писем, приёму вебхуков отказов — в любом сочетании |
| роль по спискам (назначается не более одной на пользователя) | чтение и/или управление только перечисленными в роли списками рассылки |
| API-пользователь | те же права, что у обычного пользователя с той же пользовательской ролью, но входит токеном в заголовке запроса, а не паролем |
| без входа | подписаться на публичный список и подтвердить подписку по ссылке; управлять своими подписками или отписаться по ссылке в письме; скачать или удалить свои данные, если это разрешено в настройках приватности; смотреть публичный архив кампаний и публичные списки, если это включено; переходить по трекинг-ссылкам и пикселю просмотра; входить через OIDC; видеть проверку живости — всё остальное под закрытым путём скрыто, включая содержимое приватных списков, данные других адресатов и письма кампаний не обычного типа |
