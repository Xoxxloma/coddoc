# plan.sh → plan.py: допустимые расхождения (составлено до сверки, 2026-11-24)

Единственное намеренное изменение порта — регэксп разведчика. В bash он шёл через `awkre` (`\s` → `[[:space:]]`,
`\d` → `[0-9]`, `\w` → `[[:alnum:]_]`, глобально, без учёта `[…]`) и дальше:
- условие файла (`в файлах с <регэксп>`) — `ere()` (ещё `\b` → `([^[:alnum:]_]|^|$)`) и `grep -E -f` / `grep -l -E -f`;
- строка спецификации (`## <класс> :: <регэксп> :: <маска> :: <файл спеки> :: ключ`) — `awkre()` и gawk `ln ~ re`,
  `sub(re, "", nm)` в `emitspec` (только когда названная спека тяжелее K).

В Python регэксп компилирует `re` с `re.ASCII` и ищет построчно (файл — `bom=False`); не скомпилировался — как `sbad`
у bash («условие файла не разобрано», строка считается вся). Поведение bash проверено пробой на этой машине
(GNU grep 3.0, GNU Awk 5.0.0, `LC_ALL=C`).

## Конструкции, которые awkre/ere переводил с потерей

| Конструкция | Что было в bash | Python | Сторона расхождения |
|---|---|---|---|
| `\w`, `\s`, `\d` внутри `[…]`: `[\w, ]`, `[\d]`, `[\s]`, `[^\w]` | подстановка `[[:alnum:]_]` закрывает скобку раньше: `[\w, ]*` → «один из `[`, буква-цифра, `_`», за ним буквально `, ` и `]*`; почти никогда не совпадает | класс как задуман | условие: у py больше файлов в условии |
| `(?:…)`, `(?i)`, `(?=…)`, `(?!…)`, `(?<=…)`, `(?P<n>…)` | grep разбирает как группу с буквальным `?…` — совпадения нет | работает | у py больше файлов в условии |
| `\b` рядом с не-словом в регэкспе (`foo\b\(`) | `\b` → `([^[:alnum:]_]\|^\|$)` съедает символ — `foo(` не совпадает | граница нулевой ширины | у py больше |
| `\b` в строке спецификации | gawk: `\b` — backspace, не совпадает никогда → `m = 0` → спека одной частью | граница слова → спека режется по операциям | у py куски спеки вместо одной части |
| `\D`, `\t`, `\xNN`, `\n` в условии | grep: буква без `\` (`\t` → `t`) | символ / класс | любая |
| `\p{…}`, `\z`… | grep: буква без `\` | `re.error` → «условие файла не разобрано», строка вся | у py больше + лишняя строка |
| принятое grep, отвергнутое `re`: ведущий `*`/`+`/`?`, `x**`, одинокая `)` | разбирает, фильтрует | «не разобрано», строка вся | у py больше + лишняя строка |
| ленивые `.*?`, `+?` | условие: на «есть ли совпадение» не влияет; спека: `sub` жадный | спека: `sub` ленивый | только имена operationId в задании куска спеки |
| альтернация в `sub(re, …)` строки спеки | самое длинное совпадение | первая ветка слева | имена operationId в задании куска |
| неразбираемый регэксп строки спеки (`(`) | gawk fatal, код 2, вывод оборван | `m = 0` → спека одной частью, код 0 | вывод и код выхода |
| `.{n}`, `[^x]{n}`, `\W\W` по не-ASCII тексту | `LC_ALL=C`: символ кириллицы — 2 байта | символ — 1 | любая |
| файл с байтом NUL | grep может резать строки по NUL | режет только по `\n` | `^`/`$` в условии |

Без потери (bash = py): `\s`, `\d`, `\w` вне скобок (ASCII = классы локали C); `\b` в конце после слова
(`…Api\b`); группы с повтором `(\w+,\s*)*`; `\S`, `\W`, `\B` (расширения GNU у grep); ленивые кванторы в условии.

## Строки разведчика из корпуса (`runs/`, `fixtures/`)

Счёт вправе разойтись только у этой строки:

- `контракт :: ^\s+@Override\b :: *.java :: в файлах с implements\s+[\w, ]*\w+Api\b :: ключ` —
  `runs/2026-10-25-v45-real3-apollo/sandbox/mono-01` и `runs/2026-10-25-v45-fix2-apollo/sandbox/mono-02`. В bash условие
  почти не совпадало: «итог по классам: контракт 138» (real3) / 139 (fix2), «вне условия файла: контракт 458 в файлах 102».
  Ожидание у py: итог контракта больше, «вне условия файла» меньше на столько же (сумма итог + вне условия та же), и
  вслед за итогом — строки `файл`/`часть`/`итог` плана, части и задания.

Без расхождения (конструкции без потери):
- условия: `:\s*\w+Api\b` (бриф разведчика, SM-PLAN-TYPES «з»), `exposes\s*:` (бриф, SM-PLAN-TYPES «к»),
  `implements \w+ManagementApi\b`, `implements\s+\w+Api\b`, `implements\s+(\w+,\s*)*\w+Api\b`;
  `(PetApi` (SM-PLAN-TYPES «з2») — не разбирают ни grep, ни `re`, «не разобрано» у обоих;
- строки спецификации: `^\s+operationId:` (все прогоны, SM-PLAN-TYPES, SM-SPLIT-SCRIPTS `44-server-spec`); строка
  fix2-listmonk mono-02 с путём на месте регэкспа — `emitspec` её не достигает (маска `*.yaml` файлом счёта не бывает).

**Корпус самотестов (SM-PLAN-TYPES, SM-SPLIT-SCRIPTS) конструкций с потерей не содержит: по регэкспу разведчика
расхождений plan-* в сверке быть не должно.** Машинный список для `compare.py --allow` — `allow-plan.tsv` рядом.

## Не от регэкспа разведчика (известны до сверки, по брифу)

- `for (f in tcfg)`, `for (f in specre)` (plan.sh:272, 273, 340), `for (r in sbad)` (535): порядок gawk не задан, в py —
  порядок вставки. При двух и больше конфигах топиков / названных спеках / неразобранных условиях — тот же набор
  строк `топик`/`операция`/«не разобрано»/хвостов заданий в другом порядке; `tfile` у топика, названного в двух конфигах.
- Обход дерева корней: bash — `find` (порядок каталога), py — по имени в байтах; влияет только на порядок
  «СПЕКА НЕ РАЗМЕЧЕНА» и строк `операция` при двух и больше неназванных спеках.
- Сообщения: `keys.awk` → `keys.py` (путь — абсолютный, как в promote.py); `${N:?…}` — текст stderr
  (`plan.py: 1: counts.txt`); «не прочитано N: <путь>» — только если файл дерева не открылся.
