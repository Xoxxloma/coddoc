# harvest-ledger — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Назначение

Агроном каждый день вносит полевые замеры по культурам на своих участках, главный агроном подтверждает неделю или возвращает её с комментарием, методист ведёт справочник культур, — и по подтверждённому собираются сводки по регионам и хозяйствам. Сервис ведёт заполнение и отправку недели, подтверждение или возврат, открытие уже закрытой недели для правки по запросу, назначение шаблонов замеров агрономам и передачу шаблонов другому главному агроному, загрузку показаний метеопостов хозяйств и выгрузку сводки в Excel. Главные объекты — замеры по дням и участкам, шаблоны замеров с набором культур, справочник культур и их групп, участки, запросы на открытие недели и на передачу шаблонов.

## Бизнес-правила

### `MeasurementEntry` — замер агронома за день по участку
- черновик (`DRAFT`) — агроном сохраняет день; сохранение возвращает в черновик любой день, в том числе подтверждённый; прошедшая неделя сохраняется только при открытом окне правки; черновик, который не меняли 90 дней, удаляется
- на подтверждении (`PENDING`) — агроном отправляет неделю, либо в понедельник утром черновики прошлой недели отправляются сами; в списке такой день не предлагается к правке, но сохранение его не запрещает
- подтверждён (`APPROVED`) — главный агроном; попадает в сводки; в списке не предлагается к правке
- возвращён (`RETURNED`) — главный агроном вместо подтверждения, с обязательным комментарием; агроном правит и отправляет заново

### `WeekWindow` — запрос агронома на открытие прошедшей недели для правки
- запрошено (`REQUESTED`) — агроном; на неделю один запрос навсегда; главный агроном получает письмо; пока решения нет, агроном может отозвать запрос — запись исчезает
- открыто (`OPEN`) — главный агроном одобрил; неделю можно править 72 часа
- отклонено (`REJECTED`) — главный агроном отказал; комментарий к отказу не сохраняется
- истекло (`EXPIRED`) — само, через 72 часа после открытия; новый запрос на ту же неделю подать нельзя

### сообщение «замеры сохранены»
- событие аудита в топик `ledger.audit.v1` при каждом сохранении замеров агрономом; получатель — аудит; несёт число сохранённых дней; при отправке недели, решении и удалении дня не уходит

### сообщение «запрос на открытие недели»
- при запросе окна правки; получает главный агроном агронома на e-mail, тема «Запрос на открытие недели»; в письме — ФИО агронома, неделя и причина

### сообщение «неделя передана на подтверждение»
- в понедельник утром, если у агронома остались неотправленные черновики прошлой недели; получает главный агроном, одно письмо на агронома, тема «Замеры переданы на подтверждение»; при ручной отправке недели не уходит

### сообщение «шаблон изменён»
- событие аудита в топик `ledger.audit.v1` при создании, изменении и удалении шаблона; получатель — аудит; назначение и снятие агрономов события не даёт

## Публичный контракт

### `GET /api/v1/ledger/crops`
Справочник культур.
сущности: → `Crop`, поле `group` отдаётся как `groupId`
доступ: без проверки роли; нужен вход по заголовку номера сотрудника
- `groupId: long?` — `null`, если у культуры нет группы

### `GET /api/v1/ledger/entries`
Свои замеры за интервал дат.
сущности: ← `from`, `to` · → не сущность, `EntryDay`, собранный из `MeasurementEntry` и `EntryValue`
доступ: `AGRONOMIST`; только свои замеры
- `date: date`, `plotId: long?` — `null` у замера без участка
- `status: string` — `DRAFT`, `PENDING`, `APPROVED` или `RETURNED`
- `editable: boolean` — истинно только для недели не раньше текущей и для статусов `DRAFT` и `RETURNED`; открытое окно правки прошедшей недели в нём не учитывается
- `values: list` — пары `cropId: long`, `value: decimal`
- дни интервала без замеров в ответ не попадают

### `POST /api/v1/ledger/entries`
Сохранение замеров за дни одной недели.
сущности: ← не сущность, список `EntrySave` (`date`, `plotId`, `values`) · → пустой ответ
доступ: `AGRONOMIST`; только свои замеры
меняет: `MeasurementEntry.status` → `DRAFT`
шлёт: `ledger.audit.v1`
- любой сохранённый день становится черновиком, в том числе подтверждённый; решение и комментарий главного агронома при этом не сбрасываются
- значения дня заменяются целиком
- ошибки: `409` — дни из разных недель; `423` — неделя прошла и открытого окна правки нет; `403` — участок чужой или в архиве; `404` — участка нет

### `DELETE /api/v1/ledger/entries/day/{date}`
Удаление своего черновика за день.
сущности: ← `date` · → пустой ответ
доступ: `AGRONOMIST`; только свои замеры
- удаляются все замеры дня по всем участкам
- ошибки: `409` — хотя бы один замер дня не в черновике

### `POST /api/v1/ledger/entries/submit`
Отправка недели главному агроному.
сущности: ← `weekStart` · → пустой ответ
доступ: `AGRONOMIST`; только свои замеры
меняет: `MeasurementEntry.status` `DRAFT` → `PENDING`
меняет: `MeasurementEntry.status` `RETURNED` → `PENDING`
- письмо главному агроному при ручной отправке не уходит; уходит только при автоотправке в понедельник

### `GET /api/v1/ledger/entries/week-status`
Состояние своей недели.
сущности: ← `weekStart` · → не сущность, агрегат по `MeasurementEntry` и `WeekWindow`
доступ: `AGRONOMIST`; только свои замеры
- `draft: int`, `pending: int`, `approved: int`, `returned: int` — число замеров недели в каждом статусе
- `windowOpen: boolean` — по этой неделе есть запрос в статусе `OPEN`

### `GET /api/v1/ledger/entries/{agronomist}`
Замеры агронома за интервал дат.
сущности: ← `agronomist`, `from`, `to` · → не сущность, `EntryDay` из `MeasurementEntry` и `EntryValue`
доступ: `HEAD_AGRONOMIST`, `METHODIST`; принадлежность агронома главному агроному не проверяется
- поля ответа те же, что у `GET /api/v1/ledger/entries`: `date`, `plotId`, `status`, `editable`, `values`
- признак `editable` считается так же, как для собственных замеров

### `POST /api/v1/ledger/entries/{agronomist}/decision`
Подтверждение недели агронома или возврат с комментарием.
сущности: ← `agronomist`, не сущность `Decision` (`approve: boolean`, `comment: string?`) · → пустой ответ
доступ: `HEAD_AGRONOMIST`; принадлежность агронома не проверяется
меняет: `MeasurementEntry.status` `PENDING` → `APPROVED`
меняет: `MeasurementEntry.status` `PENDING` → `RETURNED`
- решение касается только замеров на подтверждении за последний год по сегодняшнюю дату; в замер записываются кто решил и комментарий
- комментарий при подтверждении тоже сохраняется, если передан
- ошибки: `422` — возврат без комментария

### `GET /api/v1/ledger/me`
Кто я.
сущности: → не сущность, ответ `staff-profile` и роли из заголовка запроса
доступ: без проверки роли; нужен вход по заголовку номера сотрудника
- `number: string`, `fullName: string` — ФИО берётся у `staff-profile`
- `roles: list` — роли из заголовка запроса без приставки `ROLE_`

### `GET /api/v1/ledger/plots`
Свои участки.
сущности: → `Plot`, без `ownerNumber` и `archived`; только не архивные
доступ: `AGRONOMIST`; только свои участки
- `areaHa: decimal?` — `null`, если площадь не указана
- порядок по названию

### `DELETE /api/v1/ledger/plots/{id}`
Убрать участок в архив.
сущности: ← `id` участка · → пустой ответ
доступ: `AGRONOMIST`; только свой участок
- участок не удаляется: на него ссылаются замеры; в архиве он пропадает из списка и новые замеры на него не принимаются

### `GET /api/v1/ledger/windows`
Свои запросы на открытие недель.
сущности: → `WeekWindow`, проекция `Window` (`id`, `agronomist`, `weekStart`, `reason`, `status`)
доступ: `AGRONOMIST`; только свои запросы
- порядок: недели от новых к старым
- `reason: string?` — `null`, если причина не указана

### `POST /api/v1/ledger/windows`
Запрос на открытие закрытой недели для правки.
сущности: ← не сущность, `WindowRequest` (`weekStart`, `reason`) · → пустой ответ
доступ: `AGRONOMIST`
меняет: `WeekWindow.status` → `REQUESTED`
шлёт: `window-requested`
- ошибки: `409` — запрос на эту неделю уже есть в любом статусе, включая отклонённый и истёкший

### `GET /api/v1/ledger/windows/pending`
Запросы на открытие недель, ждущие решения.
сущности: → `WeekWindow`, проекция `Window` (`id`, `agronomist`, `weekStart`, `reason`, `status`)
доступ: `HEAD_AGRONOMIST`; запросы всех агрономов, не только подчинённых
- только статус `REQUESTED`; недели от старых к новым

### `DELETE /api/v1/ledger/windows/{id}`
Отзыв своего запроса на открытие недели.
сущности: ← `id` запроса · → пустой ответ
доступ: `AGRONOMIST`; только свой запрос
- запись удаляется
- ошибки: `403` — запрос чужой; `409` — по запросу уже есть решение

### `POST /api/v1/ledger/windows/{id}/decision`
Решение по запросу на открытие недели.
сущности: ← `id` запроса, не сущность `Decision` (`approve`, `comment`) · → пустой ответ
доступ: `HEAD_AGRONOMIST`; принадлежность агронома не проверяется
меняет: `WeekWindow.status` → `OPEN`
меняет: `WeekWindow.status` → `REJECTED`
- текущий статус запроса не проверяется: решить можно и уже решённый; при открытии фиксируется время открытия
- комментарий не сохраняется
- открытое окно закрывается само через 72 часа задачей `WindowsExpiryJob`

## События

### публикует `ledger.audit.v1`
Журнал действий: сохранение замеров и изменения шаблонов.
- тело: `Map` без класса, поля зависят от вида
- `type`: `string` — `ENTRIES_SAVED`, `TEMPLATE_CREATED`, `TEMPLATE_UPDATED` или `TEMPLATE_DELETED`
- `actor`: `string` — номер сотрудника, выполнившего действие
- `at`: `string` — время в ISO
- `agronomist`: `string` — только у `ENTRIES_SAVED`, совпадает с `actor`
- `days`: `int` — только у `ENTRIES_SAVED`, число сохранённых дней
- `templateId`: `long` — только у видов `TEMPLATE_*`
- ключ: `actor` — порядок гарантирован по сотруднику, не по шаблону или неделе
- когда: `POST /api/v1/ledger/entries`, `POST /api/v1/ledger/templates`, `PUT /api/v1/ledger/templates/{id}`, `DELETE /api/v1/ledger/templates/{id}`
- гарантия: как у транспорта `AuditPublisher`
- не шлётся: на назначение и снятие агрономов с шаблона, на решения по замерам, окнам и передаче, на отправку недели, на загрузку погоды

### транспорт `AuditPublisher`
Общая обвязка отправки событий аудита.
- гарантия: отправка синхронная, внутри транзакции запроса и до её коммита; ждётся подтверждение брокера от всех реплик; при сбое брокера то же событие уходит по HTTP в `audit-hub`; сбой и там возвращается вызывающему и откатывает запись; событие может уйти, а запись откатиться

## Фоновые задачи

### `StaleDraftsPurgeJob`
Чистка забытых черновиков замеров.
- расписание `0 0 3 * * *`
- удаляет черновики, которые не меняли дольше 90 дней (срок из настройки `ledger.drafts.retention-days`); возвращённые, отправленные и подтверждённые не трогает
- удаляются сразу все такие, пачек нет; пропущенный прогон не догоняется, следующий берёт всё накопившееся
- не более одного экземпляра за раз

### `UnsubmittedWeeksJob`
Автоотправка недели, которую агроном не отправил.
меняет: `MeasurementEntry.status` `DRAFT` → `PENDING`
шлёт: `week-escalated`
- расписание `0 0 6 * * MON`
- берёт прошлую неделю: все черновики всех агрономов одним проходом; возвращённые дни не затрагивает
- после перевода шлёт главному агроному агронома одно письмо на каждого агронома
- пропущенный понедельник не догоняется: следующий возьмёт уже другую прошлую неделю
- сбой отправки письма или запроса к `staff-profile` откатывает весь прогон
- блокировка между экземплярами не берётся, в отличие от остальных задач

### `WindowsExpiryJob`
Закрывает окна правки прошедших недель.
меняет: `WeekWindow.status` `OPEN` → `EXPIRED`
- расписание `0 0 * * * *`
- берёт окна, открытые дольше 72 часов (срок из настройки `ledger.windows.open-hours`)
- повторный запрос на ту же неделю после истечения подать нельзя
- не более одного экземпляра за раз

## Владеет данными

### `Crop`
Культура справочника.
- `id`: `long`
- `code`: `string` — уникален, не меняется
- `name`: `string`
- `group`: `CropGroup?` — `null`, если у культуры нет группы
— в сводке столбцы строятся по `code`; удаление культуры каскадом убирает её значения в замерах и связи с шаблонами

### `CropGroup`
Группа культур.
- `id`: `long`
- `name`: `string` — уникально
- `sortOrder`: `int` — по умолчанию 100
— порядок групп в отчётах задаётся `sortOrder`

### `EntryValue`
Значение замера по одной культуре.
- `id`: `long`
- `entry`: `MeasurementEntry`
- `crop`: `Crop`
- `value`: `decimal` — до трёх знаков после запятой
— удаляется каскадом вместе с замером

### `MeasurementEntry`
Замер агронома за день по участку.
- `id`: `long`
- `agronomistNumber`: `string`
- `entryDate`: `date`
- `plotId`: `long?` — `null` у замера без участка
- `status`: `DRAFT` \| `PENDING` \| `APPROVED` \| `RETURNED`
- `decidedBy`: `string?` — главный агроном, принявший решение
- `decisionComment`: `string?` — комментарий возврата; остаётся после повторного сохранения дня
- `updatedAt`: `datetime` — по нему чистятся забытые черновики
- `values`: список `EntryValue`
— уникальность (агроном, дата, участок) держит БД
— `status` в `PENDING` и `RETURNED` переводят главный агроном, отправка недели и задача `UnsubmittedWeeksJob`

### `Plot`
Участок агронома.
- `id`: `long`
- `ownerNumber`: `string`
- `farmId`: `long` — хозяйство из земельного реестра
- `name`: `string`
- `areaHa`: `decimal?` — `null`, если площадь не указана
- `archived`: `boolean`
— архивный участок не принимает замеры и не показывается в списке; замеры на него остаются

### `WeekWindow`
Запрос агронома на открытие прошедшей недели.
- `id`: `long`
- `agronomistNumber`: `string`
- `weekStart`: `date`
- `reason`: `string?`
- `status`: `REQUESTED` \| `OPEN` \| `REJECTED` \| `EXPIRED`
- `openedAt`: `datetime?` — `null`, пока окно не открыто
— уникальность (агроном, неделя) держит БД
— `EXPIRED` ставит задача `WindowsExpiryJob`

## Роли и доступ
| Роль | Что может |
|---|---|
| `AGRONOMIST` | вносить, удалять и отправлять свои замеры, запрашивать и отзывать окно правки, вести свои участки |
| `HEAD_AGRONOMIST` | подтверждать и возвращать недели агрономов, решать по окнам правки, вести шаблоны и назначения, просить передачу шаблонов, смотреть сводки и недельную сводку; принадлежность агронома не проверяется |
| `METHODIST` | вести справочник культур и групп, решать по передаче шаблонов, смотреть сводки, замеры агрономов и все шаблоны |
| автор шаблона | менять шаблон и его назначения; удалять и смотреть шаблон может любой главный агроном |
| владелец участка | менять участок и убирать в архив; замеры принимаются только на свои неархивные участки |
| без входа | нет: запрос без заголовка номера сотрудника получает `401`; роли приходят заголовком и в этом сервисе не выдаются |
| вход | номер сотрудника и его роли приходят готовыми в заголовках `X-Employee-Number` и `X-Employee-Roles` (роли — через запятую); фильтр сервиса кладёт их в контекст безопасности без проверки у соседа; без `X-Employee-Number` — `401` |
