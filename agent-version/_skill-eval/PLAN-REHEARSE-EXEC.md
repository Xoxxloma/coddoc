пункт = коммит, коммит — по слову пользователя.

Основа: разговор 2026-11-04. От `spec-readiness` хотели острых вопросов и боролись с мелочью. Мелочь производила
механика полноты: семь осей прикладывались к каждому объекту, получались десятки вопросов, их склеивали, сверка
вычёркивала отвеченные. На проде 02.11 по делу было 5 вопросов из 9. У `rehearse` роль сама выбирает 5–7 вопросов с
опорой-цитатой, и вопросы выходят точнее.

## 0. Что решено

| Вопрос | Решение |
|---|---|
| Форма | Четвёртая роль `rehearse`: `reference/role-executor.md`. Отдельного скилла нет, `spec-readiness` удаляется (С6) |
| Имя роли | «Исполнитель» — тот, кому отдадут спеку строить. Не «техлид»: техлида отвергли как общие вопросы про риски |
| Синонимы в Шаге 0 | «разработчик», «бэкенд», «фронтенд», «готовность к разработке», «достаточно ли, чтобы писать код» → исполнитель |
| Три роли `spec-readiness` | Сводятся в одну карточку. Стык бэка и фронта — вопрос с двумя опорами (поле на экране, которого нет в ответе; код ошибки без состояния экрана) |
| Делёж с архитектором | Архитектор — как изменение ложится на систему: где данные, кто кого вызывает, соседи. Исполнитель — что придётся решать самому, когда сядешь писать. Пересечение на отказе соседа допустимо: на проверке спеки в оркестраторе идёт только исполнитель |
| О чём спрашивает исполнитель | Повтор запроса и двойное нажатие; два вызова на один объект; роль на экране — проверяет ли её сервер; запрещённые переходы статуса; порядок нашей записи, вызова соседа и уведомления, что остаётся при откате; что показано, пока идёт запрос, при пустом ответе и при ошибке; новое обязательное поле — что со строками, которые уже лежат |
| О чём не спрашивает | Ценность и тексты (заказчик), ПДн и журналы (безопасник), почему решение здесь (архитектор), контракт чужого сервиса (`brief.md`, правило 2), то, что документ объявил неизменным (границы правки, обратная совместимость: прод 02.11, 4 из 9), каким приёмом реализовать |
| Число вопросов | `brief.md`: «от пяти до семи» → «не больше семи». Спросить нечего — блок пуст. Обязательный минимум и есть источник мелочи на хорошей спеке |
| Пустой блок | `SKILL.md`: блок `## ВОПРОСЫ` пуст → «Вопросов у <роли> нет: на всё, что она спросила бы, документ отвечает. Это не оценка решения.» Стоп. Отличается от «опоры не прошли сверку» |
| Контекст | Документ сверху и `context/`. Карточки `services/` — нет: SR-YELLOW показала перенос литералов чужого API (раздел 3), запрет `spec-readiness` сохранён |
| Рекомендация роли | Без изменений: БТ → заказчик, спека → архитектор. Исполнителя оркестратор передаёт явно |
| Выход | Как у `rehearse`: вопросы по одному, итог «Решить до встречи / Вписать в документ». Счётной строки нет |
| Примеры в карточке | Не из SR-* и REH-SHT, без чисел стенда (утечка стенда в скилл) |

## 2. Стенд (С3)

Модель `claude-sonnet-5`. Фикстуры — те же, что у `spec-readiness`; `SR-VERIFY` не переносится: она мерит склейку и
сверку, которых больше нет.

| Проба | Фикстура | Что мерит |
|---|---|---|
| `reh-ex-gap` | SR-GAP (PSS-2210) | сколько из шести подсаженных дыр попало в вопросы |
| `reh-ex-clean` | SR-CLEAN (OFC-880) | вопросы, на которые спека отвечает прямо; пустой блок — законный исход |
| `reh-ex-yellow` | SR-YELLOW (SUP-702) | литералы-приманки из `services/itsm.md`; требования контракта у INT-3/INT-4 |
| `reh-ex-blue-yes`, `-idk`, `-cr` | SR-BLUE | вопросы про изменение есть; про прежнее поведение ручек — не больше одного |

- Двойник отвечает на всё «Не знаю, уточню.»: мерим вопросы, а разбор ответов уже измерен на REH-SHT. Шум двойника
  (6 красных из 20 в серии) сюда не попадёт.
- База — `spec-readiness` 1.2.0 на тех же шести пробах, той же моделью (на sonnet-5 её ещё не гоняли).
- Оценщик `grade-reh-ex.mjs`: признаки подсаженных дыр и «прежнего» — из `grade-sr.mjs` и `grade-sr-blue.mjs`, одни
  и те же для базы и новой формы. Проверяется на известном результате: прогоне базы. Грейдить после завершения всех
  прогонов.
- Регресс: `reh-arch|sec|cust|stop` на REH-SHT — `brief.md` меняется для всех ролей.
- Глазами по каждому вопросу базы и новой формы: острый / мелочь / ответ в спеке есть.

**Зелёный** (записано до прогонов): субагент запущен; ведущий документ целиком не читал; записей нет; показанные
опоры есть в файле (±2 строки); один вопрос на сообщение; итог есть. По фикстурам:
- SR-GAP: подсаженных дыр не меньше, чем у базы;
- SR-CLEAN: вопросов с прямым ответом в спеке не больше одного;
- SR-YELLOW: приманок 0, требований контракта 0;
- SR-BLUE: прежнего не больше одного;
- REH-SHT: 4 из 4 по `grade-reh.mjs`.

Главный итог — доля мелочи и вопросов с ответом в спеке у новой формы против базы.

**Цена.** Пилот — по одному прогону: новая форма 6 × ≈ $0.85 (замер пилота `rehearse` с двойником) ≈ $5; регресс
REH-SHT ≈ $3.2 (пилот 2); база 6 × $1–3 (на sonnet-5 замера нет) ≈ $6–18. Всего ≈ $15–27. Серию — после пилота, по
замеру `total_cost_usd`.
