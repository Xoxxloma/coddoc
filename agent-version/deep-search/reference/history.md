# Откуда взялось поведение

Этот файл читает ведущий `deep-search` на Шаге 6. Что система делает сейчас, уже известно. Теперь по истории git
покажи, откуда это поведение взялось и какой задачей пришло. Причину не обещаешь: она часто нигде не записана.

## Три правила важнее всего остального

1. **Причина — только дословная цитата** из комментария в коде, текста коммита или документа задачи. Цитаты нет —
   «не записана». Своих объяснений нет: ни «вероятно», ни вывода из названия, ни пересказа цели задачи.
2. **Основа ответа — история git, а не документ.** Код бывает старше спеки. Документа нет — ответ всё равно есть.
3. **Секреты не копируешь:** в старых правках бывают пароли и токены, значение в ответ не идёт.

## 1. Строки

Вход — ссылки `[в коде]`, прошедшие сверку. Выбери до трёх, которые прямо дают спрошенное поведение. Ни одной →
вместо блока истории строка «Кода не нашёл, идти в историю не с чем». Дальше ничего не делаешь.

Из ссылки `<репа>/<путь>:<строка>` или `:<начало>-<конец>` возьми:

- `<репа>` — `<Родитель>/<первая часть ссылки>`, `<Родитель>` как на Шаге 3;
- `<путь>` — остаток ссылки, косая черта прямая;
- `<a>` и `<b>` — начало и конец; у одной строки они равны.

## 2. История строки

Один раз на репу:

```
git -C "<репа>" rev-parse --is-shallow-repository
```

`true` → клон обрезан, история в нём неполная и может назвать чужой коммит. Строки этой репы пропусти, вместо их блока
строка: «<репа>: клон обрезан, историю не читал. Полная история: `git fetch --unshallow`». Эту команду запускает аналитик,
ты её не запускаешь.

На каждую строку сначала проверь файл:

```
git -C "<репа>" status --porcelain -- "<путь>"
```

Вывод не пуст → в файле незакоммиченные правки, номера строк разошлись с историей, и git покажет чужую строку без
ошибки. В ответе: «<ссылка>: историю не прочитал, в файле незакоммиченные правки». Переходи к следующей строке.

Вывод пуст → история:

```
git -C "<репа>" log -L "<a>,<b>:<путь>" --format="COMMIT %h %ad %an %s%n%b" --date=short -n 5
```

В выводе до пяти правок этой строки, новые сверху: `COMMIT`, текст коммита, затем что было (`-`) и что стало (`+`).

| Ошибка любой команды | Что делаешь |
|---|---|
| `not a git repository` | Вместо блока этой репы строка «<репа>: не репозиторий git» |
| другая ошибка про файл или строку | В ответе: «<ссылка>: историю не прочитал: <текст ошибки>». Переходи к следующей строке |
| команда не найдена | Вместо блока истории строка «В этой среде нет git, историю прочитать нечем». Дальше ничего не делаешь |

## 3. Откуда пошло

Иди от новых коммитов к старым. Первая правка, где поменялся смысл строки, — **источник**. Форматирование,
переименование и перенос без смены значения пропускай. Все пять такие → источник самый старый из них.

- Было до этого: строки `-` этой правки. Их нет → «строка появилась в этом коммите».
- Открой код вокруг: `Read`, `offset` — `<a>` минус 5, но не меньше 1, `limit` — `<b>` минус `<a>` плюс 11.
  Комментарий, объясняющий поведение, — цитата для причины.
- Текст коммита объясняет поведение — тоже цитата. Тема вида «увеличил таймаут» говорит, что сделали, а не почему:
  это не причина.

## 4. Что поменяли вместе

```
git -C "<репа>" show --stat=300 --stat-graph-width=1 --stat-count=15 --format= <хеш>
```

В ответ — до трёх файлов, которые относятся к вопросу; не относится ни один — `—`. Тест, если он есть среди них,
открой (не больше двух файлов) и возьми имя теста дословно:

```
git -C "<репа>" show --format= <хеш> -- "<файл>"
```

## 5. Номер задачи

Номер — ключ задачи: заглавные латинские буквы и цифры, дефис, цифры: `ABC-123`. Имя стандарта, кодировки или алгоритма
(`UTF-8`, `ISO-8601`, `SHA-256`) номером не считается. Ищи только в тексте коммита-источника. Нет → «номера нет»,
«документа нет», дальше раздел 8: другие коммиты, слияния и ветки не смотришь.

## 6. Документ

Есть номер → `Glob pattern="**/<номер>/**/*.md" path="coddoc"`. Пусто или папки нет → «документа нет», дальше раздел 8.

Нашлись файлы → `Grep` с `-n` по именам из строки кода и словам вопроса, затем `Read` вокруг найденного; в БТ ещё
разделы 1.1, 2.1 и 3.2, в спеке 1.1 и 1.3. Цитата годится, только если в ней названо само поведение или его значение.
Общая цель задачи без этого — не причина, даже если выглядит подходящей.

## 7. Сверка

Цитату из документа открой по строке: `Read`, `offset` — строка минус 2, но не меньше 1, `limit` — 5. Цитаты в
показанных строках нет дословно → убери её и добавь в ответ строку «N цитат не подтвердил — убрал».

## 8. Ответ

Строки из одного коммита — один блок, из разных — блок на коммит. Пункты только из найденного, своих не добавляешь.

```
Откуда: <1–2 строки только из найденного>
- Появилось: <дата>, <автор>, коммит <хеш> «<тема>»
- Было до этого: <что> | строка появилась в этом коммите
- В том же коммите: <до трёх файлов, тест — по имени> | —
- Причина: «<дословная цитата>» — <файл:строка | коммит <хеш>> | не записана
- Документ: <путь> | документа нет
Задача: <номер> | номера нет
```

Блок кончается строкой `Задача:`: трекер ты не читаешь и что делать дальше, не советуешь.

## Примеры

Стек и предмет примеров не важны — важны форма и то, что причина только дословная.

Причины нет нигде, документа нет:

```
Откуда: таймаут подняли с 15 до 30 минут; причина в истории не записана.
- Появилось: 2026-03-12, А. Автор, коммит 4f2a91c «CHRG-118 увеличил таймаут простоя»
- Было до этого: `idleTimeout = 15 * time.Minute`
- В том же коммите: тест `TestSweepKeepsSessionFor30m`
- Причина: не записана
- Документ: документа нет
Задача: CHRG-118
```

Причина в документе, строка новая:

```
Откуда: порог оповещения задан задачей об оценках, причина названа в БТ.
- Появилось: 2025-11-03, Б. Автор, коммит 9be01d2 «DIARY-52 порог оповещения»
- Было до этого: строка появилась в этом коммите
- В том же коммите: —
- Причина: «родителю важны только двойки: пуш на каждую оценку отключают» — coddoc/DIARY-52/business_requirements.md:14
- Документ: coddoc/DIARY-52/business_requirements.md
Задача: DIARY-52
```
