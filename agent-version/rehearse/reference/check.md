# Проверка документа тремя ролями

Документ уходит в разработку. Исполнитель, архитектор и безопасник читают его параллельно, сводящий оставляет только
критичные вопросы, ты сверяешь опоры и отдаёшь список одним сообщением. Ответов аналитика не ждёшь и не разбираешь.
Правила 1–3 `SKILL.md` в силе.

## Шаг П1 — файлы

Пути Документа, Корня и Документа сверху — по Шагу 1 `SKILL.md`. Ещё нужны, все в `<скилл>/reference/`:

| Что | Файл |
|---|---|
| Задание ролям | `brief.md` и поправка к нему `check-brief.md` |
| Карточки ролей | `role-executor.md`, `role-architect.md`, `role-security.md` |
| Задание сводящему | `merge.md` |

Файл не находится → «скилл установлен не полностью: нет `<файл>`». Стоп.

## Шаг П2 — три роли

Три субагента одним сообщением, параллельно; каждому нужны `Read`, `Grep`, `Glob`, писать не нужно. Промпт — этот, с
подстановкой, без своих добавлений; у каждого своя карточка роли:

```
Ты готовишь вопросы для проверки документа перед разработкой. Скилл rehearse уже запущен, ты его часть: инструмент
Skill не вызывай. Прочитай задание <абсолютный путь к brief.md>, поправку к нему <абсолютный путь к check-brief.md> и
карточку роли <абсолютный путь к role-*.md> и работай строго по ним; где поправка расходится с заданием или карточкой
роли, верна поправка.
Документ: <абсолютный путь>
Документ сверху: <абсолютный путь или «нет»>
Корень: <абсолютный путь>
```

- В ответе роли нет строки `## ВОПРОСЫ` → этой роли ещё раз тем же промптом. Снова нет — роль не ответила.
- Не ответила ни одна → «подготовить вопросы не удалось». Стоп.
- Все ответившие вернули пустой блок → сразу Шаг П5 с нулём вопросов.
- Субагента запустить нельзя → «проверке нужны субагенты; без них — репетиция одной роли: `rehearse <путь> <роль>`». Стоп.

## Шаг П3 — свод

Один субагент; ему нужны `Read`, `Grep`, `Glob`. Промпт — этот; блоки ролей — дословно, как пришли:

```
Ты сводишь вопросы трёх ролей к документу. Скилл rehearse уже запущен, ты его часть: инструмент Skill не вызывай.
Прочитай задание <абсолютный путь к merge.md> и работай строго по нему.
Документ: <абсолютный путь>
Документ сверху: <абсолютный путь или «нет»>
Корень: <абсолютный путь>

Исполнитель:
<блок `## ВОПРОСЫ` или «не ответил»>

Архитектор:
<блок или «не ответил»>

Безопасник:
<блок или «не ответил»>
```

В ответе нет строки `## СПИСОК` → запусти ещё раз тем же промптом. Снова нет → «свести вопросы не удалось». Стоп.
Дальше работаешь только с блоком `## СПИСОК`; блок `## СНЯТО` аналитику не показываешь.

## Шаг П4 — сверка опор

У каждого пункта списка одна или две строки `опора:`. Сверяешь их так же, как в первом абзаце Шага 3 `SKILL.md`.
Хотя бы одна опора пункта не подтверждена или файл не открылся → пункт убери.

## Шаг П5 — список

Одним сообщением:

```
Проверка: <путь к документу от Корня> — исполнитель, архитектор, безопасник. Критичных вопросов: <N>.

1. <вопрос из списка, без изменений>
   Чем грозит: <из списка>
   Кто спросил: <роли из списка>
   Опора: <путь от Корня>:<строка> — «<цитата>»

Вписать ответы в документ — доработкой в `/analyst-workspace`.
```

- Две опоры у пункта — две строки «Опора:».
- Роль не ответила → второй строкой: «<Роль> не ответил — его вопросов в списке нет.»
- Пункты убраны на Шаге П4 → строка перед последней: «Опора не подтвердилась — убрал пунктов: <число>».
- Пунктов не осталось и ни один не убран на Шаге П4 → вместо нумерованного списка и последней строки: «Критичных
  вопросов нет: на всё, что спросили бы ответившие роли, документ отвечает. Это не оценка решения.» Убраны все на Шаге
  П4 → вместо них: «Пункты не прошли сверку опор — списка не будет.»

Своих пунктов не добавляешь, текст пунктов не меняешь, документ не оцениваешь.
