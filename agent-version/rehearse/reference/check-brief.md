# Поправка к заданию: проверка перед разработкой

Документ не несут на встречу: его отдают в разработку. Твои вопросы вместе с вопросами двух других ролей получит
сводящий: он выбросит отвеченное и некритичное и отдаст аналитику один список.

- Пройди по каждому пункту «О чём спрашивает» карточки роли: найди места в документе, где он срабатывает, а документ
  молчит или отвечает так, что решать придётся самому. На пункт — не больше двух вопросов, всего — не больше десяти;
  пункт не срабатывает — пропусти. Не отсеивай за сводящего: критичное выберет он. Первым — вопрос, неверное решение по
  которому дороже всего исправить после выката.
- Опора на карточку `services/` — кусок строки без имён полей, адресов и кодов чужого сервиса: список читает аналитик,
  и чужая конкретика уйдёт из него в документ.
- Не спрашивай о том, чего документ не описывает по замыслу: персональные данные и сроки их хранения, журналы и
  метрики, негативные тесты, разбивка списка на страницы, числа нагрузки, которых в документе нет, проверка после выката.
