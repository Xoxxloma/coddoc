# Репетиция встречи по документу

Аналитик несёт документ на встречу. Ты играешь одного из тех, кто будет его принимать, задаёшь неудобные вопросы по
одному и в конце отдаёшь слабые места. Вопросы готовит субагент; ты сверяешь их опоры, задаёшь вопросы и разбираешь
ответы.

## Четыре правила

1. **Документ ты не читаешь.** Его читает субагент. Документ могли писать в этой же сессии: тогда ты знаешь, что имел
   в виду автор, и спросишь мягко.
2. **Ничего не правишь и не пишешь.** Выход — вопросы и итог в чат.
3. **Вопрос без подтверждённой опоры не задаёшь.** Опора — цитата из файла с путём и номером строки.
4. **Итог — только по ответам аналитика.** Своих вопросов и слабых мест не добавляешь, документ не оцениваешь.

`<скилл>` — папка этого `SKILL.md`. Поиск файлов: папку задаёт параметр `path`, маску — `pattern`; маска, которая
начинается с имени папки (`reference/brief.md`), не находит ничего.

## Шаг 0 — документ и роль

- Путь к документу — из вызова. Нет → спроси одной строкой. Файл не находится → скажи об этом и остановись.
- В вызове «проверка» или просьба проверить, хватит ли документа, чтобы по нему строить, → режим проверки: роль не
  спрашиваешь, после Шага 1 работаешь по `<скилл>/reference/check.md` вместо Шагов 2–5.
- Роль — из вызова: заказчик, архитектор сервиса, безопасник или исполнитель. «Бизнес», «клиент» — заказчик; «ИБ»,
  «кибербезопасность» — безопасник; «разработчик», «бэкенд», «фронтенд» — исполнитель.
- Роли нет → вопрос с вариантами «Заказчик», «Архитектор сервиса», «Безопасник», «Исполнитель». Рекомендуемый вариант первым,
  с пометкой «(рекомендую)»: для `business_requirements.md` — заказчик, для `technical_specification.md` — архитектор сервиса;
  для остальных файлов рекомендации нет.
- Названа другая роль → тот же вопрос с первой строкой: «Пока умею четыре роли».

## Шаг 1 — пути

| Что | Откуда |
|---|---|
| Документ | путь из Шага 0, абсолютный |
| Корень | папка, в которой лежит `coddoc/`, — отрезается от пути документа. Документ не в `coddoc/` → текущая папка |
| Документ сверху | только у `technical_specification.md`: в той же папке `business_requirements.md`; нет — `bug_report.md`; нет — `change_request.md`; нет ни одного → «нет». У остальных документов → «нет» |
| Задание | `<скилл>/reference/brief.md` |
| Роль | `<скилл>/reference/role-customer.md`, `role-architect.md`, `role-security.md` или `role-executor.md`; в режиме проверки — файлы из `check.md` |

Задание или карточка роли не находится → «скилл установлен не полностью: нет `<файл>`». Стоп.

## Шаг 2 — вопросы

Один субагент; ему нужны `Read`, `Grep`, `Glob`, писать не нужно. Промпт — этот, с подстановкой, без своих добавлений:

```
Ты готовишь вопросы для репетиции встречи. Скилл rehearse уже запущен, ты его часть: инструмент Skill не вызывай.
Прочитай задание <абсолютный путь к brief.md> и карточку роли <абсолютный путь к role-*.md> и работай строго по ним.
Документ: <абсолютный путь>
Документ сверху: <абсолютный путь или «нет»>
Корень: <абсолютный путь>
```

В ответе нет строки `## ВОПРОСЫ` → запусти ещё раз тем же промптом. Снова нет → «подготовить вопросы не удалось».
Стоп. Субагента запустить нельзя → выполни задание сам.

Строка `## ВОПРОСЫ` есть, вопросов под ней нет → «Вопросов у <роли> нет: на всё, что она спросила бы, документ
отвечает. Это не оценка решения.» Стоп.

## Шаг 3 — сверка опор

У каждого вопроса одна или две строки `опора: <путь>:<строка> — «<цитата>»`, путь — от Корня. Каждую открой
отдельно: `Read <Корень>/<путь>`, `offset` — строка минус 2, но не меньше 1, `limit` — 5; файл целиком не открывай,
даже если опор в нём много. Путь — только имя файла Документа или Документа сверху → открой этот файл по пути из
Шага 1. Опора подтверждена, если слова цитаты подряд есть в показанных строках; кавычки и знаки препинания не в счёт.
Хотя бы одна опора вопроса не подтверждена или файл не открылся → вопрос убери.

Не осталось ни одного вопроса → «вопросы не прошли сверку опор — репетиции не будет». Стоп.

## Шаг 4 — репетиция

Первым сообщением одна строка: «Я — <роль>. Задам <N> вопросов по одному. Скажете „хватит“ — сразу итог.»

Каждый вопрос — отдельным сообщением, обычным текстом, без вариантов ответа:

```
<номер>/<N>. <текст вопроса из блока, без изменений>
Опора: <путь>:<строка> — «<цитата>»
```

Две опоры у вопроса — две строки «Опора:».

После ответа:

| Аналитик | Ты |
|---|---|
| назвал место в документе, где ответ есть | вопрос снят, документ не открываешь → следующий |
| сказал, что посылка вопроса неверна | вопрос снят → следующий |
| ответил по существу | → следующий |
| ответил уклончиво: общие слова, «как-нибудь решим», «это не ко мне» | одно уточнение от лица роли: суть вопроса короче и просьба о конкретике — кто, что, когда, сколько. После ответа на уточнение — следующий, что бы ни ответил |
| «не знаю», «уточню», «надо спросить» | «Записал.» → следующий |
| «хватит», «стоп», «давай итог» | Шаг 5 |

Не споришь, не объясняешь, как правильно, не хвалишь.

## Шаг 5 — итог

```
Репетиция: <путь к документу от Корня>, роль — <роль>. Задано вопросов: <K> из <N>.

Решить до встречи:
1. <вопрос коротко> — <путь>:<строка>

Вписать в документ:
1. <вопрос коротко> — ваш ответ: <суть одной фразой> — <путь>:<строка>

Снято: <число> — ответ в документе есть или посылка неверна.
```

- `<K>` — сколько вопросов ты показал, считая тот, в ответ на который аналитик сказал «хватит».
- «Решить до встречи» — ответ из строки «не знаю» таблицы Шага 4 или уклончивый после уточнения. «Вписать в
  документ» — ответ по существу.
- Пустая группа → `—`.
- Вопросы убраны на Шаге 3 → строка «Опора не подтвердилась — убрал вопросов: <число>».
- «Вписать в документ» не пуста → последней строкой: «Вписать ответы — доработкой документа в `/analyst-workspace`».

## Не делаешь

- не читаешь документ целиком — кроме случая, когда субагента нет;
- не пишешь и не правишь файлы, не вписываешь ответы сам;
- не задаёшь своих вопросов и не меняешь текст вопросов из блока.
