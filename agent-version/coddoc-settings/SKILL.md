# Свои разделы в БТ и спеке

Скрипт `settings.py` лежит в `reference/` рядом с этим файлом. Он показывает, проверяет и пишет файлы настроек
`.coddoc-tmp/coddoc-settings/sections-bt.md` и `sections-spec.md` в корне репозитория. Файлы личные, git их не видит.
Твоя работа — собрать у человека поля, вызвать скрипт и передать его вывод.

## Порядок

1. **Команда** — из папки репозитория, одна за раз. Python — `python3`, на Windows — `python`. `bt` — БТ, `spec` —
   спека:

   ```
   python3 .gigacode/skills/coddoc-settings/reference/settings.py show
   python3 .gigacode/skills/coddoc-settings/reference/settings.py add bt --name "<название>" --what "<что писать>" --question "<вопрос>" --dry-run
   python3 .gigacode/skills/coddoc-settings/reference/settings.py edit spec --name "<название>" --new-name "<…>" --what "<…>" --question "<…>" --dry-run
   python3 .gigacode/skills/coddoc-settings/reference/settings.py remove bt --name "<название>" --dry-run
   python3 .gigacode/skills/coddoc-settings/reference/settings.py check
   ```

   Если скиллы установлены в другую папку, путь до `reference/` начинается с неё. В `edit` — только те поля, что
   меняются.

2. **Не сказано, что сделать, — `show`:** покажи, что настроено, и спроси — добавить, поправить или убрать раздел,
   в БТ или в спеке.

3. **Добавить** — по очереди: документ (БТ или спека); название; что в разделе писать; вопрос, который задаст
   интервью. Вопрос предложи сам по названию и «что писать» — человек подтверждает или правит. Вопрос — одно
   предложение с одним «?».

4. **Поправить или убрать** — выбор из разделов, которые показал `show`.

5. **Сначала `--dry-run`:** покажи итоговый файл и спроси «записать?». После «да» — та же команда без `--dry-run`.

6. **Ответ** — по последней строке вывода, она начинается с `coddoc-settings:`.
   - `ok` — файл записан, путь в `path=`. БТ или спека спросят по этим разделам при следующем интервью. При
     `sections=0` разделов не осталось и файл удалён.
   - `dry-run` — над ней итоговый файл, дальше шаг 5. `show` — строки над ней как есть. `check ok` — файлы по форме,
     ничего не записано.
   - `error <код>` — строку над ней передай как есть и спроси, что поправить.
   - Скрипт не запустился (`command not found`, `is not recognized`, `не является … командой`) — «Нужен Python 3:
     на Windows — команда `python`, на macOS и Linux — `python3`».

## Чего не делать

- Базовые разделы БТ и спеки не убираются, не переименовываются и не ослабляются. Такую просьбу отклони до скрипта
  одной строкой: «базовые разделы и их проверки менять нельзя — можно добавить свой раздел».
- Файл настроек не пиши и не правь сам — только скриптом. Человек поправил файл руками — `check`.
- Поделиться разделами с коллегой — скопировать ему файл из `.coddoc-tmp/coddoc-settings/`.
