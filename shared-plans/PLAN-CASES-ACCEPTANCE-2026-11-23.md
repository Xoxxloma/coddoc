# План: места изменяемого события в спеке — 2026-11-23, итог 2026-11-24

Источник: дефект из прода, прошедший через `change-request-doc` 1.4.0 и спеку; самоанализ агента из прода; разбор
23.11 с архитектором. Первая редакция плана (случаи → отдельные FR в запросе, БТ, спеке) пересмотрена по ходу работы;
ниже — что сделано по факту.

## Инцидент

Аналитик оформил правку поля события в сервисе с процессом (карточка `services/vector-b3.md`). Изменение было
названо через два случая (статусы), приёмка — одна. Одна и та же логика заполнения поля работала в нескольких местах
публикации события; правка сломала место, которое должно было остаться прежним. Спека в §6.2 написала общую фразу
«остальное — как сейчас», тестировщик это место не проверил. Карточка перечисляет места публикации (потоки, ручки),
но не связывает их с полем.

Граница: общий метод — дефект кода; документ его не предотвращает, он даёт тестировщику строку проверки на каждое
место.

## Сделано — `technical-spec-doc` 2.4.2 → 2.5.0 (CHANGELOG 5.136)

- Шаблон §6.2: подписанный пункт «Места публикации изменяемого события:» + образец из трёх строк (меняется по FR /
  значение из источника, то же / то же, что до правки); событие не меняется — пункт неприменим.
- Гейт 2: изменённое событие — грепом по всей карточке владельца, откуда оно уходит.
- Замер: перечень неизменяемых мест 9 из 10 (форма инцидента 4/5, доработка по БТ 5/5), база 2.4.2 — 0 из 6;
  выдумок и ловушек 0, шума на пробах без события нет, регресса `ts-cr-*` нет. Порог 5/5 на форме инцидента не взят.
- Стенд: пробы `OCC-*`, грейдер `grade-occ.mjs`; поток вызовов вне песочницы; фраза лимита — отказ API.

## Причина, найденная по ходу

Модель видит места в карточке до записи (5 из 6 красных прогонов), но при записи §6.2 выбирает ось: места, статусы
(как документ сверху называет случай) или читатели (заголовок §6.2 и ответы аналитика). Правила прозой (круги 1–2)
выбор не убирали; подписанный пункт — убирает. Отброшено: общая фраза «что рядом» в запросе как корень (без неё
1/3), приём «назови вслух» (исполняется в 1 из 22).

## Не сделано и почему

- **Этапы** (`stage-breakdown-doc`: §6.2 в файл этапа) — откачено по слову пользователя: не эта задача. Факт
  остаётся: §6.2 спеки до файлов этапов не доезжает.
- **Приёмка** (`spec-review`: пункт «событие меняется, а в §6.2 общая фраза») — отклонена пользователем: задача —
  чтобы спека писала перечень сама.
- **Запрос на правку** (`change-request-doc`: отдельный FR на каждый названный случай, бывший С1) — вне ядра;
  этот баг он не ловит.
- **БТ** (развилки в критериях) — снято: на уровне бизнеса реализация не видна.
- **Значение в ответах нескольких ручек** — старый скилл находит сам (3/3), правка сужена до событий.

## Пределы и открытое

- 1 из 10 — пункт не применён, в §6.2 общая фраза; сети нет.
- Значение поля у места переносится не всегда; шаблон его не требует.
- Фоновая задача — именем из кода, как в карточке (правило «без имён реализации» не исполняется; оставлено решением
  пользователя).
- Места пишутся по карточке без отдельного «да» аналитика.
- Без карточки сервиса не проверено.
- На прод-модели доля может быть ниже — пилот в проме.
