# План: скилл «план работы» (`work-plan`) — 2026-11-17

Источник: описания аналитика (Аксенов Н., 16.11.2026) — «общий план работы» и «трекинг открытых вопросов»
(`test.md` в корне, не в git), и решения в разговоре 17.11.

## Зачем

Аналитик ведёт план по инициативам и открытые вопросы руками — в Конфлюенсе, переписке, голове. Скилл собирает
дела из открытых вопросов документов, которые сейчас в работе. Ноут, БТ или спека обновились — новый запуск
пересобирает список дел.

## Решено

- **Один скилл, отдельного трекера вопросов нет.** Открытые вопросы уже живут в документах:
  - БТ, спека, запрос на правку, баг-репорт — блок «Открытые вопросы» и строка шапки
    `**Статус готовности:** Требуются уточнения (N)`, N — число вопросов; вопросов нет — «Готово к оценке»
    (у спеки — «Готово к разработке»);
  - ноут — строки `- [открыто] … — ждёт: <кто>` без пометки `‖` (с `‖` — закрыт, заменён, снят или оспорен).
- **Кандидаты ищет `/peek`** новым режимом списка: документы `coddoc/` — в невлитых локальных ветках; ноуты
  `notes/*/notebook.md` — в рабочей копии, в основной ветке и в невлитых ветках (дискавери идёт до ветки задачи).
  Рабочая копия смотрится всегда, с незакоммиченным.
- **Фильтр один: открытых вопросов 0 — не кандидат.** Документ без строки «Статус готовности» (этапы,
  разбиение, старые файлы) — тоже не кандидат. Автор, отличие от основной ветки, сортировка — не сейчас.
- **Какие документы берём, решает аналитик** — вопросом по найденному списку. Ноуты — такие же кандидаты, руками
  не добавляются.
- **Файл плана — один на инициативу, в `.coddoc-tmp/work-plan/<инициатива>.md`**, не в git (только на этой
  машине). Свои данные плана: цель и список документов, которые ведём. Дела каждый запуск собираются заново.
- **Документ дошёл до 0 вопросов** — вопрос «закончили с ним или следим дальше?».
- **Не делаем:** `intent.md`, ранжирование (позже), внешние трекеры, отправку наружу. Скилл не правит документы
  и ноут, не запускает другие скиллы и сам вопросы не закрывает.

## Срезы

Каждый срез — коммит в одной ветке, по «да». Номера CHANGELOG — от `origin/main` в момент коммита (сейчас 5.114).

### С0 — `/peek` режим списка (peek 1.0.0 → 1.1.0)

- Вызов `peek.py --list`. Основная ветка — та, на которую указывает `origin/HEAD`; её нет — локальная `main`,
  потом `master`; не нашлась — строка «не знаю основную ветку — смотрю все локальные».
- Невлитые ветки — `git for-each-ref --no-merged=<основная> refs/heads`. Текущая ветка читается с диска, а не
  с вершины.
- Документы: `coddoc/**/<КЛЮЧ>/*.md` со строкой «Статус готовности» → число из «Требуются уточнения (N)».
  Ноуты: `notes/*/notebook.md` → число строк `- [открыто]` без `‖`, из шапки — `ключ:` и `тема:`.
- Один и тот же путь в нескольких местах — берётся самый свежий, как в `peek_key` (`last_commit`, «ещё в»).
- Вывод — строка на документ: `<КЛЮЧ | —> · <путь> · <ветка | рабочая копия> · <автор> · <дата> · открытых: N`
  (у ноута ещё `тема: …`). Найденные файлы копируются в `.coddoc-tmp/peek/list/<путь в репо>` (папка
  пересоздаётся каждый вызов) — их читает скилл плана. Последняя строка — `peek: list N`.
- Переиспользовать из `peek.py`: `find_top`, `fetch`, `branches`, `read_blobs`, `last_commit`, `header` (рядом —
  разбор числа N).
- `SKILL.md` peek: строка режима, строка таблицы ответов; README, CHANGELOG.
- Проверка: `selftest-peek.py` — в песочницу добавить влитую ветку (не видна), документ «Готово к оценке» (не
  виден), ноут в ветке с закрытыми и открытыми строками, правку в рабочей копии, меняющую N; мутанты на каждое
  правило. Пробы модели для С0 не нужны: скрипт проверяется самотестом.

### С1 — скилл `work-plan` 1.0.0: первый запуск

1. `peek.py --list`. Кандидатов 0 — так и сказать, файл не создавать.
2. Кандидаты — нумерованным списком, вопрос «какие берём — номера через запятую». (У `AskUserQuestion` не больше
   4 вариантов, кандидатов бывает больше.)
3. Инициатива — гипотезой: документы и ноуты с одним ключом — одна инициатива «<КЛЮЧ>»; ноут без ключа — по своей
   теме. Аналитик может поправить.
4. Файл `.coddoc-tmp/work-plan/<инициатива>.md`:
   - шапка: инициатива, `обновлён: <дата>`, цель — по умолчанию «БТ и спека влиты» (меняет только человек);
   - «Документы»: путь, ветка, открытых N;
   - «Дела»: по делу на открытый вопрос — текст вопроса, откуда (документ и пункт блока / номер пункта ноута),
     кого ждём (у ноута — из `ждёт:`, у БТ и спеки — «—»).
5. Отчёт в чат: путь файла, документов, дел.

### С2 — повторный запуск

- `/work-plan <инициатива>` — или без слов: планы в `.coddoc-tmp/work-plan/` списком, какой обновить.
- `peek.py --list` → документы плана перечитываются, «Дела» собираются заново; шапка и «Документы» остаются.
- Документ плана дошёл до 0 вопросов или не нашёлся в невлитых ветках (влита или удалена) — вопрос
  «закончили с ним или следим дальше?»; «закончили» — убрать из «Документов».
- Новые кандидаты, которых нет в плане, — строкой «ещё N документов в работе не в плане», без вопроса; добавить —
  по слову аналитика («добавь документы»).
- Отчёт: что закрылось и что появилось — сравнением с прошлой версией файла перед перезаписью.

### С3 — стенд, по «да»

- Песочница по образцу `selftest-peek.py` и `run-peek-probes.mjs`: две невлитые ветки, одна влитая, документ
  «Готово…», ноут с открытыми и закрытыми строками.
- Пробы: первый запуск; повторный после закрытия вопроса в ноуте и обнуления БТ (ждём вопрос «закончили?»);
